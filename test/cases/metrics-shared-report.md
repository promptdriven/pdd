# Shared metrics native verification cases

These are requirement-derived native cases, not evidence of a Runtime or native test run. Execute against the public command and exported data as well as calculator/store APIs.

- Snapshot issues 1, 2; issue 1 has prompt PR and code PR plus two attempts. Issue denominator remains 2, attempt count 2, code delivery 1 only when explicitly mapped and merged.
- Single PR small-change can deliver; prompt-only stop and new-product/observe holds are planned stops. PR1 alone is prompt progress.
- Attempted, failed and uncertain launches are not starts. Confirmed starts preserve manual, Autopilot and unknown origin independently; a claim/tick alone is no start. Record actual decision linkage when known.
- Validation FAIL then repair and PASS at head A are separate events. New candidate head B makes A stale; missing checker, absent evidence, Runtime no-verdict and CI each remain separate. Apply existing evidence acceptance, including supported equivalence, and preserve reviewer and evidence links.
- Code PR explicitly maps issues 1 and 2: both may be delivered, with one PR; casual mention alone does not map. Later merge remains attributed to the earlier snapshot and no earlier event is invented.
- Human complaint explicitly linked to delivered fix counts as failed-fix report; admin reopen, new scope, revert and unknown reasons do not. Show 7/30-day maturity, retain later report, and never call no report a success.
- Import the same event twice and then a second machine's observation of the same issue: one issue, no duplicate event; conflicting same-identity payloads remain visible. Missing expected machine is unknown coverage. Incompatible definitions must not silently mix.
- Run >200 attempts and record repeated overwritten workflow steps: all durable metric events survive independent of index/status snapshots. Record missing historical values as unknown and show installation coverage start.
- Report the same fixture in terminal and JSON with explicit timezone and cutoff; compare count, issue membership and reasons. Activity counts local-day events and is not a same-issue conversion funnel; zero denominator is not applicable.
- Exercise `metrics record`, export and import in another repository without private paths or credentials; repeat import, inspect no raw prompts, chats, secrets or issue bodies, and reproduce the report independently.
