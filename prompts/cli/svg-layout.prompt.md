# SVG layout lint

Own `src/svg-layout.mjs`. Its module function `lintSvgLayouts({root, files, promptPaths})` returns a deterministic array of warning strings for disagreements between screen prompts and their linked `.ui.svg` drawings. It reads local files only, makes no AI or network call and changes no file. Preserve existing Check admission: these warnings never refuse a test or approve a prompt.

`root` is the repository root; `files` is its Git-visible repository-relative file list. With `promptPaths`, inspect those prompts only; without it, inspect every Git-visible `*.prompt.md`. Read local inline and reference-style Markdown image/link destinations ending in `.ui.svg`, relative to their prompt; ignore remote links, fragments and duplicate destinations. Files must stay inside root and be regular files with no symlink ancestors. An unreadable, missing, escaping or malformed drawing produces a warning naming the prompt and drawing; never silently claim it matches.

## Workspace advice

Use the [workspace authority](runtime-seam.prompt.md) (`loadRuntimeWorkspace`, `allowsRuntimePath`) before prompt/drawing content access, including no-Story local scans. Filter optional excluded candidates without opening them; report unavailable advice where relevant. Required linked drawings remain preflight's capture responsibility and cannot be silently pruned. Keep advisory warnings advisory and retain strict no-link reads.


## Parts and advice

The drawing is the layout spec for its declared state: visible parts, words, order and stable ids. Prose owns behavior and dynamic value sources. Ignore Runtime interface JSON, valid comments and SVG `title`, `desc`, `defs`, hidden elements and their descendants. A context-only region, marked `data-context-only="true"` or class `context-only`, and its descendants are outside the owned layout. Decode XML entities and normalize whitespace and case when comparing labels; preserve original spelling in diagnostics. Reject malformed or nested comments with a source/drawing warning; never remove delimiters and reinterpret the result as active markup. CDATA remains literal SVG text. Do not execute SVG scripts or load external resources.

Report all three kinds of disagreement, identifying the prompt, drawing and part:

| Warning | Required observation |
|---|---|
| Prompt control absent from drawing | An explicit control declaration lacks a matching visible drawing part (normalized `id` or `<text>`), reported as `control "<value>": prompt control absent from drawing`. For directional-control phrases (including four direction buttons), check `left`, `right`, `up` and `down` against visible part words and report each missing direction as `move-<direction>` (or the missing group). |
| Drawing label absent from prompt | A visible nonnumeric label is never mentioned in the prompt prose. Match complete normalized words/phrases, not arbitrary substrings. Pure numeric sample values remain dynamic content for this advisory. |
| Drawing region layout unspecified | A visible stable id is not acknowledged as an id/region or named layout part in the prose. Generic data-field mentions do not specify that field's box, bar or container. A label such as SCORE with data prose saying “score” may match as text while the `score` region still needs a layout declaration. |

Explicit control extraction covers both HTML markup and prose while excluding non-control attributes, CSS `.class` tokens and non-control copy:

- **Native HTML controls** (`<button>`, `<input>` with `type` `button`, `submit` or `reset`, `<select>`, `<textarea>`, and other non-`hidden` `<input>` elements, whether written directly or inside Markdown code spans/fences) declare their non-empty `id` and `name`; `<button>` also declares its non-empty `value` and decoded visible text label, and button/submit/reset `<input>` also declares its non-empty `value`. Non-control HTML elements (`<div>`, `<main>`, `<section>`, `<p>`, `<span>`, headings, lists, `<form>`, `<input type="hidden">`, etc.) never declare prompt controls, even when they carry an `id` (such as `<div id="app">` or `<main id="wait-card">`) or sit beside controls.
- **Non-control attributes and CSS selectors** (`class`, `role`, `aria-*`, `data-*`, `style`, `type`, `placeholder`, `title`, `href`, boolean state attributes, `.class` tokens, etc., whether double- or single-quoted or backticked, in HTML markup or prose) never become prompt controls.
- **Prose control declarations** (outside HTML tags) segment sentences and clauses while tracking quote (`"..."`, `'...'`, `“...”`) and Markdown code-span/fence boundaries, so punctuation inside quoted text or code spans (such as multi-sentence help strings) never splits a literal or pairs a closing quote with a subsequent opening quote to capture connecting prose (such as `" Also explain "`). Negated control clauses (`no button`, `no controls`, `without a button`, `without controls`) declare no controls. Affirmative control clauses declare explicit control bindings (`id`, `ids`, `name`, `names`, `value`, `values`), backticked control identifiers tied to the control declaration (excluding HTML snippets, `.class` tokens and non-control field/region identifiers such as `` `instructions` ``), quoted labels tied to the control declaration (excluding attribute values and quoted status, instruction or explanation copy), and directional-control phrases.

When a prompt links a single resolved `.ui.svg` drawing, check every extracted prompt control against that drawing. When a prompt links multiple distinct resolved `.ui.svg` drawings, normalize CRLF line endings, derive each drawing's distinguishing view tokens from its filename stem, state/variant and layout mode (keeping only tokens shared by strictly fewer than all linked drawings), and scope control checks per drawing: controls in a subsection whose heading or links identify a subset of drawings (intersecting nested heading scopes), a list item (and its indented continuations, code fences or sub-items) whose lead label before `:`, `—` or spaced `--` identifies a subset of drawings, a block linking a subset of drawings, or prose following a non-gallery standalone view image apply only to the matched drawing(s), while controls in shared or unscoped prose (including prose after consecutive gallery images) remain required on every linked drawing.

Explicit prose or HTML markup such as `region score`, `id="score"`, or “score box” acknowledges the corresponding drawn region without turning non-control container `id`s into required prompt controls. A backticked id within `## Appearance` also acknowledges it. Do not count an interface schema property or a general state-field declaration as a layout mapping. Retain explicit behavioral control declarations anywhere in the prose. Matching is conservative local advice: name uncertain/unmatched parts; do not infer a semantic equivalence or change the prompt/drawing automatically. Report source-read/parse limitations as warnings. This is a vocabulary and part check, not an AI assessment of meaning or a geometry check.

Also inspect workspace-allowed non-fixture `prompt-runtime.app-map.v1` app maps (`(^|/)(app-map\.json|app/maps/[^/]+\.json)$` in `files` outside `fixtures/`, plus non-fixture string entries of `"app_maps"` in workspace-allowed `test/**/*.json` and `tests/**/*.json` files) and delegate stylesheet and CSS-class checks for inspected prompts to [screen design check](screen-design-check.prompt.md). Read each referenced stylesheet safely inside `root` without following symlinks, passing any read/escape/symlink failure as that stylesheet's `error` record rather than throwing. Merge its returned warnings into the deduplicated sorted output.

Screen drawing and stylesheet warnings start `Warning: SVG layout` (ordered by prompt path, drawing path and part), while local app-map, scenario and dependency preflight advisories start `Warning: <path>:`; all warnings are deduplicated and deterministically sorted. A 2048-like screen with four direction buttons only in prose and SCORE/SEED boxes and a READY bar only in the drawing must warn about directions, READY and the unspecified score/seed layout regions, even when prose mentions score and seed data.

## Local app-map timer, scenario schema_version, native-only dependency, and simulation override advisories

Using the same local file access and workspace policy (`0` AI or network calls, never mutating files or blocking `pdd lint --local`):

- **Scoped-upload `.ui.svg` link syntax warning:** When an inspected prompt links an in-repo `.ui.svg` drawing ONLY via plain non-image Markdown link syntax (`[label](...)`) outside `## Dependencies` (with no `![label](...)` image link anywhere in the prompt and no link under `## Dependencies`), warn `Warning: SVG layout ${prompt} -> ${drawing}: link syntax: plain Markdown link outside "## Dependencies" is skipped by scoped uploads (causes dependency-file-unreadable); use image syntax ![label](...) or link it under "## Dependencies".`
- **Inverted `native-only` dependency warning:** Scoped to checkable prompts reached from checkable Runtime scenario entries (`steps[].entry_path` or scenario `app_maps`), extract plain-Markdown `.prompt.md` dependency links only from `## Dependencies` (outside code fences, ignoring `## Caller navigation` and general prose). When such a checkable prompt (no embedded `Runtime interface` block or carrying frontmatter, and not `kind: native-only`) reaches an in-repo `kind: native-only` prompt via `## Dependencies` / `calls`, warn `Warning: ${prompt}: checkable prompt links kind: native-only prompt ${target} (invert the dependency and inject a <port>.<op> port so Story checks do not skip)`.
- **Scenario `simulation_overrides` and plain-Markdown `simulation` port alignment:** For each Git-visible non-fixture `prompt-runtime.program-scenario.v1` JSON file in `files` whose reachable in-repo `steps[].entry_path` prompts are in scope (intersecting `promptPaths` when supplied), inspect step `simulation_overrides` entries and top-level `simulation` entries on plain-Markdown entry closures:
  - Warn when an operation key does not match `<port>.<operation>`.
  - Collect embedded `Runtime interface` port operations from `resources` entries of shape `{name, kind: "port", access, operations: [{name, access}]}` (`<name>.<op.name>` with `op.access ?? res.access`, keeping flat `res.operation` as fallback). When all reachable prompts carry embedded `Runtime interface` blocks, warn when a `simulation_overrides` operation is absent from reachable `resources` (or lacks `read` or `write` port access for `port.write`). When any reachable prompt is plain Markdown without that embedded resource, warn when neither `<port>.<operation>` nor both `<port>` and `<operation>` appear in reachable prompt prose.
  - On `simulation_overrides`, expand `initial_world.$seed` safely inside `root` (applying `initial_world.set` pointer overrides; skip the pointer check if `$seed` cannot be read) and warn when a `port.write` `world_pointer` does not resolve inside the expanded `initial_world`, when `criterion_id` is not checked by that step, or when a nonblank `failure_quote` is absent from that criterion's text.
- **App-map `schema_version`, screen `prompt_path`s, and `timers` preflight (`<150ms`, advisory):** On every workspace-allowed non-fixture `app-map.json`, `app/maps/*.json`, and string entry of `app_maps` in scenario JSON files in scope, warn with an exact 1-line fix when `schema_version` is not `"prompt-runtime.app-map.v1"`, when a screen `prompt_path` is absent from Git-visible `.prompt.md` files, or when any `timers` entry (max 16) has a missing/duplicate/wildcard `screen`, non-integer or out-of-range `interval_ms` (`1000..3600000`), `enabled_pointer` not resolving to a `boolean` in `initial_state` and a required `{"type": "boolean"}` property (without `oneOf`) in `state_schema`, `generation_pointer` not resolving to a safe integer `0..9007199254740991` in `initial_state` and a required `{"type": "integer", "minimum": 0}` property (without `oneOf`; optional `maximum` <= `9007199254740991` and >= `minimum`) in `state_schema`, or a `tick_operation` / `handler` (`{prompt_path, operation}`) whose prompt path is missing or whose tick operation is not declared.
- **Scenario `schema_version` preflight (`<150ms`, advisory):** On non-fixture JSON files under `test/` or `tests/` paired by basename with a `user_stories/**/<story>.md` Story (or declaring `story_path` or `steps[].entry_path`), warn with an exact 1-line fix when JSON is malformed or `schema_version` is not `"prompt-runtime.program-scenario.v1"`.
