# SVG layout, app-map, and scenario structural lint

Own `src/svg-layout.mjs` (backed by focused modules under `src/core/ui/{svg-layout,svg-xml,app-map-lint,scenario-lint}.mjs`). Its module function `lintSvgLayouts({root, files, promptPaths, appMapPaths, scenarioPaths, tests, includeShortDiagnostics})` returns a deterministic array of warning strings for structural `.ui.svg`, app-map, and scenario issues. It reads each local file in a single pass, makes no AI or network call and changes no file. Preserve existing Check admission: these warnings never refuse a test or approve a prompt.

`root` is the repository root; `files` is its Git-visible repository-relative file list (always used as the full lookup index). With `promptPaths`, inspect those prompts only; with optional `appMapPaths` or `scenarioPaths`, restrict app-map or scenario checks strictly to those selected files (still resolving referenced prompts and drawings against the full `files` index); without them, inspect every Git-visible `*.prompt.md`, app map, and scenario. Read local inline and reference-style Markdown image/link destinations ending in `.ui.svg` outside fenced code blocks and inline code spans, relative to their prompt; ignore remote links, fragments and duplicate destinations. Files must stay inside root, match exact letter case on disk/Git, and be regular files with no symlink ancestors. An unreadable, missing, wrong-case, escaping, unsafe, malformed, or bad-`viewBox` drawing produces a warning naming the prompt and drawing.

## Workspace advice

Use the shared workspace authority (`src/shared/workspace-policy.mjs`) before prompt/drawing content access, including no-Story local scans, with zero imports from `src/runtime-seam.mjs`. Filter optional excluded candidates without opening them. Keep advisory warnings advisory and retain strict no-link reads.

## Structural `.ui.svg` validation (`svg-xml.mjs` & `svg-layout.mjs`)

Validate every linked `.ui.svg` strictly as inert XML and sane SVG geometry (never regex-match controls, labels, or region names against English prompt prose):

- **Upload-compatible link syntax:** When an inspected prompt links an in-repo `.ui.svg` drawing ONLY via plain non-image Markdown link syntax (`[label](...)`) outside `## Dependencies` (with no `![label](...)` image link anywhere in the prompt and no link under `## Dependencies`), warn `Warning: SVG layout ${prompt} -> ${drawing}: link syntax: plain Markdown link outside "## Dependencies" is skipped by scoped uploads (causes dependency-file-unreadable); use image syntax ![label](...) or link it under "## Dependencies".`
- **Exact-case existence and no-symlink safety:** Reject missing drawings, case mismatches against Git-visible files (naming the exact file on disk when only casing differs), paths escaping `root`, symlink ancestors, and non-regular files.
- **Inert XML safety:** Decode XML entities strictly, reject malformed/nested comments, unsafe processing instructions, mismatched/malformed XML elements or duplicate attributes, text outside root, non-`<svg>` or multiple roots, active/unsafe tags (`<script>`, `<foreignObject>`, `<iframe>`, `<object>`, `<embed>`), `on*` event handler attributes, and external resources (`href`/`xlink:href`/`src` not starting with `#`, or `@import`/external `url(...)` inside attributes or `<style>`). Allow any standard CSS selectors inside `<style>` without a brittle selector allowlist. CDATA stays literal text; valid comments are ignored.
- **Finite & sane `viewBox` check:** When the root `<svg>` declares a `viewBox` attribute, require exactly 4 finite numbers (`minX minY width height` separated by whitespace or commas) with `width > 0`, `height > 0`, aspect ratio `max(width/height, height/width) <= 50`, and finite coordinates within `[-1_000_000, 1_000_000]` (with `width <= 1_000_000` and `height <= 1_000_000`) so non-finite, zero/negative, hairline-collapse, or extreme aspect-ratio `viewBox` values emit `Warning: SVG layout ${prompt} -> ${drawing}: viewBox: ...`.

## Local app-map, scenario schema_version, native-only layering, and simulation validation

Using the same local file access and workspace policy (`0` AI or network calls, never mutating files):

- **Inverted `native-only` dependency warning:** Scoped to checkable prompts reached from checkable Runtime scenario entries (`steps[].entry_path` or scenario `app_maps`), extract plain-Markdown `.prompt.md` dependency links only from `## Dependencies` (outside code fences, ignoring `## Caller navigation` and general prose). When such a checkable prompt reaches an in-repo `kind: native-only` prompt via `## Dependencies` / `calls`, warn `Warning: ${prompt}: checkable prompt links kind: native-only prompt ${target} (invert the dependency and inject a <port>.<op> port so Story checks do not skip)`.
- **Scenario `simulation` and `simulation_overrides` structural alignment:** For each Git-visible non-fixture `prompt-runtime.program-scenario.v1` JSON file in `files` whose reachable in-repo `steps[].entry_path` prompts are in scope:
  - Warn when an operation key does not match `<port>.<operation>`.
  - When all reachable prompts carry embedded `Runtime interface` blocks, validate `simulation_overrides` operations and `port.write` access against declared `resources` entries (never regex-scrape plain-Markdown prose for port names).
  - On `simulation` and `simulation_overrides`, warn when an embedded resource `result_schema` excludes `result_value_pointer` (`impossible-result-value-pointer`) or when a non-empty `result_value_pointer` is absent from `result_template` (`missing-result-placeholder`).
  - On `simulation_overrides`, expand `initial_world.$seed` safely inside `root` (applying `initial_world.set` pointer overrides) and warn when a `port.write` `world_pointer` does not resolve inside the expanded `initial_world`, when `criterion_id` is not checked by that step, or when a nonblank `failure_quote` is absent from that criterion's text.
- **App-map `schema_version`, screen `prompt_path`s, `/state/...` bindings, whole-event `"$ref": "/event"`, and `timers` preflight:** On every workspace-allowed non-fixture `app-map.json`, `app/maps/*.json`, and string entry of `app_maps` in scenario JSON files in scope, accept compact app maps and `"prompt-runtime.app-map.v1"` / `"prompt-runtime.app-map.v2"`. Warn with an exact 1-line fix on invalid JSON, invalid `schema_version`, missing/empty `screens`, non-object `state_schema`, missing screen `prompt_path`, unresolved `{"$ref": "/state/..."}` or `state`/`after[].bind` pointers in `state_schema` (preserving field pointers such as `{"$ref": "/event/value"}` and `{"$ref": "/event/key"}`; rejecting forbidden whole-event `{"$ref": "/event"}` inside handler/timer `input` as an offline `app-map-whole-event-ref` error), or invalid `timers` (max 16, unique non-wildcard `screen`, `interval_ms` `1000..3600000`, `enabled_pointer`, `generation_pointer`, `tick_operation` / `handler.prompt_path` existence, and nonblank `handler.operation` checked against embedded `Runtime interface` entries when present — never regex-scraping plain-Markdown prompt prose or stylesheet `.class` names).
- **Scenario `schema_version` preflight:** Compile PDD Short JSON scenarios (`isShortScenarioDoc`) in-memory against their paired Story so Short JSON scenarios pass `schema_version` and participate in `app_maps`, `native-only`, `simulation`, and `simulation_overrides` checks. When `includeShortDiagnostics: true` is passed, emit compact-scenario compile refusals and compile warnings (such as `patch-null-deletes-key`) for in-scope candidate scenarios.
