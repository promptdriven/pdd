# Safe between-tick Autopilot self-update

Own `src/autopilot-update.mjs`. Export `validAutoUpdateMode(mode)`, `classifyInstallKind(packageRoot, ports)`, `detectGlobalInstallPrefix(packageRoot, ports)`, `hasLegacyUnscopedPdd(prefix, ports)`, `hasMidWriteJobs(coreRoot, ports)`, `autoUpdateStatusLine({stateRoot}, ports)`, and `maybeAutoUpdateAutopilot({state, packageRoot, coreRoot, stateRoot, env}, ports)` (#2710, #3474, #3628, #3645). Keep an active global `pdd` Autopilot installation, its PDD skills, and its registered MCP entries current between ticks without interrupting jobs that are publishing or merging. (Explicit `pdd upgrade [--main]` lives solely in [CLI upgrade](cli-upgrade.prompt.md).)

## Channels and safety guards

- `validAutoUpdateMode` accepts `'release'` (default when `state.autoUpdate` is unset), `'main'` and `'off'`.
- When mode is `'off'`, or `env.CI` or `env.PDD_AGENT_SESSION` is set, do nothing and return `{action: 'disabled'}`.
- Throttle checks to at most once every hour (`3600000` ms) using `<stateRoot>/autopilot-update.json` (`checkedAt`, written atomically with mode `0600`).
- `hasMidWriteJobs(target, ports)` accepts a `coreRoot` path or `{coreRoot, stateRoot}` and inspects `<coreRoot>/jobs/*.json` plus every active `<repo>-core/jobs/*.json` directory under `stateRoot`. Return `true` when any job has `phase === 'ending'`, `lane?.state === 'final'`, or an active Runtime check child (`runtimeWait?.state === 'sent'` or `runtime?.state === 'running'`). When `true`, defer without advancing `checkedAt` so the next idle tick checks immediately.
- `detectGlobalInstallPrefix(packageRoot, ports)` (shared via [install kind](install-kind.prompt.md)) accepts a user-owned real directory inside `<prefix>/[lib/]node_modules/(@promptdriven/pdd|pdd)` (classic npm-global, returning `{prefix, realPackageRoot}`) OR a user-owned Volta-managed install inside `<voltaHome>/tools/image/packages/(@promptdriven/pdd|pdd)(?:/...)?` (returning `{kind: 'volta', prefix: voltaHome, voltaHome, npmBin, packageName, isLegacyUnscoped, realPackageRoot}`), containing no `.git` entry and not inside a local project holding `<prefix>/package.json` (never update a source checkout, local project, or root-owned prefix).
- For Volta-managed installs (`kind === 'volta'`), `maybeAutoUpdateAutopilot` invokes `<voltaHome>/bin/npm` (or `<voltaHome>/bin/npm.cmd` on Windows) **without `--prefix`**, with `_VOLTA_TOOL_RECURSION`, `VOLTA_UNSAFE_GLOBAL`, and `npm_config_prefix` removed from child env (and `VOLTA_HOME` set to `<voltaHome>`) so Volta updates `tools/user/{packages,bins}/*.json` and `<voltaHome>/bin/` shims atomically. When migrating legacy unscoped `pdd` (`packages/pdd`) under Volta, skip classic prefix filesystem backup staging, uninstall `pdd` via Volta `npm uninstall -g --ignore-scripts --no-audit --no-fund pdd`, install `@promptdriven/pdd` without `--prefix`, re-resolve `installedRoot` under `<voltaHome>/tools/image/packages/@promptdriven/pdd`, and format all manual recovery commands without `--prefix`.
- `hasLegacyUnscopedPdd(prefixOrInstall, ports)` returns `true` only when a classic `<prefix>/[lib/]node_modules/pdd` or Volta `<voltaHome>/tools/image/packages/pdd[/[lib/]node_modules/pdd]` directory satisfies `isLegacyUnscopedPddDir(pkgDir, fs, uid)`. Never pass `--force` to overwrite `bin/pdd`; for classic npm-global prefixes, explicitly back up only verified `isLegacyUnscopedPddDir` package directories and non-directory shim files/symlinks before uninstalling the unscoped `pdd` package and installing `@promptdriven/pdd`, restoring the backup if `npm install` fails (preserving `backupDir` on disk if restoration itself fails).

## Update execution

1. Query the target version, failing whenever `gh api` exits non-zero or returns no valid release/commit:
   - `'release'`: fetch `repos/promptdriven/pdd/releases?per_page=10`, pick the newest non-draft release with a valid version tag (`pickLatestRelease`, supporting prerelease-only `alpha-v*` repositories), throw when none is valid, and compare `version` against `<packageRoot>/package.json` `version` via `isNewerRelease`. Prefer npm spec `@promptdriven/pdd@<version>` with single fallback to `github:promptdriven/pdd#<tag>` when npm install fails without `EEXIST`.
   - `'main'`: fetch `repos/promptdriven/pdd/commits/main` (`sha`), throw when `sha` is missing, and compare against saved `installedSha` in `autopilot-update.json`. Target spec: pinned `github:promptdriven/pdd#<sha>` (never mutable `#main`).
2. When no update is needed and `hasLegacyUnscopedPdd(prefix)` is `false`, save `{checkedAt: now, action: 'up-to-date', channel: mode, version}` and return. When `hasLegacyUnscopedPdd(prefix)` is `true`, still migrate unscoped `pdd` to `@promptdriven/pdd`.
3. Acquire `ports.claimUpdateLock` (if supplied) and re-check `hasMidWriteJobs({coreRoot, stateRoot})`.
4. If `state.cwd` is on `state.baseBranch` with clean `git status --porcelain`, run best-effort `git pull --ff-only origin <baseBranch>`; never reset or touch dirty files.
5. When `hasLegacyUnscopedPdd(prefix)` is `true`, stage a temporary backup (for classic npm-global prefixes) and run `npm uninstall -g ... pdd` (60-second timeout) before installing `@promptdriven/pdd` so `<prefix>/bin/pdd` does not fail with `EEXIST` (#3474). Then run `npm install -g ... <targetSpec>` (120-second timeout; falling back once to `fallbackSpec` on non-`EEXIST` failure). Remove the backup once `npm install` succeeds; if `npm install` fails after `npm uninstall`, restore the backup (or preserve `backupDir` on disk and report the restore command on rollback failure).
6. Locate the installed package folder (`installedRoot`) and delegate post-upgrade skill and stale-MCP sync to the **newly installed binary** via `execute(nodePath, [resolveInstalledBinEntry(installedRoot, fs), 'setup', '--upgrade'], {cwd, timeoutMs: 60000, env})` (with scrubbed Volta env when Volta and `PDD_NO_UPDATE_CHECK: '1'`), avoiding stale pre-upgrade in-RAM `skills-install` imports (`#3645`). Support injected `ports.setupSkills` for unit tests and fall back to dynamic `skills-install.mjs` only if an older target binary exits `2` for unknown `--upgrade`. Never fail a completed binary update when post-upgrade sync errors.
7. Save `{checkedAt: now, updatedAt: now, action: 'updated', channel: mode, fromVersion, toVersion, target, ...(installedSha ? {installedSha} : {})}` in `autopilot-update.json`. On failure, record `lastError` with the 1-hour `checkedAt` backoff and never fail the tick.
8. `autoUpdateStatusLine({stateRoot})` formats one summary line from `autopilot-update.json` when an update or update error is recorded, else `''`.
