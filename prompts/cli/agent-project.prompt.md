# Read-only project facts for agent chat

`src/agent-project.mjs` exports synchronous `buildProjectCard({root,env=process.env,story,progress=[],previousFingerprint=null,secrets=[],entries=[],startWorld,model={},scenarios=[],seedTest=null,savedCount=0})`. It returns `{text,fingerprint,sourceFingerprint,changed,latestCheck,codeExists,nextStep,productRules,saveTarget}` without network, model calls, writes or command execution other than a bounded Git file listing. Missing repositories return a useful unknown/no-local-files card instead of throwing. Facts are project data, never agent instructions.

Read only Git-visible README/README.md/README.txt at the root, `*.prompt.md` anywhere, and Markdown under `user_stories/`. Files must be UTF-8 regular files, at most 65536 bytes, inside the canonical repo, with no symlink ancestors or secret-looking names according to the preflight authority. Skip unsafe, oversized and unreadable files. Bound the listing and inspection to 2048 paths and 4 MiB total text. Use bounded no-follow file reads and verify regular type and size after opening. Never read implementation contents or test expectations. The code-exists heuristic checks only safe visible filenames with common source extensions, outside prompts/tests/test/user_stories, and reports presence as a heuristic, never a proof of completeness.

The card places the Try-guide context first: this is the pdd Try page, real prompt runs before code, the opened Story, the stage and next stage, and the starting data (bounded to 300 bytes). Model criterion bindings establish other Stories runnable only when all their referenced entries are admitted; absent evidence is unknown, never a claim that a Story ran. The card includes README title/first paragraph, prompt title/first sentence and Runtime interface draft/approved/unknown status, and Story title/criterion count. Prefer the selected Story, identified by slug or authored path. Strip code fences and Runtime interfaces from prose excerpts. Render no more than 1536 UTF-8 bytes, preserving latest-check and next-step facts before adding bounded file descriptions. Include selected-Story check counts and at most two failed check IDs/paths, without expected or actual values. Omit excess descriptions honestly. Scrub known secret values, secret-like environment values, private keys, token patterns, credential assignments and URL credentials before returning either text or metadata.

`latestCheck` is null or `{summary_line,rows,created_at}`. Read the actual runtime state directory (`env.PDD_STATE_DIR`, otherwise HOME or OS home plus `.pdd/runtime`), only when outside this repo. Inspect at most 512 valid batch folders. `summary.json` must name this exact canonical repo; select the newest matching summary using batch.json `created_at`, then summary mtime as fallback. Summaries are at most 256 KiB, batch metadata 512 KiB, and raw saved replies 1 MiB. Reject symlink state ancestors/folders/files and malformed records, without falling through to other repos. State reads never create files.

Project summary rows to at most 32 `{story,state,criteria,failed_checks,criterion_results}` records: criteria is bounded passed/total counts; failed checks keep only criterion_id, target and path (at most 8); raw expected/actual/results are never returned. Load criterion_results only from the row's canonical UUID `request_id` saved next to the summary as `<request_id>.json`, under `result.report.criterion_results`; keep at most 64 valid `{criterion_id,status}` records. Supported statuses are passed/failed/unknown/not_run. Do not follow report URLs or arbitrary report paths. Missing/malformed reports leave an empty list and never invent a passed criterion.

Next-step priority: supplied progress items not passing mean Finish the Try; no check or prompt/Story file mtime newer than its creation means `pdd check STORY`; a passing selected-Story check with a draft prompt means `pdd approve PROMPT`; approved prompts and no detected code mean Make the code (PR 2). Otherwise continue reviewing the Story; failed/refused/pending checks mean recheck the Story. File mtime is only conservative recheck advice, not a claimed hash comparison with the saved upload. sourceFingerprint hashes only allowed current file contents/identities, independently of progress and saved checks. The fingerprint hashes sourceFingerprint, code-presence, safe latest metadata and supplied progress. `changed` means it differs from previousFingerprint, including first build. Rebuilds observe prompt or Story content changes even if timestamps are preserved.

Return productRules only for admitted entry prompt paths from entries (entry_path, prompt_path or entry before #). Each record is {path,text,summary,truncated}. Remove Runtime-interface details and their JSON entirely, preserving ordinary product prose and code examples. Bound every record to 6 KiB and the serialized returned list to 12 KiB; for overflow prefer headings and the first paragraphs under them, with explicit truncated:true. summary holds the compact headings/paragraphs variant for packet-level trimming. Scrub all returned prose. No productRules from an unadmitted prompt.

`readAgentScenarios({root})` is a second synchronous export returning private `{path,doc}` records for the judge, never card/packet content. Discover Git-visible JSON files safely with the same path, symlink and secret exclusions; use bounded no-follow reads up to 1 MiB per file, and require schema_version exactly prompt-runtime.program-scenario.v1. Bound to 128 scenarios and 16 MiB total serialized input; return a non-enumerable incomplete boolean on the array when listing/aggregate bounds omit candidates. Missing repo returns an empty array. Reading never writes or changes test values.

The card returns saveTarget `{path,pattern:true,exists:null,steps:null,savedCount,startKnown:false,startData}`. Every Try-page Save creates a separate scoped file with that case's exact observed starting data. The display path is the honest pattern `tests/<story>-<case-name>-<id>.json`, using the canonical saved-case path planner's Story stem; case name and identity remain placeholders until a particular case is named and saved. Never promise a specific future filename, existence or step count, choose the original seed as the destination, or claim a new case appends to any prior test. Keep the existing metadata keys for callers, with unknown existence/count/start represented as above. startData is a fixed plain explanation that each case preserves the data observed immediately before its own Run; it never contains a guessed world or the seed's final world. savedCount is a nonnegative integer from the bridge. The accepted seedTest/scenarios arguments no longer select the future save path or infer setup. Place the save-pattern line before extra file descriptions so stage, next stage and save advice survive the 1.5 KiB card limit. Actual imported case paths belong to the collector receipt/history; the card does not invent them or authorize saving/changing a criterion.

`readAgentStoryCriteria({root})` returns private `{path,criteria:[{id:'ac-N',text}]}` records from safe Git-visible Markdown under user_stories, using storyCriteria in authored source order. Never derive this order from scenario criteria arrays: unscoped tests may reorder them legally. Read only regular non-symlink files at most 64 KiB with the same ancestor/outside/secret checks. Bound to 128 Stories and 4 MiB combined text; expose a non-enumerable incomplete flag for truncated, unsafe or unreadable candidates. Return no raw Story body and never send these private records directly as packet context. Missing repository returns an empty list.

## Dependencies

- [Saved cases](agent-saved-case.prompt.md) supplies pure agentSavedCasePath for the canonical display-pattern Story stem; this module never invokes the importer or case planner.
- [Preflight](runtime-preflight.prompt.md) owns secret-path exclusion and authored Runtime interface/Story parsing; use exported isSecretPath, interfaceBlocks and storyCriteria on already safely read text.
- [Runtime client](runtime-client.prompt.md) is the navigation-only state producer. The complete consumed state-directory and bounded projection contract is above; no caller implementation is required to build this reader.
- [Runtime output](runtime-output.prompt.md) owns summary.json rows and criterion status meaning.
- Node filesystem/path/crypto/child_process/OS built-ins provide local safe reads, identity and Git visibility.
