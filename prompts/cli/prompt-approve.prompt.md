# Prompt approve

Own `src/prompt-approve.mjs`. Export `runApprove({words, cwd, said}, ports)` (returns an exit code) and `approvePromptText(text)` (returns the approved text or null). `pdd approve PROMPT` records a person's decision for plain Markdown prompts, frontmatter `kind: native-only` prompts, and prompts with an embedded Runtime interface block through terminal y/N or, in easy mode, an agent-supplied `--said` value after the person approves in chat. Preserve existing exports, including `presentAndApprove`, and the Prompt Interpreter callback behavior; this command adds no browser approval route.

## Steps

1. PROMPT is one path (relative to cwd). It must be a Git-visible `*.prompt.md` file in the repo (`git rev-parse --show-toplevel`), else exit 2: `<path> is not a Git-visible *.prompt.md file in this repository.`
2. Resolve repository policy through the required shared owner before any write. In strict mode --said always refuses before reading stdin. After policy/configuration prechecks, resolve present `said` through the shared person-words helper; invalid or blank input exits 2 without changes. Keep accepted words verbatim. Without said, easy mode retains its existing both-TTY requirement; strict mode additionally excludes agent-marker and current workflow-chat-pane invocations. A refused route uses exit 2, `pdd approve is for a person at a terminal. Ask the person to run: pdd approve <path>`. Nothing changes.
3. Before reading the prompt or taking the already-approved fast path (including the Prompt Interpreter callback), refuse with exit 4 when PROMPT is a misplaced test prompt (`isTestPromptPath`) or claims any test file (`isTestOwnedPath`) via `pdd-bindings.json`, Git-visible test headers or opening-sentence prose (`findTestPromptViolations`), and refuse with exit 4 (`formatStoryLint`) when any authored or changed Story file (`isLintableStoryPath`) in the checkout (uncommitted, untracked, changed since `origin/main` or `main`, or present in a single-commit repository) fails local [Story quality lint](story-lint.prompt.md). Read the prompt through the required shared authored-file reader (`readPrompt`). Plain Markdown prompts (`!blocks.length`), frontmatter `kind: native-only` prompts, and single-block embedded Runtime interfaces are valid; duplicate blocks, invalid JSON or frontmatter, unsafe/missing/cyclic contract references, and schema problems refuse (`promptSchemaRefusals(..., { allowMissingInterfaces: true })`) with the same reason as lint/test before any question or write. Keep the authored bytes for the edit and prose view. A reader source/reference failure returns the same declined result and reason to the Prompt Interpreter callback; it must not escape before the callback can record that refusal.
4. Check the Prompt Interpreter callback's `expectedHash` before schema diagnostics: a different `proseSha256` declines with the existing changed-prompt reason and no question or write. After the shared parse/schema checks pass, when a plain or frontmatter `native-only` prompt already has a matching `proseSha256` recorded in `<git-common-dir>/pdd/approvals.json` (`readPromptApprovals`)—or an embedded Runtime interface has `"status": "approved"` with matching `prose_sha256`—print `<path> is already approved and current.` and exit 0.
5. Use the shared reader's `promptSchemaRefusals(..., { allowMissingInterfaces: true })` for the prompt and called prompts. Print every problem with its code, section, message and fix hint, then `Fix these before you approve.`, exit 4. Contract references stay authored references on disk; when an embedded Runtime interface exists, the approval view shows its resolved fields, types and constraints.
6. For a plain Markdown prompt, show `<path>` (or `<path>` with its `Kind: native-only` and `Reason:` for frontmatter `native-only`), then the compact `<= 25`-line advisory [Human boundary card](human-boundary-card.prompt.md), followed by the prose view. For an embedded Runtime interface, show `<path> (<status>)` (plus `Kind:` and `Reason:` when `native-only`), then the compact `<= 25`-line advisory [Human boundary card](human-boundary-card.prompt.md) above raw schema and prose details, then for each entry `Operation <name>`, `Input:` and `Result:` with one line for each field (`name: type, rule`; nested lists and objects indented; a field not in `required` is `(optional)`; an enum is its values; `oneOf` is its variants joined with `or`), and `Errors: …`, plus calls, resources, and any interface diff since the last approved Git version (`The Runtime interface has one global status. The whole interface needs re-approval.`). The boundary card is strictly advisory: it surfaces owned policy, per-rule/criterion source and observation provenance (`supplied fact`, `model-returned value` with port-spy/native note on returned effects, `observed simulated port call` including `0 observed port calls`, `native test`, and `missing owner connection` when an owning source or rule is not exercised), the runtime vs. `native-only` verification split, prose/step complexity budgets, and saved multi-sample divergences without blocking approval or altering `native-only` eligibility. The prose is the file text without any embedded Runtime interface block. The last approved version is the newest Git commit (of the last 200 that touch the file) whose file text either has `"status": "approved"` with matching `prose_sha256` or whose `proseSha256` appears for `path` in `<git-common-dir>/pdd/approvals.json`. With one: `Text changes since the last approved version (<first 12 of its commit>):` and the changed lines, `  - ` for a removed line and `  + ` for an added one, with 1 unchanged line around each change (`    ` in front) and `  …` between parts; or `Text: the same as the last approved version (<commit>).` With none: `Text (no approved version in Git, so all of it):` and every prose line, 2 spaces in, without the empty lines at the end. Show at most 40 of these lines, then `… N more lines not shown.` and `See all of them with: git diff <commit> -- <path>` (or `Read the whole file: <path>`). Never cut inside a line; remove control characters so that terminal codes cannot hide text. When an embedded block was approved or a journal approval exists for an earlier prose hash: `The text changed after it was approved. Read the prompt again before you answer.`
7. With valid said in easy mode, use the resolved words as the decision without another stdin read or a native conversation-log lookup. Otherwise ask `Approve <path>? y/n ` and read one line. On the terminal route only `y` or `yes` (any case) approves. Anything else, or no answer: `Not approved. Nothing changed.`, exit 1.
8. On terminal yes or accepted said: for a plain Markdown or frontmatter `native-only` prompt, do not mutate `<path>` on disk; record durable evidence in `<git-common-dir>/pdd/approvals.json` (`recordPromptApproval`) with the current path, `proseSha256` (plus `kind` and `reason` when `native-only`), invoking actor, route, clock time, and verbatim words (`null` for terminal). For an embedded Runtime interface block, set top-level `"status"` to `"approved"` and top-level `"prose_sha256"` to the current prose hash while keeping every other byte unchanged (exiting 4 with `Add "prose_sha256": "" to the Runtime interface, then run pdd approve again.` when `"prose_sha256"` is absent), verify the updated block and unchanged prose hash, write the file, and record durable evidence in `<git-common-dir>/pdd/approvals.json`. Print `Approved <path>.`, the approved path/hash and a short evidence line; exit 0 only after evidence is saved. Already-approved/current files keep their existing no-op output and do not invent another approval.

Ports (tests inject them): `stdout`, `stderr`, `stdin`, `interactive` (default: stdin and stdout are TTYs), `env`, `now`, filesystem and Git execution ports for policy/journal/root resolution. Native filesystem/hash/TTY effects require native tests, not a surrogate Runtime operation.

## Native-only approval

Show a native-only declaration's kind and reason before approval (whether authored via YAML frontmatter `kind: native-only` + `reason` or an embedded Runtime interface block). It is eligible for the person routes after kind/reason validation, without entry schemas or limits. Record the kind and reason with its path/hash. Validate before the already-approved fast path too.

## Dependencies

- [Runtime seam](runtime-seam.prompt.md#public-contract): required generation, verification, and testing context for the shared authored-file reader (`readPrompt`, `parsePromptFrontmatter`, `promptRefusal`, `promptSchemaRefusals`, references, and numeric tokens) from `@promptdriven/runtime-client`.

- [Approval policy and journal](approval-policy.prompt.md): required authoring/generation/native-production/verification/testing context for config, actor, evidence shape and storage.

- [File owner](file-owner.prompt.md) and [Story quality lint](story-lint.prompt.md): required generation/verification context for refusing test-prompt ownership (`findTestPromptViolations`) and low-level Story plumbing (`lintStories`, `formatStoryLint`).

- [Human boundary card](human-boundary-card.prompt.md): required authoring/generation/verification context for building and formatting the compact `<= 25`-line advisory boundary card and source/observation provenance above raw schema and prose details.

Read the full [Prompting guide](../../skills/pdd/references/prompting.md) before you change this prompt. Follow the [alpha boundary](public-boundary.prompt.md).

## Caller navigation

The [CLI](pdd-cli.prompt.md) routes `pdd approve PROMPT` here. `@promptdriven/runtime-client` (bound by [Runtime seam](runtime-seam.prompt.md)) uses the same view and edit for Try-page approvals.

Use “Runtime interface” when naming the declaration and its global approval status in user messages.
