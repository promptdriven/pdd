# Sort observations and effects

Own sort integration with GitHub and local area/release data. Use injected ports
for GitHub, settings, files, clock and waits. The native adapter reads root pdd.json,
CODEOWNERS (.github first, then root, then docs) and package version. The resulting
area/release fingerprint and each issue's routing labels (omit only pdd:working, pdd:stuck, pdd:code-pending, pdd:close-proposed and pdd:needs-owner unless an area rule names them) are snapshot inputs. Draft signals include past assignees from the already observed assignment timeline. No extra issue or model reads for
classification: use the dependency snapshot and coordinator analysis.sorts.
The prepareSortContext input admits the full normalized dependency snapshot, including its issue metadata, saved reviews, impacts, edges, capture time and warnings. Preserve the existing required input fields; extra admitted metadata does not authorize routing. Prepare supplies sort context in contextJson. The existing delivery fingerprint includes relevant sort input revisions and sort heads, so an input change delivers a fresh request. Queue issues with no current sort
alongside ordinary dependency subjects, at most 10. Completion requires one sort
per requested issue only when sort context is supplied. Reuse current records.
Validate the entire sort batch and reread current inputs before saving any sort.
Save one immutable sort comment, with named base IDs and human readable evidence.
Untrusted or edited sort comments cannot supply decisions. Record comments are
bookkeeping and do not stale requirements or dependency review.

Routing uses current mode and rereads it after any pacing wait. It rereads the issue's assignees and live claim before
each effect. Read ownership again after the comments, source, area/release and timeline checks, as the last evidence read before the effect. Native close/assignment updates accept checkOwnership(), which must run inside admitMutation after any admission wait; false stops the PATCH. The final issue response must still match the recorded issue and label inputs. A missing or changed final response holds the route. After pacing, reread trusted requirement comments, sort heads, examined source and area/release inputs too. Missing or changed evidence stops effects. Never close or assign a person-owned or live-claimed issue. A remaining work label is safe only when the current claim observation confirms it expired. Off writes
nothing. Auto: one evidence comment with a reopen hint, then close. Observe:
pdd:close-proposed and one evidence comment, leave open. Assign another login
with one comment and no start. For another repository write one link note and
no start. Unsure: pdd:needs-owner and one question. Every write is serial, at
least 1000 ms after the preceding write, including record saves. The shared writer checks current mode after each wait, before both record and route effects. Use immutable
comment bodies to recover retries. A failed or unconfirmed write stops the batch;
never blindly retry it. Confirm comments and issue updates by readback. Missing comment identity or update confirmation stops the route before further effects. Labels are created and attached only when absent. Remember the hash marker of trusted intact route notes as issue.sortRouteNotes. Skip already completed link, question and observe routes before applying the 10-route cap so later issues progress. Native non-GET REST effects, including label creation, issue PATCH, issue creation and label attachment, all cross admitMutation immediately before transport. Preserve final ownership/evidence checks. Each routing invocation admits at most 10 currently actionable issues; stale or newly owned candidates do not consume those slots. Check the budget while scanning candidates and each shared sort stream permits at most 20 write attempts (record saves included). Remaining effects wait for a later tick. Check the existing machine GitHub budget before each native effect and each paced action; low or reserve stops the stream without another approval gate. Do not change claims, trust, approvals or merging.

Load/save group lifecycle state through sortGroups.read/save({cwd,repository,groups?}) returning {groups}/{ok}; native default is repository Git-common-dir pdd/issue-groups.json. Missing state starts empty; malformed/unreadable state holds sorting. Compare saved sorts, not refetched full issue bodies, to compute membership. Save state after confirmed effects. Recover a dedicated umbrella by its exact pdd-issue-group:v1 cause marker in the trusted open issue index before creating one. Creation must hold repository-shared cause admission, independent of checkout state. Use github.withSortGroupAdmission({repository,rootCause,write}, action): run action only after exclusive admission; return without running it when another coordinator holds admission. The native adapter atomically creates refs/heads/pdd/issue-groups/<SHA-256 of rootCause>, pointing to the current HEAD commit. A failed reservation never authorizes creation. Under admission reread every page of the current open issue index and verify author trust before marker recovery. Duplicate markers remain held. Recover one trusted marker, otherwise validate members and create. Release the reservation only after the action returns a confirmed issue identity or a safe no-effect result. On an exception or uncertain creation, retain it: later observations may recover a confirmed marker, but elapsed time must never permit a second POST. This reservation protects issue creation only; it does not claim members or authorize work. Reservation creation and deletion use the shared paced writer, budget and native mutation guard. The paced writer exposes read-only remaining (write attempts left of 20); reserve only with room for reservation, issue creation and release. Save confirmed group progress even when a later group exhausts the budget. In auto, create one "Global fix: <cause>" issue at 3+ members or across areas, with member links, cause and one fix statement plus member evidence. Observe keeps a group proposal without creating an issue. Recheck current member ownership/evidence after pacing before creation or a join note. Group effects share the 20-write bound and admission guard. Retain a running umbrella, including an existing pair work issue; defer creation of a replacement while it is occupied. Validate idle members before its note, leaving the occupied umbrella untouched except for that note. Post an idempotent join note naming the complete current member set.
For every closed saved group work issue, including a pair work issue, read its newest CLOSED_EVENT through GraphQL. Only a PullRequest closer with merged:true and a valid PR URL is merge evidence. Treat only a merged PR which closes the umbrella as the global fix. Persist its URL and each member's sort-head IDs as the recheck boundary; queue a fresh sort for each member. Never infer merge from mere closure, an unrelated merged mention, or an open PR. Closed or unavailable umbrellas without merge evidence hold their members. Include saved umbrella URLs in the dependency observation scope, even after they close. Group state and notes are bookkeeping, not new requirements. The current sort record and ordinary dependency review still own eligibility.

The native ports consumed here are github.issue({repository,issue}) and
page({repository,issue,kind,cursor}), which return {json}; appendComment accepts
{repository,issue,body} and returns the confirmed comment in {json}; sortUpdate
accepts {repository,issue,label?,assignee?,close?} and returns {ok}; ensureSortLabel
accepts {repository,label,write}. owners.read({repository,issues}) returns {json}
with current claims. context.read({cwd,repository,inputs}) returns {json} with
current source rows. settings.read({cwd,repository}) returns {mode}. clock.now({})
returns {iso}; wait.sleep({ms}) waits. sortContext.read is an optional injected
local area/release source. Invalid sort comments retain identity and authority but
expose record:null and intact:false. This owner declares these transport shapes;
the dependency reader retains its own trust, claims and native observation rules.

`readSortGroups({cwd,repository}, ports)` returns a validated group array from the group store and rejects malformed or unavailable state. `syncSortGroups({cwd,repository,snapshot,mode}, ports, write?)` returns and persists current groups, updates snapshot.sortContext.groups, and performs only confirmed group effects. It is called before ordinary routing on completion and reconciliation. Its optional writer is the shared paced stream. Missing write ports, changed ownership/mode/budget, or an unconfirmed effect leave work pending; never approve a prompt or merge here. `github.createSortUmbrella({repository,title,body})` returns {json} containing the created issue after readback. `github.sortMergedFix({repository,issue})` returns {url}, empty when no merged closing PR is proved. Native group creation and label creation also use admitMutation.

Mixed part orchestration delegates to issue-mixed using the same paced writer
before normal routes in both completion and reconciliation. Save comments only
while the subject remains unassigned and unclaimed. Whole assignment notes list
all touched areas and their evidence. For a confirmed split parent, current child
completion replaces pre-split source evidence for closure admission; verify both
children again after waits. All label, comment and native update effects carry
an ownership guard inside native mutation admission.
