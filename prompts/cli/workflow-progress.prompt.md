# Foreground workflow progress

Own src/workflow-progress.mjs. Export createWorkflowProgress({stdout,now}), returning observe(event) and interrupt(). This is a renderer, with no repository reads, run allocation, stage effects or decisions. A person starting an issue run must immediately see that PDD is working, learn the saved run and agent location, review the proposal at a gate, and find that same run after an interruption. Preserve 0.1.0 identities and controller semantics.

When the actual run becomes known, print one line with the full run ID, workflow, `#`issue number and quoted issue title (when known) and current stage ordinal/count; then `Working copy: <worktree> (branch <branch>)`; then `Watch live: pdd workflow attach <full UUID>` exactly once. Never print the journal path or other internal run files, in normal or interrupt output. Print the actual agent and Herdr session/workspace as one line (`Codex is working in Herdr session S, workspace W.`), once per new identity and only after the workspace exists; never print a placeholder, never substitute the default session and never repeat the attach command there. Reuse the plain summary/read/approve/PR formatting of the existing watch design, without importing newer commands or state layout.

Timestamps are the person's local clock as 24-hour `HH:MM` followed by two spaces, never ISO text; accept an optional timeZone so tests are stable.

Each agent/PR intent prints a timestamped `<stage> started`. Completion, skip, human approval and test execution changes print timestamped lines tied to the actual stage (`<stage> done`, `<stage> skipped`, `<stage>: running approved tests`, `<stage>: tests passed|failed`). Repeated backend polling adds no repeated lines, except a timestamped `<stage> still working (N min)` each time another two minutes have passed since that stage started, checked as observations arrive; none after the stage ends or reaches a result. Result states print a timestamped line: a waiting gate says `waiting for you before <stage>`, a merge wait says `waiting for you to merge the PR`, and other states say `<stage>: <state>`. At a waiting gate show accepted artifact JSON and project file paths plus a short agent summary, preserving any recommendation contained in it, and the exact full-ID resume --decision approve command. Optional gates also show --decision skip. For an unresolved pending stage print inspect and attach guidance; do not call it approved. Merge waits show saved PR links, say the person must merge, and use no-decision resume. Always print known PR URLs at final results. Show the runner's actual final message separately, once, through the CLI.

Collapse terminal control characters and newlines in all interpolated values. Keep summaries to a short readable line. Do not shorten IDs in executable commands. Observations must not mutate caller data. Track state only within this renderer instance. interrupt() prints that the foreground controller stopped and the agent may keep working in Herdr, then the known attach/inspection commands and an explicit approve command for continuing after inspection. Before an identity is known, explain that preparation was interrupted and point to the repository's existing .git/pdd/workflow-inputs directory; never fabricate a run ID or promise continuation.
