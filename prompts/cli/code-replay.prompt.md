# Code replay evidence

Own `src/code-replay.mjs`. Validate agent-supplied native replay records so prompt-runtime success cannot imply that production code replayed the original cases. This is an audit guardrail, not a security boundary: an agent can fabricate execution records. This module never executes code, contacts a service or proves equivalence. Preserve the real outcomes, source identity and incomplete work.

Export `sourceFingerprint(root)` for Git-visible content identity (sorted paths, file bytes, executable bits and symlink targets, including uncommitted files; unavailable identity returns null); `freezeReplayVectors(root, {committed: false})` for a versioned inventory of all discoverable scenario JSON paths and SHA-256 bytes; and `readCodeReplay({root, runDir, baseline})` returning a JSON-safe outcome, reason, counts and manifest hash; and `codeReplayLine(outcome)` for a prominent status/count line with the execution trust boundary. Freeze before code work. The runner passes `committed: true` to inventory regular JSON blobs from the chosen Git HEAD tree, never dirty or untracked expectations. Current reads still require identical original file bytes. This baseline is immutable during code work. A missing/empty/invalid inventory is blocked. Paths must remain repository-contained regular files. The manifest is a regular file at `runDir/code-replay.json`, at most 2 MiB.

## Manifest and outcomes

`schema_version` is `code-replay-v1`; `source_sha256` equals the current source fingerprint. `vectors` contains exactly one `{path, sha256, steps}` for each frozen file, with its unchanged hash. Each original step has exactly one row, in order, with original `step_id` and `operation`, plus `execution: {executed, boundary, command}` and `checks`. Each check row, in order, repeats original `criterion_id`, `target`, `path` and `op`, and has `status: pass|fail|blocked|not_replayed`. Pass/fail rows also carry the observed `actual` JSON value (including null when that is the observation); non-pass rows need `reason`; unsupported targets can never pass. Valid unrelated JSON containing scenario terminology is not a vector; classify by its schema_version prefix, while malformed JSON containing that terminology remains unreadable. Scenario schema must be exactly `prompt-runtime.program-scenario.v1`. Its criteria have nonempty unique IDs and text; each check names a declared criterion, a nonempty string target/op and a valid JSON Pointer path (the empty root pointer is allowed). Reject nonfinite JSON numbers in vectors or evidence, including overflow parsed from a numeric literal. Every step must have checks; every original check must appear exactly once. Execution is asserted only with literal `executed: true` and nonempty boundary/command. Missing execution is not replayed even if checks claim pass. No free-form PASS inference.

`mutation` supplies `{kind: "semantic", command, assertion_failures, crashed: false}`. Detection requires a positive integer assertion failure count, never a crash. `formal` supplies `status` from `proved_bounded|proved_solver|failed|not_run|not_applicable`; all need a nonempty `rule`. Proved results also need `bounds`, `command` and a detected semantic `control`; failed needs `counterexample`; not-run/not-applicable need `reason`.

Derive exact counts from rows. Identity/shape errors yield `blocked`, without trusting supplied counts. Otherwise precedence is actual failed assertions or formal failure → `fail`; blocked rows, missing semantic control or formal not-run → `blocked`; unmapped checks or unexecuted operations → `not_replayed`; complete replay and adequate controls → `pass`. Every outcome may be published prominently for review. Always label supplied execution evidence as agent-reported; structural validation is not independent execution verification.

## Dependencies

- [Runtime preflight](runtime-preflight.prompt.md): `gitFiles` and `findTests` inventory discovery for freezing and source identity. Node filesystem, path and crypto supply local reads and SHA-256. No model/service calls.


A synthetic check row is `{"criterion_id":"AC1","target":"result","path":"/value","op":"equals","status":"pass","actual":2}`. This is a shape example, not executed evidence. Use the unchanged scenario's check order and identity. `actual` records the selected observation; it is not a substitute for executing the assertion in the replay runner. This validator does not reimplement the assertion language.
