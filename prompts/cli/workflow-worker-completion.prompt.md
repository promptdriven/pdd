# Automatic worker completion

`src/workflow-worker-completion.mjs` connects a confirmed automatic worker launch to the existing capacity yield. Its module function `armWorkerCompletion(identity, ports)` starts one detached listener and returns without waiting for the worker. The identity captures the issue, source root, run ID, current area, pane and launch attempt. The caller arms only a positively launched automatic chat, for a fresh pane or a supported current automatic resume. Manual and historical chats are not armed. A resumed pane must first reach native `working` after the resume before its subsequent native `done` can signal completion; a prior turn’s `done` is not completion of the resume. Save positive activity against the current run, area, pane and resume anchor, so an explicit Autopilot start can recover observation after a listener is lost. A changed anchor invalidates that evidence.

During the shared startup grace, an `agent_not_found` reply for the captured fresh pane is a registration gap: retry the native wait while the captured run, area, pane and launch anchor remain current. Grace expiry or another failure leaves completion unknown. The listener waits for the captured pane to reach native `done` through `herdr --session pdd agent wait PANE --until done`, with no timeout. It neither resends the first prompt nor treats idle, elapsed time, failure or an unavailable listener as completion. On successful native wait, it calls the existing yield with the captured identity; yield owns native confirmation, current ownership and allocation checks. An old listener must not yield for a replacement run or attempt. The caller must ensure the listener belongs to the launched attempt, including that a prior turn's `done` cannot be mistaken for the new attempt.

The outside-program port starts the listener using the current Node executable, module path and serialized identity, detached with ignored standard streams, and unrefs it. The long native wait uses an outside-program port without the ordinary short command timeout. No service is created; retries are confined to the startup registration gap. Failures leave completion unknown and do not call yield.

## Dependencies

- [Workflow runner](workflow-runner.prompt.md): runtime ownership, yield policy and captured-identity admission; the runner supplies the launch hook and rechecks identity inside yield.
- Herdr's `agent wait` command supplies the native completion event; [workflow chat](workflow-chat.prompt.md) owns the startup grace and launch anchor.

The executable one-shot listener accepts a serialized context or a context file. After worker completion it reads the local Autopilot state for the canonical source root. If enabled, the saved coordinator pane must match the captured coordinator pane, and the listener waits in session `pdd-autopilot` until that pane is idle or done before requesting yield. If disabled, it may request yield for inactive cleanup without waiting. Missing or mismatched state leaves completion unknown. Under the existing run lock the listener checks run ID, area, pane and launch anchor against its captured identity, and supplies that identity and the lock release to yield. Yield rechecks the identity and releases the lock before its completion tick. The listener always releases the lock on exit. Reused panes require independent activity provenance; current done alone does not establish a resumed attempt completed.

Explicit Autopilot start may rearm saved current automatic chats belonging to its repository and coordinator. Resumed chats without saved positive activity still require native working before done; fresh panes or resumed chats with matching saved activity can wait for done. A grace-expired registration or failed native wait remains unknown; tell the person that explicit inspection and `pdd workflow yield` after positive completion evidence are the fallback, without promising a later wake.
