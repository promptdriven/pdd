# Autopilot metrics calculator

Own `src/metrics-model.mjs`. Export pure deterministic functions `SKILLS`, `GATES`, `PR_GATES`, `PROMPT_CHECKS`, `localAnchorUtcMs`, `resolveStandupWindow`, `buildFunnelSummary`, `computeStageFunnel`, `evaluateMatureCohort`, `extractGraphQlReopenedEvents`, `validateRepoName`, `normalizeSkill`, `normalizeMetricsConfig`, `isMetricsEnabled`, `applyMetricsToggle`, `calculateAutopilotMetrics`, `formatMetricsText`, and `renderMetricsHtml` (delegating DST-safe standup window, stage funnel, and 7-day cohort helpers to `src/autopilot/metrics/funnel-cohort.mjs`). Perform no filesystem, network, process, or clock I/O, and never mutate caller inputs.

## Domain decisions

- **Autopilot-only scope & configurable monthly targets.** Metrics summarize local Autopilot runs across one or more `owner/repo` repositories on this machine, enriched with optional GitHub open/closed issue data, reconciled PR merge states, and auto-detected regressions supplied as pure inputs.
  - Configurable monthly target defaults live in `config.targets`: `{ convMinPct: number, maxRegressionPct: number, label: string | null }`, defaulting to `{ convMinPct: 90, maxRegressionPct: 0, label: null }` when absent or invalid (`convMinPct` and `maxRegressionPct` must be finite numbers in `[0, 100]`; `label` is a trimmed non-empty string or `null`).
  - Resolve the active month abbreviation (`month`) in `timezone` from `date` (when supplied) else `now` (`Intl.DateTimeFormat("en-US", { timeZone: timezone, month: "short" })`, e.g., `"Nov"`).
  - `overview.target` is `{ label, month, convMinPct, maxRegressionPct, convDisplay, regressionDisplay }`, where `label` is `"Target (${targets.label ?? month})"` (e.g., `"Target (Nov)"`), `convDisplay` is `">=${Number.isInteger(convMinPct) ? convMinPct : convMinPct.toFixed(1)}%"` (default `">=90%"`), and `regressionDisplay` is `"${maxRegressionPct.toFixed(1)}%"` (default `"0.0%"`).
- **Recording switch (`on` / `off`) & per-repo exclusion.** Recording configuration has shape `{ enabled: boolean, repos: { [repoLower]: boolean } | Array<{ repo: string, enabled: boolean }>, pausedSince: string | null, repoPausedSince: { [repoLower]: string } | Array<{ repo: string, pausedSince: string }>, pausedIntervals: Array<{ repo: string | null, from: string, to: string | null }>, targets: { convMinPct: number, maxRegressionPct: number, label: string | null }, updatedAt: string | null }`. Missing or empty configuration defaults to `enabled: true`, empty `repos`, empty `pausedIntervals`, and default `targets` (`normalizeMetricsConfig`, normalizing both plain-object maps and `{ repo, enabled }` / `{ repo, pausedSince }` entry lists cleanly).
  - `isMetricsEnabled(config, repo)` checks `config.repos[repoLower]` when boolean; otherwise returns `config.enabled !== false`.
  - `applyMetricsToggle({ config, action, repo, at })` (also accepting positional `(config, { action, repo, at })`) accepts `action` `"on"` or `"off"` (else throws code `"invalid-action"`), optional `repo` matching `OWNER/REPO` (`validateRepoName`, else throws code `"invalid-repo"`), and UTC timestamp string `at` (default `"1970-01-01T00:00:00.000Z"` if omitted in pure tests, invalid throws `"invalid-at"`). Preserve `targets` across toggles.
    - Turning `"off"` globally (`repo` omitted) sets `enabled: false`, starts an open global interval `{ repo: null, from: at, to: null }` when not already globally paused, and sets `pausedSince: at`.
    - Turning `"on"` globally sets `enabled: true`, closes any open global interval (`to: at`), and clears `pausedSince: null`. `"off"` with `repo` sets `repos[repoLower] = false`, sets `repoPausedSince[repoLower] = at`, and opens `{ repo: repoLower, from: at, to: null }`; `"on"` with `repo` sets `repos[repoLower] = true` (or deletes `repos[repoLower]` when global `enabled` is true), deletes `repoPausedSince[repoLower]`, and closes open intervals for `repoLower`.
  - **Excluding turned-off repos in unified rollups:** When `repoFilter` is unset, any repository with `recording.repos[repoLower] === false` (turned off via `pdd metrics off --repo OWNER/REPO`) is excluded completely from `repos`, `scopeLabel`, `openNow`, `Pool`, `Taken`, `PRs`, `Merged`, `Regressions`, `Stages`, and `Skills`, even if it has prior runs or entries in `repos`/`openIssues`. When `repoFilter` explicitly names that repository, include only that repository, apply `pausedIntervals`, keep pre-pause history visible, and report `recording.enabled = false`. Global `recording.enabled === false` (without per-repo `false`) keeps pre-pause history visible in unified rollups while excluding runs inside global `pausedIntervals`.
  - Any run whose start time (`startedAt`, else `at`) or completion time (`at` when `status !== "running"`) falls inside a matching global (`repo: null`) or repository (`repo: repoLower`) paused interval `[fromMs, toMs ?? Infinity)` is excluded from calculations while all runs completed before `fromMs` or started after `toMs` remain visible.
- **Repository normalization and explicit named scope label.** Repository names validate as `OWNER/REPO` and deduplicate case-insensitively (`repoLower = repo.toLowerCase()`), keeping the first canonical display casing supplied in `repos` or `runs` (falling back to `repoFilter` casing when the repository is not yet in `repos` or `runs`). Sort included repositories by `repoLower`. When `repoFilter` is given, validate `OWNER/REPO` (invalid throws `"invalid-repo"`) and restrict the report to that repository (displaying it even when it has 0 runs).
  - Build explicit repository names instead of opaque `"Unified (N repos)"`: for `reposList`, extract short repo names (`repo.split("/")[1]`); when all short names are unique case-insensitively use short names, otherwise keep full `owner/repo` for colliding short names. Join with `" + "` (e.g., `"pdd + pocket"`, `"pdd"`, or `"0 repos"` when empty).
  - `scopeLabel` is `repoFilter` when `repoFilter` is set, `"Per Repo · ${repoNamesLabel}"` when `byRepo` is true, else `repoNamesLabel` (e.g., `"pdd + pocket"`).
- **Time windows.** Validate `now` (ISO-8601 UTC timestamp, default `"1970-01-01T00:00:00.000Z"` if omitted in pure tests, invalid throws `"invalid-now"`) and `timezone` (valid IANA timezone via `Intl.DateTimeFormat`, default `"America/Los_Angeles"` when `standup: true`, else `"UTC"`, invalid throws `"invalid-timezone"`). Export DST-safe `localAnchorUtcMs(year, month, day, hour, timezone)` solving the exact UTC timestamp for a wall-clock anchor hour across DST transitions.
  - Without `date` and `standup` false, compute two windows:
    1. `last24h` (`label: "Last 24h"`): `[nowMs - 86400000, nowMs]`.
    2. `week` (`label: "Week (Mon-Sun)"`): local Monday `00:00:00.000` in `timezone` of the week containing `nowMs` through `nowMs` (Monday is day 1, Sunday is day 7, refreshing every Monday at `00:00` local time).
  - With `standup: true` and no `date`, compute two windows:
    1. `standup` (`label: "Standup (9am-9am PT)"` for `America/Los_Angeles`, else `"Standup (9am-9am)"`): local `09:00:00.000` yesterday through `today 09:00:00.000 - 1ms` when `nowMs >= today 09:00`, else through `nowMs`.
    2. `week` (`label: "Week (Mon-Sun)"`): local Monday `00:00:00.000` through `nowMs`.
  - With `standup: true` and `date` (`YYYY-MM-DD`), compute one window:
    1. `standup` (`label: "Standup ${date} (9am-9am)"`): local `09:00:00.000` on `date - 1 day` through `09:00:00.000 - 1ms` on `date` in `timezone` (exact 23h on spring-forward, 25h on fall-back, 24h otherwise).
  - With `date` (`YYYY-MM-DD` real calendar date, invalid throws `"invalid-date"`) and `standup` false, compute one window:
    1. `date` (`label: date`): local `00:00:00.000` through `23:59:59.999` on `date` in `timezone`.
  - Funnel & Gates (`stages`) and Work Mix (`skills`) evaluate the primary window: the single window when `date` is supplied, else `week` (`Week (Mon-Sun)`).
- **GitHub PR merge state reconciliation & per-issue deduplication.** Each input run has `{ repo, issue, issues?, skill?, startedAt?, at, status?, outcome?, pr?, prCreated?, mergedAt?, prMerged?, gates?: { runtime?, vectors?, formal?, suite?, review?, ci?, e2e? }, gateCounts?: { runtime?: { passed: integer, total: integer }, vectors?: { passed: integer, total: integer }, formal?: { passed: integer, total: integer } }, reopened?, reverted?, regressionIssues?, durationMinutes?, promptChanged?, pathsOnlyD?, title? }`.
  - Optional `prStates` array of `{ repo: string, pr: integer, merged: boolean, mergedAt?: string | null, state?: string | null }` reconciles actual GitHub PR merge state for any run matching `(repoLower, pr)`:
    - When `prState.merged === true` or `prState.state === "MERGED"` or valid `prState.mergedAt` (and any provided `prState.mergedAt` is `<= nowMs`): reconcile the run as `merged: true`, effective `status: "merged"`, `prCreated: true`, and `mergedAt: prState.mergedAt ?? run.mergedAt ?? run.at` (upgrading `observe` `would-merge`, `stopped`, `ended`, `needs-person`, `running`, `released`, or `abandoned` runs whose PR actually merged on GitHub). Historical `--date` windows do not count a PR as merged if its reconciled `mergedAt` is after `window.endMs`.
    - When `prState.merged === false`: reconcile `merged: false` and preserve `prState.state` (`"OPEN"` / `"CLOSED"`); an unmerged `would-merge` PR is not counted in `Merged` and classifies under `Unmerged PRs`.
    - When no matching `prState` is supplied (offline or pure input without `prStates`): `merged` is `status === "merged" || run.prMerged === true || validTimestamp(run.mergedAt)`; backward-compatible `mwmFlag` is `merged || status === "would-merge"` (when `prState` explicitly reports `merged === false`, `mwmFlag` is `false`).
  - A run belongs to window `[startMs, endMs]` when its activity time `atMs` (`Date.parse(run.at ?? run.endedAt ?? run.updatedAt ?? run.startedAt)`) or reconciled `mergedAtMs` satisfies `startMs <= ms <= endMs`, or when `run.status === "running"` and `startMs <= nowMs <= endMs` with `(startedAtMs ?? atMs) <= endMs`.
  - Expand grouped runs (`issues` array of positive integers) or single `issue` so each `(repoLower, issue)` taken in the window is counted once (`taken`). When multiple run records exist for the same `(repoLower, issue)` in one window, select the winning record by outcome rank (reconciled `merged` = 6 > `would-merge` = 4 > `running` = 3 > `needs-person` = 2 > `ended` / `failed` / `released` / `stopped` / `abandoned` = 1), breaking ties by latest `atMs`.
  - For `PRs` (`prCreated`), count distinct `(repoLower, issue)` entries with a positive integer `pr`, `prCreated === true`, `merged === true`, or `status === "would-merge"`. For `Merged` (`merged`), count entries with `merged === true`. For backward-compatible `mwm`, count entries with `mwmFlag === true`.
  - Conversion percentage `convPct` is `taken === 0 ? null : Math.round((merged / taken) * 1000) / 10`, formatted in `mergedDisplay` as `"${merged} (${convPct.toFixed(1)}%)"` when `taken > 0`, else `"0 (n/a)"`. Backward-compatible `mwmDisplay` formats `mwm` over `taken` identically (`"${mwm} (${mwmConvPct.toFixed(1)}%)"` or `"0 (n/a)"`).
- **Live `Open now` & accumulated window `Pool`.**
  - Live `openNow` resolves across included (non-excluded) repositories from `openIssues` (`{ [repo]: non-negative integer | null } | Array<{ repo: string, count: non-negative integer | null }> | null`) or `openIssueNumbers` (`Array<{ repo: string, issues: integer[] }>`): sum per-repo live open counts when every included repository has a numeric count (or `0` for `0` repositories when `openIssues` or `openIssueNumbers` is provided as an object/array); else `null` (`openNowDisplay: "?"`). Keep backward-compatible `open` / `openDisplay` on each Overview row equal to that scope's live open count (`openNow` / `openNowDisplay`, or per-repo open count in `perRepoWindows`).
  - Per-window `Pool` (`pool: integer | null`, `poolDisplay: string`) deduplicates `open now ∪ closed in window ∪ taken in window` per included repository using optional `openIssueNumbers` (`Array<{ repo: string, issues: integer[] }>`) and `closedIssues` (`Array<{ repo: string, issue: integer, closedAt: string }>` filtered to `startMs <= Date.parse(closedAt) <= endMs`):
    - If neither numeric `openIssues[repoLower]` nor `openIssueNumbers` entry exists for an included repository, `pool` is `null` (`poolDisplay: "?"`).
    - When `openIssueNumbers` is supplied for repository `r`: let `openSet` be its distinct positive issue numbers, `openCount` be numeric `openIssues[r] ?? openSet.size`, `unlistedOpen = Math.max(0, openCount - openSet.size)`, `closedSet` be distinct issue numbers closed in `[startMs, endMs]`, and `takenSet` be distinct issue numbers taken in `[startMs, endMs]`. Then `repoPool = Math.max(takenSet.size, |openSet ∪ closedSet ∪ takenSet| + unlistedOpen)`.
    - When only count `openIssues[r]` is supplied without `openIssueNumbers`: let `mergedSet` be distinct `takenSet` issues with `merged === true`, and `repoPool = Math.max(takenSet.size, openCount + |closedSet ∪ mergedSet|)`.
    - Unified `pool` is the sum of included `repoPool` values when all are non-null (or `0` for `0` repositories when `openNow !== null`), else `null` (`poolDisplay: "?"`).
    - Invariant: whenever `pool !== null`, `pool >= taken >= prCreated >= merged >= regressions >= 0`.
- **Auto-detected `Regressions` aggregation.** Optional `regressions` array of `{ repo: string, pr?: integer | null, issue?: integer | null, issues?: integer[], reopened?: boolean, reverted?: boolean, regressionIssues?: integer[], reopenedAt?: string | null, revertedAt?: string | null, regressionIssueAt?: string | null, detectedAt?: string | null, signals?: Array<{ kind: string, level?: string, at?: string | null, url?: string | null }> }` attaches to **merged** items matching `(repoLower, pr)` (when `pr > 0`) or `(repoLower, issue)`, merged with inline run flags (`run.reopened`, `run.reverted`, `run.regressionIssues`), preserving earliest `reopenedAt`, `revertedAt`, `regressionIssueAt`, `detectedAt`, and deduplicated `signals` per item.
  - A merged item has `hasReopened` (`reopened === true`), `hasReverted` (`reverted === true`), and `regressionIssueNumbers` (sorted unique positive integers from follow-up regression issues); `hasRegression` is `hasReopened || hasReverted || regressionIssueNumbers.length > 0`.
  - Overview `regressions` counts distinct merged items in the window with `hasRegression === true` (multiple signals on the same merged PR/issue count once so `0 <= regressions <= merged`).
  - `regressionsPct` is `merged === 0 ? null : Math.round((regressions / merged) * 1000) / 10`. Optional boolean `regressionsComplete` defaults to `true`: when `merged === 0`, `regressionsDisplay` is `"0 (n/a)"`; when `regressionsComplete !== false`, `regressionsDisplay` is `"${regressions} (${regressionsPct.toFixed(1)}%)"`; when `regressionsComplete === false` and `merged > 0`, `regressionsDisplay` is `"?"` when `regressions === 0` or `"${regressions}+ (${regressionsPct.toFixed(1)}%+)"` when `regressions > 0`.

## Views and public operations

### View 1: Overview (`overview`)
- Unified (`byRepo` false): `windows` has one row per active window (`Last 24h`, `Standup (9am-9am PT)`, `Week (Mon-Sun)`, or `YYYY-MM-DD`) with `{ key, label, startAt, endAt, pool, poolDisplay, open, openDisplay, taken, prCreated, merged, convPct, mergedDisplay, mwm, mwmDisplay, regressions, regressionsPct, regressionsDisplay, funnel }`, where `funnel` reports stage-by-stage percentages `{ pool, poolDisplay, taken, takenPct, pr, prPct, merged, mergedOfPrPct, mergedOfTakenPct, regressions, regressionsPct, line }` (`Pool -> Taken (%) -> PRs (%) -> Merged (%/PRs, %/Taken) | Regressions (%)`), plus sibling `overview.target` (`{ label, month, convMinPct, maxRegressionPct, convDisplay, regressionDisplay }`).
- Per-repository (`byRepo` true): `perRepoWindows` array (matching the active windows: `[week, last24h]` when `date` is unset, `[date]` when `date` is set), each containing `rows` (one row per included repository in sorted `repoLower` order) and `total` (`label: "Total"`), using the same row shape.

### View 2: Funnel & Gates (`stages`)
- Evaluates the primary window across the selected repositories (`repoFilter` or unified).
- Gate states per issue normalize as:
  - `runtime`, `vectors`: `"pass"` -> `"pass"`; `"fail"` -> `"fail"`; else `"na"`.
  - `formal`: `"proved"`, `"bounded"`, `"pass"` -> `"pass"`; `"failed"`, `"fail"` -> `"fail"`; else `"na"`.
  - `suite`: `"pass"` -> `"pass"`; `"fail"`, `"broken"`, `"hung"` -> `"fail"`; `"running"` -> `"running"`; else `"na"`.
  - `review`: `"pass"` -> `"pass"`; `"fail"` -> `"fail"`; `"running"` -> `"running"`; else `"na"` (case-insensitive).
  - `ci`: `"green"`, `"pass"` -> `"pass"`; `"red"`, `"fail"` -> `"fail"`; `"pending"`, `"running"` -> `"running"`; else `"na"`.
  - `e2e` (optional): `"green"`, `"pass"` -> `"pass"`; `"red"`, `"fail"`, `"broken"`, `"hung"` -> `"fail"`; `"pending"`, `"running"` -> `"running"`; else `"na"`.
  - For merged or `would-merge` runs where `suite` or `review` is `"na"`, treat `suite` and `review` as `"pass"`.
- **Left-to-right funnel split (`beforePr` and `unmergedPrs`):**
  - `beforePr`: partitions every taken issue with `!prCreated` into exactly one primary reason in order `["running", "needs-person", "stopped"]` (`status === "running"` -> `"running"`, `status === "needs-person"` -> `"needs-person"`, else `"stopped"`). Returns `{ total, breakdown: Array<{ reason, count }>, summary }`, where `summary` is `"Before PR (0): none"` or `"Before PR (${total}): ${counts joined by ' · '}"`. Invariant: `beforePr.total + pr === taken`.
  - `unmergedPrs`: partitions every taken issue with `prCreated && !merged` into exactly one primary reason in order `["failed runtime", "failed vectors", "failed formal", "failed suite", "failed review", "failed ci", "failed e2e", "needs-person", "open/draft", "closed unmerged"]` (first gate in `["runtime", "vectors", "formal", "suite", "review", "ci", "e2e"]` with state `"fail"`, else `"needs-person"` when `status === "needs-person"`, else `"closed unmerged"` when reconciled `prState === "CLOSED"`, else `"open/draft"`). Returns `{ total, breakdown: Array<{ reason, count }>, summary }`, where `summary` is `"Unmerged PRs (0): none"` or `"Unmerged PRs (${total}): ${counts joined by ' · '}"`. Invariant: `merged + unmergedPrs.total === pr` and `beforePr.total + unmergedPrs.total + merged === taken`.
- **Reconciled universal `prGates` (of total PRs):**
  - For `suite`, `review`, `ci`, and optional `e2e`, denominator is always `pr` (all PRs created in the primary window) and `passed` counts PR-created issues with state `"pass"` (`display: pr === 0 ? "-" : "${passed}/${pr}"`). `e2e.present` is `true` iff at least one PR in the window has `e2e` state other than `"na"`.
  - `prGates` is `{ totalPrs: pr, suite, review, ci, e2e: { passed, total, present, display }, summary }`, where `summary` is `"PR Gates (of 0 PRs): none"` when `pr === 0`, else `"PR Gates (of ${pr} ${pr === 1 ? "PR" : "PRs"}): Suite ${suite.display} · Review ${review.display} · CI ${ci.display}"` plus `" · E2E ${e2e.display}"` when `e2e.present` is `true`.
- **Prompt-only `promptChecks` (of prompt PRs, strictly at PR granularity):**
  - `promptPrs` counts PR-created issues in the primary window where `promptChanged === true` or any of `runtime`, `vectors`, `formal` has executed state `"pass"` or `"fail"`.
  - For each check `g` in `PROMPT_CHECKS = ["runtime", "vectors", "formal"]`: grade strictly at PR granularity using normalized `item.gates[g]` (`"pass"` increments `passed` and `total` by `1`; `"fail"` increments `total` by `1`; `"na"` / `"not-run"` is excluded; raw vector or story test-case counts in `gateCounts` are never summed across PRs). `display` is `total === 0 ? "-" : "${passed}/${total}"`.
  - `promptChecks` is `{ promptPrs, runtime, vectors, formal, summary }`, where `summary` is `"Prompt Checks (of 0 prompt PRs): none"` when `promptPrs === 0`, else `"Prompt Checks (of ${promptPrs} ${promptPrs === 1 ? "prompt PR" : "prompt PRs"}): Runtime ${runtime.display} · Vectors ${vectors.display} · Formal ${formal.display}"`.
- **Regressions breakdown (`regressions`):**
  - `{ total, reopened, reverted, regressionIssueCount, regressionIssues, complete, events, summary }`, where `total` counts distinct merged items in the primary window with `hasRegression === true`, `reopened` counts merged items with `hasReopened === true`, `reverted` counts merged items with `hasReverted === true`, `regressionIssues` is the sorted unique array of follow-up regression issue numbers across those merged items, `regressionIssueCount` is `regressionIssues.length`, `complete` equals `regressionsComplete !== false`, and `events` lists per-item timestamped regression details (`{ repo, pr, issue, reopened, reverted, regressionIssues, reopenedAt, revertedAt, regressionIssueAt, detectedAt, signals }`).
  - `summary` is `"Regressions (${total}): ${reopened} reopened · ${reverted} reverted · ${regressionIssueCount} ${regressionIssueCount === 1 ? "regression issue" : "regression issues"}${regressionIssues.length > 0 ? " (" + regressionIssues.map(n => "#" + n).join(", ") + ")" : ""}${complete ? "" : " (scan incomplete)"}"`.
- **Stage-by-stage `funnel` on `stages`:** `stages.funnel` carries `{ pool, poolDisplay, taken, takenPct, pr, prPct, merged, mergedOfPrPct, mergedOfTakenPct, regressions, regressionsPct, line }` for the primary window (`Pool -> Taken (%) -> PRs (%) -> Merged (%/PRs, %/Taken) | Regressions (%)`).
- **Backward-compatible `stages` fields:** Keep `gates` (`{ runtime, vectors, formal, suite, review, ci }` with `{ passed, applicable, display }`), `mwm`, `reopen` (count of `mwm` items with `hasRegression`), `nonMerged`, and `nonMergedSummary` (classifying taken items where `!mwmFlag` by `"running"`, `"needs-person"`, first failed gate in `GATES`, else `"ended"`, formatted `"Non-merged (0): none"` or `"Non-merged (${count}): ..."`).

### View 3: Skills (`skills`)
- `normalizeSkill(value, hints)` maps `"small-change"` / `"pdd-small-change"`, `"bug"` / `"pdd-bug"`, and `"feature"` / `"pdd-feature"` (case-insensitive) to `"small-change"`, `"bug"`, or `"feature"`. When `value` is absent, use `hints`: `pathsOnlyD === true` -> `"small-change"`; `/\b(?:fix|bug|regression|broken|crash|error|fail(?:ed|ing|s)?)\b/i` in `title` or `promptChanged === false` -> `"bug"`; else `"feature"`.
- Rows in fixed order `["small-change", "bug", "feature"]` plus `total` (`skill: "Total"`):
  - `{ skill, taken, prCreated, merged, convPct, mergedDisplay, mwm, mwmDisplay, medianMinutes, medianDisplay }`.
  - `medianMinutes`: median of finite positive `durationMinutes` (`> 0`) among merged (or un-reconciled `would-merge`) issues in that row, rounded to nearest integer (`Math.max(1, Math.round(median))`), or `null` when none have positive duration (`medianDisplay`: `"${medianMinutes}m"` or `"n/a"`).

### Return shape and formatting
- **Recurring cross-job flakes (`recurringFlakes`, #3562):** Accept optional `flakeEntries` (array of `{ ts, repo?, issue?, pr?, head?, target, outcome, detail? }` records) or pre-summarized `recurringFlakes`, plus optional `flakeWindowDays` (finite positive number, default `7`) and `flakeThreshold` (default `3`). Guard numeric timestamps within valid ECMAScript Date bounds (`|ms| <= 8.64e15`), reject non-finite `windowDays` and negative outcome counts safely without throwing, exclude entries from turned-off repositories (`excludedRepos`) or non-matching `repoFilter`, count in-window occurrences up to the report reference timestamp (`date` window end when `date` is set, else `now`), keep targets with `count >= threshold` sorted by `count` descending then `target` ascending, and attach `recurringFlakes: { totalEntries, windowDays, threshold, recurring }` to the returned report.
- `calculateAutopilotMetrics` validates `view` (`"overview"`, `"stages"`, `"skills"`, or `"full"`, default `"overview"`, else throws `"invalid-view"`) and returns `{ schema: "pdd.autopilot.metrics.v1", generatedAt: now, displayDate, timezone, date: date ?? null, view, byRepo: Boolean(byRepo), repoFilter: resolvedRepoFilter ?? null, scopeLabel, openNow, openNowDisplay, regressionsComplete, recording: { enabled, globalEnabled, repoOverrides, targets }, repos, overview: { windows, target, perRepoWindows }, stages: { window, taken, pr, merged, mwm, beforePr, unmergedPrs, prGates, promptChecks, regressions, gates, reopen, nonMerged, nonMergedSummary }, skills: { window, rows, total }, recurringFlakes }`, where `displayDate` formats `now` in `timezone` with `Intl.DateTimeFormat("en-US", { timeZone: timezone, weekday: "short", month: "short", day: "numeric" })` (e.g., `"Thu, Nov 19"`).
- `formatMetricsText(report, { view })` renders aligned plain-text tables (column 0 left-aligned, remaining columns right-aligned, separated by 3 spaces, trailing spaces trimmed) matching `report.view` (or explicit `view`):
  - Header line: `"PDD Autopilot Metrics · ${report.scopeLabel} · ${report.date ?? report.displayDate} · Open now: ${report.openNowDisplay}"`; adds `'Recording: OFF (existing history shown; run "pdd metrics on" to resume)'` on the next line when `!report.recording.enabled`.
  - Overview table (unified): columns `Window`, `Pool`, `Taken`, `PRs`, `Merged (Conv%)`, `Regressions`, printing each row in `overview.windows` followed immediately by the target row `[target.label, "-", "-", "-", target.convDisplay, target.regressionDisplay]`. When `byRepo` is true, print one table per window in `overview.perRepoWindows` with columns `Repo`, `Pool`, `Taken`, `PRs`, `Merged (Conv%)`, `Regressions` and its `Total` row.
  - Funnel & Gates block:
    - `"Funnel & Gates · ${stages.window.label} · ${stages.taken} Taken -> ${stages.pr} PRs -> ${stages.merged} Merged"`
    - `"- Funnel: ${stages.funnel.line}"`
    - `"- ${stages.beforePr.summary}"`
    - `"- ${stages.unmergedPrs.summary}"`
    - `"- ${stages.prGates.summary}"`
    - `"- ${stages.promptChecks.summary}"`
    - `"- ${stages.regressions.summary}"`
  - Skills block: `"Work Mix · ${skills.window.label}"` followed by columns `Skill`, `Taken`, `PRs`, `Merged (Conv%)`, `Median Time` for `small-change`, `bug`, `feature`, and `Total`.
  - Recurring flakes block (appended only when `report.recurringFlakes?.recurring?.length > 0` in `"overview"`, `"stages"`, or `"full"` views; omitted completely when empty): `"Recurring flakes (${windowDays}d, >=${threshold})"` followed by one bullet per recurring target naming repo (when multi-repo), target, total count, and outcome breakdown.
  - View layout: `"overview"` prints Overview + blank line + Funnel & Gates (plus Recurring flakes when non-empty); `"stages"` prints Funnel & Gates (plus Recurring flakes when non-empty); `"skills"` prints Skills; `"full"` prints Overview + blank line + Funnel & Gates + blank line + Skills (plus Recurring flakes when non-empty).
- `renderMetricsHtml(report)` returns a self-contained HTML5 document (`<!doctype html>`) escaping all dynamic strings (`&`, `<`, `>`, `"`, `'`) and rendering Header (`scopeLabel`, date, `Open now: ${openNowDisplay}`), Overview (with `Pool`, `PRs`, `Merged (Conv%)`, `Regressions`, `Target` row, and Per-Repo tables), Funnel & Gates (Before PR, Unmerged PRs, PR Gates, Prompt Checks, Regressions breakdown), Work Mix by Skill, and (only when `report.recurringFlakes?.recurring?.length > 0`) a Recurring Flakes card.

## Dependencies

None. This module is pure calculation and formatting.

## Runtime input shapes

For strict-schema runtime checks of `calculateAutopilotMetrics`, pass map-valued inputs as typed entry lists: `openIssues` as `Array<{ repo: string, count: integer | null }> | null`, `recording.repos` as `Array<{ repo: string, enabled: boolean }>`, and `recording.repoPausedSince` as `Array<{ repo: string, pausedSince: string }>`. Native JavaScript callers may pass either those entry lists or plain `{ [repo]: value }` objects.
