# Compiled Story checks

`src/compiled-test.mjs` exports async `runCompiledTest({root, words, json}, {stdout, stderr, spawn})`. `root` is the invocation working directory, `words` selects Stories, and `json` selects JSON output. `stdout` and `stderr` are writable streams; `spawn` is an injected synchronous process runner, defaulting to Node's `spawnSync`. The function returns exit code 0 only when the commit is known and every selected Story passes, 1 for failure or not run, and 2 when selection is empty or contains unknown or untested Stories. File access, Git and process execution are outside-world operations; no AI or interpreter call is made.

## Domain decisions

The native route uses the selected scenario's original inputs, saved replies and checks. It must never invent expected values, skip a check to obtain a pass, or substitute a live service for a missing fixture. A project supplies its own trusted native adapter; running that code is not an operating-system sandbox or proof of prompt/code equivalence.

## Admission and selection

Discover scenarios using the project workspace and Git-visible source rules. Apply ordinary local preflight admission, including Story identity, partial scenarios, prompt status and prose hash, schema validity, actual criterion texts and coverage, and input schemas. A malformed, incomplete, stale or inaccessible scenario is not run. A missing implementation warning alone does not refuse interpreter admission. A native-only interface is not run and reports its declared reason.

Validated native `call` metadata is local to this route. When the installed admission accepts only CLI metadata, admit a source projection with only the validated `call` implementation member removed. All other original source bytes, numeric tokens, prompt prose/status/hash, dependencies and workspace restrictions retain their meaning. Apply the unmodified ordinary preflight to that projection; never discard its first refusal or claim that later checks ran. Inspect original required sources through the strict source boundary before projection. Unsafe sources, an unrepresentable workspace policy or a projection failure are not run. Temporary admission material is private, removed on completion or failure, and cannot change the project. Do not alter the installed Runtime package or the ordinary interpreter route.

Resolve path selections from the invocation directory before applying preflight selection at the Git root; bare Story names remain names. Directory selections include untested Stories beneath that directory as not run, including when no tested Story matches. Bound directory matches to descendants, combine multiple selections without duplicates, and do not treat paths outside the project as all Stories. Explicitly named untested Stories remain selection errors. Do not follow source symlinks or output symlinks outside the workspace.

## Existing CLI route

Preserve `implementation: {"kind":"cli","command":"node bin/tip.mjs"}` and the `cli` convention on both input and result schemas. Only resource-free, call-free entries with an empty initial world, simulation and step simulation overrides can run on this route. Expected errors and referenced or unsupported inputs are not run. The command is whitespace-separated argv with no shell; reject command strings containing quotes, escapes, shell metacharacters, newlines or glob characters. Append the step's string argv and pass optional string stdin (default empty). Capture exit code and exact UTF-8 stdout and stderr with a ten-minute timeout and 10 MiB output cap. A launch failure or timeout is not run. Only `equals` checks of `result` pointers `/exit_code`, `/stdout`, and `/stderr` are supported. Compare every check exactly; any unsupported check makes the step not run before launching the application. Preserve existing CLI refusal precedence.

## Typed call adapter

The [native adapter contract](../../docs/code-call-adapters.md) owns implementation metadata, versioned request/response fields, fixture obligations and exact JSON transport. Admit literal inputs against the selected entry's input schema. This route supports entries without prompt-to-prompt calls, with no resources or resources of kind `port` supplied by the contract's bounded `fixture.lookup` shape. Empty simulation is permitted for a pure entry. Missing resource fixtures, unsupported actions, nonempty step overrides and input references are not run before application launch. An absent or empty legacy object for step overrides is permitted. Do not silently remove unsupported scenario data.

For each supported step, execute its declared command exactly once, without a shell, from the Git root. Send the operation, symbol, original input, current world and unchanged simulation; never send the Story, checks or expected values. Use the existing ten-minute timeout and 10 MiB output cap. Launch failure, nonzero process exit, signal, timeout, invalid JSON, extra output or an invalid response is not run with a reason. Validate a normal result against the admitted result schema and an error against the entry's declared codes. An error response is an application outcome, not a process failure.

Support `equals` and `count` checks on `result`, `world`, `calls` and `error`, with literal values and RFC 6901 pointers, including the empty root pointer. `equals` compares complete JSON values exactly; object key order is irrelevant and array order matters. `count` compares a nonnegative integer with the number of array items, object keys or Unicode code points in a string. Missing paths differ from present null and fail both checks. Use own properties only; do not traverse prototypes. Other operators, HTML selectors, `json_path`, reference comparisons and extra check modifiers are unsupported and make the entire step not run before launch. Preserve each original check and its criterion association.

An expected-error step passes only when the adapter returns that exact declared code and every original check passes. An unexpected error or a normal result where an error was expected fails the step, even if other checks pass. Evaluate world and calls checks on both normal and error responses. A valid response commits its returned world for the next step even when a check fails. Each scenario starts from its own initial world. An invalid or unexecuted typed step leaves subsequent typed steps in that scenario not run because their required starting world is unknown; independent scenarios still run. Cross-step result references, internal prompt calls, HTTP, dual-target execution and native mutation-control flags are outside this route.

## Reports

The JSON report and `.pdd/code-test/latest.json` have `target: "code"`, `commit` (the Git HEAD SHA, or null if unavailable), `ai_calls: 0`, `dirty` (true for uncommitted tracked or untracked worktree changes, false for a clean worktree, or null when Git cannot determine it), and `stories` in selection order. Each Story has `story`, `status` (`passed`, `failed`, or `not run`), and `steps`. A step has `step_id`, `status`, and either `reason` for not run or `checks`. Each check has `criterion_id`, `path`, `status` (`passed` or `failed`), `expected`, and `actual`. A Story fails if any step fails, otherwise is not run if any step is not run, otherwise passes. Text output prints each Story's status, path, commit and dirty state, with reasons for steps not run and failing checks (scenario path, `step_id`, `criterion_id`, `path`, `expected` and `actual`). JSON output prints the complete report on stdout. Record the report locally for both output modes; missing commit cannot pass the command. Check `.pdd`, `.pdd/.gitignore`, `.pdd/code-test` and `.pdd/code-test/latest.json` against symbolic links before writing, and seed `.pdd/.gitignore` with `*\n` when absent so `.pdd/` stays ignored in repositories without setup. Do not represent a not-run step as passed.

Typed check records also carry their original `target` and `op`. A missing actual value is reported as `{"missing":true}`, distinct from null. A typed step may additionally carry `reason` for an unexpected application outcome. Preserve exact integers in stdout, stderr diagnostics and the saved report. Existing CLI report fields remain compatible.
