# Compiled Story checks

`src/compiled-test.mjs` exports async `runCompiledTest({root, words, json}, {stdout, stderr, spawn})`. `root` is the invocation working directory, `words` selects Stories, and `json` selects JSON output. `stdout` and `stderr` are writable streams; `spawn` is an injected synchronous process runner, defaulting to Node's `spawnSync`. The function returns exit code 0 only when the commit is known and every selected Story passes, 1 for failure or not run, and 2 when selection is empty or contains unknown or untested Stories. File access, Git and process execution are outside-world operations; no AI or interpreter call is made.

Discover scenarios using the project workspace and Git-visible source rules. Apply the ordinary local preflight admission to each scenario, including Story identity, partial scenarios, prompt status and prose hash, schema validity, actual criterion texts and coverage, and input schemas; a malformed, incomplete, stale or inaccessible scenario is not run. When a Story splits its acceptance criteria across multiple sibling scenario files (`S.json`, `S.<variant>.json`), reconcile criterion coverage across selected sibling scenarios for the same Story (when selecting the Story, directory, or all Stories) and, when a user explicitly targets a single `.json` scenario file (`pdd test --target code tests/split.a.json`), classify coverage via [Test ergonomics](test-ergonomics.prompt.md) `classifyTargetedScenarioCriteria`: execute only the targeted scenario file when it checks at least one Story criterion and every remaining criterion of its Story is covered by valid sibling scenario files, while staying fail-closed (`not run`) whenever any Story criterion is uncovered across all sibling scenarios or the targeted scenario checks zero criteria. Admit missing interfaces, as the other callers do since plain-Markdown prompts became the default (#3367): a prompt without a Runtime interface is not a refusal by itself (#3641). A missing implementation warning alone does not refuse interpreter admission. A native-only interface is not run and reports its declared reason. Resolve path selections from the invocation directory before applying preflight selection at the Git root; bare Story names remain names. Directory selections include untested Stories beneath that directory as not run, including when no tested Story matches. Bound directory matches to descendants, combine multiple selections without duplicates, and do not treat paths outside the project as all Stories. Explicitly named untested Stories remain selection errors. Do not follow source symlinks or output symlinks outside the workspace. An entry prompt with an embedded Runtime interface names `implementation: {"kind":"cli","command":"node bin/tip.mjs"}` on each tested entry, and both input and result schemas carry the `cli` convention; that interface alone decides its command. An entry prompt with no Runtime interface (plain Markdown) has no schemas, so the step itself shows that it is a CLI call: validate the input and check rules below before looking up a command (so non-CLI plain steps report the input or check refusal rather than a missing `pdd.json` command). Its command comes from the root `pdd.json` as `{"code": {"commands": {"prompts/tip.prompt.md": "node bin/tip.mjs"}}}`, keyed by the step's `entry_path` and read once per run through the same Git-visible source access. A missing, unreadable or invalid `pdd.json`, a missing key or an unsupported command makes the step not run with `CLI implementation command is missing or unsupported. ENTRY has no Runtime interface, so add "code": {"commands": {"ENTRY": "COMMAND"}} to pdd.json (whitespace-separated argv, no shell).` Only resource-free, call-free entries and scenarios with an empty initial world, simulation, and step simulation overrides can run; other steps are not run because their outside world cannot be faithfully supplied. Referenced or unsupported inputs are not run. The command is whitespace-separated argv with no shell; reject command strings containing quotes, escapes, shell metacharacters, newlines or glob characters. Append the step's string argv, pass optional string stdin (default empty), and capture exit code and exact UTF-8 stdout and stderr with a ten-minute timeout and 10 MiB output cap. A launch failure or timeout is not run. Only `equals` checks of `result` pointers `/exit_code`, `/stdout`, and `/stderr` are supported; any other check makes the step not run. Compare every supported check exactly.

The JSON report and `.pdd/code-test/latest.json` have `target: "code"`, `commit` (the Git HEAD SHA, or null if unavailable), `ai_calls: 0`, `dirty` (true for uncommitted tracked or untracked worktree changes, false for a clean worktree, or null when Git cannot determine it), and `stories` in selection order. Each Story has `story`, `status` (`passed`, `failed`, or `not run`), and `steps`. A step has `step_id`, `status`, and either `reason` for not run or `checks`. Each check has `criterion_id`, `path`, `status` (`passed` or `failed`), `expected`, and `actual`. A Story fails if any step fails, otherwise is not run if any step is not run, otherwise passes. Text output prints each Story's status, path, commit and dirty state, with reasons for steps not run and failing checks (scenario path, `step_id`, `criterion_id`, `path`, `expected` and `actual`). JSON output prints the complete report on stdout. Record the report locally for both output modes; missing commit cannot pass the command. Check `.pdd`, `.pdd/.gitignore`, `.pdd/code-test` and `.pdd/code-test/latest.json` against symbolic links before writing, and seed `.pdd/.gitignore` with `*\n` when absent so `.pdd/` stays ignored in repositories without setup. Do not represent a not-run step as passed.

## Reuse by blind build

`codeTestReport({root, words, implementationRoot}, {spawn})` returns `{exit, report, runs, error}` without printing or writing anything. It applies the same selection, admission and step rules as `runCompiledTest`, but runs every command with `cwd: implementationRoot` (default: the Git root) while scenarios and prompts are still read from the Git root. `error` is the selection error text for exit 2, else null. `runs` lists each runnable step as `{story, scenario, step_id, entry_path, operation, words, input, input_schema}`, where `words` is the parsed command and `input_schema` is the entry's input schema, or for a plain-Markdown prompt the CLI input shape `{argv: string[], stdin?: string}` with no other fields. `runCompiledTest` uses it and then records and prints as above, so its output is unchanged.

`runCliStep({words, input, cwd}, {spawn})` runs one CLI command with the step rules above (no shell, string argv appended, optional stdin, ten-minute timeout, 10 MiB cap) and returns `{exit_code, stdout, stderr}` or `{not_run: REASON}`. Both `codeTestReport` and [Blind build](blind-build.prompt.md) use it. `codeTestReport` also takes `dry: true`, which selects and admits steps and lists `runs` without running any command (each runnable step is `not run` with `Selection only.`), and returns the `found` discovery and `selected` tests. `writeLocalReport(root, parts, text, stderr)` writes `.pdd/PARTS…` with the symlink checks and `.gitignore` seeding above and returns false after printing `Code test result path is a symbolic link.` when a path is a symlink.

## Dependencies

[Runtime seam](runtime-seam.prompt.md#public-contract) supplies Story selection, source boundaries, scenario shape, entry parsing, schema checks, exact integer scenario parsing and serialization, and workspace access rules from `@promptdriven/runtime-client`, [Short scenario compiler](scenario-compile.prompt.md) compiles Short JSON and omitted-`criteria` scenarios to `program-scenario.v1` before execution, and [Test ergonomics](test-ergonomics.prompt.md) supplies `classifyTargetedScenarioCriteria` for single-scenario sibling-criteria validation. These are required context for this checker.
