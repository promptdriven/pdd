# Local PDD Alpha command boundary

PDD Alpha supplies a guide and recipes for the user's existing coding-agent conversation. Keep `pdd` as the command name. Provide local discovery and an optional client dispatch seam without hosted-service implementations or private dependencies.

The local command surface includes help (root and known local command help), `--version`, `--skill`, `workflow list [--json]`, `completion bash|zsh`, `session [--agent codex|claude] [request text]`, and `workflow feature|bug|small-change [--agent codex|claude] [request text]`. Unknown or excluded commands, including with help flags, refuse clearly with exit2 before effects. Only the catalogued optional client commands may dispatch validated argv to an explicitly supplied adapter, as defined by [CLI adapter registration](pdd-cli.prompt.md#optional-client-registration). Do not search for installed service adapters, forward unknown commands, import private dependencies, implement authentication, make PDD service calls, change accounts or install services in this package. Public local workflow run/resume may use ordinary authenticated Git/GitHub tools through the distinct runner. Expose only supported local command declarations and validators.

Keep one catalog authoritative for help/parser/completion. Parse before local reads. Success returns0; unsupported syntax2; missing guidance/local filesystem failure1. Do not echo untrusted input. Local discovery reads do not create project files. Explicit session launches only the installed native Codex or Claude; native keeps the user’s existing environment/login and follows their conversation instructions. Full-access launch modes are owned by [native session](native-session.prompt.md) and [workflow stage transport](workflow-stage-herdr.prompt.md); no global permission or configuration rewrite is performed. No hosted workflow service or fallback. Package metadata/lock must be dependency-free, retain bin `pdd`, include complete docs/skills/recipes/example and avoid lifecycle scripts. Source use and private temporary package-consumer tests are supported; registry publication/global installation are outside scope.

## Dependencies

Read the entire [Prompting guide](../../docs/prompting-guide.md) before authoring prompts or Stories. Source files implement these contracts; tests exercise observable behavior from the actual packed package.

Named workflow shortcuts select exactly one bundled manual recipe and use the same ordinary native launcher. This is one conversation, not a managed or stage-separated runner, and no PR effect is automatic. Existing session still loads all bundled recipes.

Workflow execution uses `pdd workflow run NAME ISSUE [--agent codex|claude]` and `pdd workflow resume RUN_ID [--decision approve|skip]`. DISTINCT local runner owns durable journals, saved agent/identity, human choices, handoff/test completion and real GitHub PR effects. CLI parses/dispatches and supplies existing guidance/native ports, never duplicates that policy. Resume without decision is inspect/reconcile/wait only. No status command, user-supplied native-argument passthrough, hosted engine or auth/provider gate. Direct shortcuts are one-conversation companions, not the runner.

The optional client surface is limited to phone, link, fleet, agents/agent/open, accounts, setup and join. Their command declarations and local help/completion are public; their implementations remain outside this package. Missing registration or method prints `This command needs the optional client.` on stderr and returns1. Unknown syntax remains exit2 before adapter access.
