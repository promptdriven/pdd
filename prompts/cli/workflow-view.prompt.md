# Inspect a run without starting work

Own `src/workflow-view.mjs`, exporting `viewRun({ref, cwd}, ports={})` with the runner result shape `{exitCode, message}`. Resolve the same issue references as [run records](workflow-runs.prompt.md). Return exit 1 with its selection diagnostic when no unique saved run exists. This view is a passive local read: no Herdr calls, chat startup/resume/focus, approval, PR refresh, Git fetch, runtime/authentication calls, journal/index writes or file creation. Only local Git reads and existing files may be consulted. It must work while Herdr or the network is unavailable.

Show the issue title and link to the full problem/discussion, saved run state, current area and gate, open person question or chat-start failure, recorded human approvals and remaining approval decisions. A completed or cancelled run has no active gate, except a completed-at-PR-1 code-or-stop question remains optional code authorization. When the current area has finished and waits on its recorded PR with no open gate, identify PR review/merge as the remaining human action; do not say the area still needs to finish. Explain that one ready-gate approval covers that gate and all its selected draft prompts. A later code-or-stop gate requires its own decision. Standalone prompt approval still covers only that prompt. Include saved PR URLs and states, Prompt tests lines/report URLs, and Try URLs, or explicitly say that none are recorded. Find the lines with the [Prompt tests pattern](runtime-output.prompt.md#prompt-tests-line), so older `Runtime check` lines show too. Saved external status is not refreshed by viewing.

Show each step's saved `pddResults`, associated with that step, including steps outside the current area. Use the [results reader's formatting](workflow-results.prompt.md) for saved results and explicitly say "none" for a step whose results list is absent or empty. Keep agent summaries separate; run-wide results or report links do not replace the saved per-step results. This display keeps the view's passive local-read behavior.

Link to the exact current review files in the run worktree: changed Stories/PLAN, prompts and views, runtime scenario JSON and app maps relative to the pinned base; include untracked authored files. A runtime scenario is a test by the [test name rule](runtime-preflight.prompt.md#test-name-rule) (`findTests` on the run worktree), never by its content; its Stories are the ones the rule matched. Read linked files up to the upload limit (`LIMITS.bytes`), not less. If test discovery fails, print `Test discovery unavailable: <reason>` and link JSON files in test folders as `Test/app map`. Add each reached scenario's story and entry prompt paths even when unchanged, and the run folder's Markdown gate notes. Use encoded local file URLs. Identify the current Git commit and whether uncommitted changes exist; explain that these links show current files and recorded gate approvals do not certify later edits. Missing or inaccessible artifacts stay visible as unavailable; unavailable Git inspection must not be presented as a clean or empty checkout. Resolve the run root once when validating files: a file must resolve to that real root plus its unchanged relative path. An ancestor alias such as macOS /var to /private/var is valid; a redirected artifact path below the root is unavailable. Apply the same rule under the saved common Git directory for run-folder notes. Print “Gate notes unavailable” if the note folder cannot be validated or read; never silently omit that failure. Malformed scenario/prompt content may be linked for review but must not crash the view.

For reached prompts with a Runtime interface, show their current admission status: approved with current prose hash, draft, stale approval/hash, or invalid interface. Surface drafts and stale/invalid interfaces as needing person review. Explain that the next ready-gate approval can cover its selected drafts together; earlier gate evidence does not approve later edits. Prompts without a Runtime interface remain review-file links without fabricated approval status.

Keep the output small and textual. Do not embed entire documents or build a server/browser UI. Links let the person read the full Story, acceptance criteria, plan, prompts and tests. Display data only; never execute a command contained in a summary or artifact.

## Dependencies

- Read the full [Prompting guide](../../docs/prompting-guide.md) before authoring. [Run records](workflow-runs.prompt.md) owns run selection; [runtime preflight](runtime-preflight.prompt.md) owns interface discovery and prose hashes.
- Runtime: Node filesystem/path/URL primitives, Git local read commands through optional `ports.execFile`, and `ports.env`/`stateDir` for existing run-index selection. No runner/chat mutation helpers.
- [Results reader](workflow-results.prompt.md): required generation/runtime/verification context for formatting saved per-step results; viewing does not acquire fresh results.

The Runtime entry below is the actual public `viewRun` module function. `runs.resolveRun` transports the existing resolver reply `{run}` or `{error}` as JSON text. `files` binds the named read-only Node filesystem operations (UTF-8 reads; null means failure), and `program.execFile` binds the existing process port. A stat transports its `isFile()`/`isDirectory()` observations and size. These supplied replies do not establish physical Git/file selection, path safety or artifact availability; native replay must verify those reads and the passive-view promise. No new snapshot/renderer operation is introduced.
