# Inspect a run without starting work

Own `src/workflow-view.mjs`, exporting `viewRun({ref, cwd}, ports={})` with the runner result shape `{exitCode, message}`. Resolve the same issue references as [run records](workflow-runs.prompt.md). Return exit 1 with its selection diagnostic when no unique saved run exists. This view is a passive local read: no Herdr calls, chat startup/resume/focus, approval, PR refresh, Git fetch, runtime/authentication calls, journal/index writes or file creation. Only local Git reads and existing files may be consulted. It must work while Herdr or the network is unavailable.

Show the issue title and link to the full problem/discussion, saved run state, current area and gate, open person question or chat-start failure, recorded human approvals and remaining approval decisions. A completed or cancelled run has no active gate, except a completed-at-PR-1 code-or-stop question remains optional code authorization. When the current area has finished and waits on its recorded PR with no open gate, identify PR review/merge as the remaining human action; do not say the area still needs to finish. Distinguish approving a workflow gate, approving a runtime prompt and authorizing code work; never imply that one grants the others. Include saved PR URLs and states, Runtime check lines/report URLs, and Try URLs, or explicitly say that none are recorded. Saved external status is not refreshed by viewing.

Link to the exact current review files in the run worktree: changed Stories/PLAN, prompts and views, runtime scenario JSON and app maps relative to the pinned base; include untracked authored files. Add each reached scenario's story and entry prompt paths even when unchanged, and the run folder's Markdown gate notes. Use encoded local file URLs. Identify the current Git commit and whether uncommitted changes exist; explain that these links show current files and recorded gate approvals do not certify later edits. Missing or inaccessible artifacts stay visible as unavailable; unavailable Git inspection must not be presented as a clean or empty checkout. Resolve the run root once when validating files: a file must resolve to that real root plus its unchanged relative path. An ancestor alias such as macOS /var to /private/var is valid; a redirected artifact path below the root is unavailable. Apply the same rule under the saved common Git directory for run-folder notes. Print “Gate notes unavailable” if the note folder cannot be validated or read; never silently omit that failure. Malformed scenario/prompt content may be linked for review but must not crash the view.

For reached prompts with a Runtime interface, show their current admission status: approved with current prose hash, draft, stale approval/hash, or invalid interface. Surface drafts and stale/invalid interfaces as needing separate person review; a gate approval alone is not prompt approval. Prompts without a Runtime interface remain review-file links without fabricated approval status.

Keep the output small and textual. Do not embed entire documents or build a server/browser UI. Links let the person read the full Story, acceptance criteria, plan, prompts and tests. Display data only; never execute a command contained in a summary or artifact.

## Dependencies

- Read the full [Prompting guide](../../docs/prompting-guide.md) before authoring. [Run records](workflow-runs.prompt.md) owns run selection; [runtime preflight](runtime-preflight.prompt.md) owns interface discovery and prose hashes.
- Runtime: Node filesystem/path/URL primitives, Git local read commands through optional `ports.execFile`, and `ports.env`/`stateDir` for existing run-index selection. No runner/chat mutation helpers.

## Structured review (`--json`)

`pdd workflow view ISSUE --json` returns one JSON object on stdout and no human-formatted headings. It is the same passive review and uses the same saved run selection and local-only reads as the text form. The object has `version` (the integer `1`), `issue` (the saved issue number, title and URL), `state`, `area`, `gate`, `message`, `links` and `approvals`. `gate` is an object containing the saved gate id, area and kind when a gate is open, and is `null` for completed, cancelled or otherwise ungated runs. `message` is the saved gate/question message, or `null` when none is saved. `links` groups only saved review links for Stories, the plan and pull requests; it never includes Try URLs. `approvals` contains only recorded human decisions, each with its decision, actor and timestamp; it does not create or infer an approval. Missing saved values remain `null`, empty arrays or an explicit unavailable entry according to their group, and malformed local artifacts do not crash the command. The JSON form performs no writes, chat calls, approvals, network calls, Git fetches or refreshes.

The JSON contract is fixed as follows. `gate` is either `null` or an object with exactly `id`, `area` and `kind`. `id` is the saved `run.gate.id` string when that field exists and `null` when the saved gate has no id; the view never derives an id from area, kind or time. `area` and `kind` are the saved strings. `message` is the saved question/gate text string or `null`; an absent or malformed question is `null`.

Each `approvals` item has exactly `decision`, `actor` and `timestamp`. `decision` is the saved decision string. `actor` is an object with exactly `via`, where `via` is the saved `via` string (`"terminal"` or `"chat"`); no person identity is inferred. `timestamp` is the saved `at` number serialized as an ISO-8601 UTC string when finite, otherwise `null`. This preserves the only actor and time fields currently recorded by workflow runs.

`links` has exactly `stories`, `plan` and `pull_requests` arrays. Each item is a saved URL string (or an object reduced to its saved `url`/`href`), and Try/report URLs are excluded. Missing groups are empty arrays. For malformed or unavailable run files, the command still exits 0 with the affected scalar set to `null` and affected arrays empty; the output includes an `unavailable` array of short field names (`"run"`, `"gate_notes"`, or an artifact path) when local inspection cannot validate them. It never fabricates a gate id, actor identity, timestamp, or link.
