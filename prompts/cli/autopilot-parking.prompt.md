# Autopilot parking

Own src/autopilot-parking.mjs. Behavioral refinement authorized by #3091: keep one existing run, claim, worktree and native session, and reuse the existing check queue, issue groups and workflow resume path.

Export idleParkingBlocker(run,now,graceMs=60000), idleSince(run), interpreterWaitFor(run), blockerFor(run), parkingSummary(runs,limit), parkingWords(summary,interpreter), and async reconcileParking(state,ports,{wakeRules=[],wake=false,policy={}}={}). Every external effect is injected: list, park, wake, release, blockerCleared, checkProgress, observeBlocker, alertUnknown, now. alertUnknown returns true only on confirmed delivery. state.parkingAlerts stores confirmed run/cause alert identities. observeBlocker reuses native account health/session observations when no saved blocker exists; a known limit parks until its actual reset timestamp, and an unknown reset remains blocked. The launcher binds them to native guarded workflow/GitHub/clock/process observers. No AI calls, polling loop, second queue, independent resume or direct process signaling.

A named blocker is {kind,until}, with kind interpreter, person, pdd, dependency, account, github, ci, review, environment or unknown; until is null or its explicit clearing value. Use saved blockedOn first, then runtimeWait (interpreter), open question or person gate (person), eligible #3064 environmentRetry (environment), or waiting PR (ci). On every tick also classify stuck/waiting/paused records saved before parking existed. Saved interpreter no-verdict, unknown saved-read and runner-stopped causes take precedence over a generic approval gate. interpreterWaitFor returns the current saved runtimeWait, or derives {at,reason,batch,cause} from that stopped record: at is updatedAt then startedAt then 0, batch is the saved batch identifier when present, cause is unknown for unknown reads/runner-stopped and service otherwise. Reuse parking.interpreterWait only while the current park is for the interpreter and its reason, batch and cause still match the current inferred evidence; keep its original at across unchanged ticks. A wait inferred from a finished check without a saved cause must be re-observed through observeBlocker on every tick, even at the same approval gate. Bind it to interpreterGate and interpreterCheck: the completed check step plus the current saved result identity (batch, completion/start timestamp and states). A changed gate, check step, batch or result replaces that inferred wait; unchanged evidence preserves its identity. A saved verdict retires the inferred interpreter blocker in favor of the current gate. A superseded wait cannot supply a later wait's batch or identity. Save each current wait with the park, including replacements, so cleanup cannot move its timestamp. Explicit independent questions retain person precedence. An automatic approve-pr gate whose check step finished without a saved verdict waits for the interpreter, not approval. Never infer an interpreter wait from an old no-verdict result while an agent or check still works.

Recognize a saved wait for #2897, or a saved question/stop about the missing supported PR 1 recovery/current-main integration route, as {kind:pdd,until:"#2897"}; do not hardcode affected run numbers. Other missing PDD fixes named by issue use #N and require installed capability issue-N. A saved dependency wait that names an issue to merge uses dependency; a saved account/GitHub limit uses its ISO reset time or null when unknown; a saved review lease uses review and a saved CI wait uses ci. Other explicit named blockers retain their clearing values. A wait explicitly for an issue to merge remains a dependency even when that issue also supplies a PDD fix. Saved idle-nudge and stopped-chat resume ceilings and bare pauses release their chats through parking after 60 seconds without progress. Keep their state, reason, recovery counters and existing alert custody; do not send another stuck alert for these records. They use unknown blockers and wake only for a durably queued explicit reply or retry bound to this park, through normal oldest-first capacity admission. idleSince is the latest finite progressAt (falling back to updatedAt, startedAt, then 0), current unanswered question/gate timestamp and recovery-ceiling timestamp. idleParkingBlocker returns null for ended or working records without a saved wait, and during grace; otherwise it returns blockerFor or unknown for stuck/waiting/paused records. A running record with a gate or unanswered question is person-waiting, even when its state has not changed. A PDD-recovery question retained through an admitted resume is already being handled: while running, with a current chat resumed at or after that question, do not infer the same PDD wait again. A newly stopped record still classifies its current cause. Other unclassified stopped runs keep their existing immediate unknown parking, keep their saved workflow state, wake only for a durably queued explicit reply or retry bound to this park, and send one stuck alert per run/cause through the injected alert port; retry an unconfirmed alert. No migration command or AI is required. Preserve manual and foreign-coordinator runs. A current chat deliberately closed for area-end, run-end, budget or cancel keeps that intent; do not reclassify, re-close, alert or revive it through parking. A running/queued check process prevents closing its parent chat. Environment waits keep existing backoff and repair counts.

On each auto tick, close blocked workers via park and retain all disk custody. A parking phase closing remains occupied until close confirms absence; a missing session or unknown chat custody also retains native admission occupancy even when the stopped workflow is not reported as working; parked consumes no working slot only while check custody is positively idle. A check admitted after parking, including queued or unavailable custody, reserves working capacity without reopening chats; retain this observation as parking.checkHeld until a fresh idle observation clears it. Such runs cannot wake or release, including at timeout or surplus limits. Never infer stopped custody from labels or age. Retry incomplete cleanup. A closing reservation does not override new progress: retain its occupied custody while a new recovery-ceiling grace runs or the worker has returned to running without a saved blocker. An accepted replacement blocker supersedes the previous clearing condition without resetting park age or saved-session custody. Retain a parked blocker when no replacement cause is saved. Once parked, do not restore chats until the current blocker clears and normal capacity permits. Wake before fresh work, by parking.at then issue number. person clears on a durably queued reply bound to the current parked wait, or recorded reply/approval (the bound old gate/question no longer present); an unbound person blocker remains parked; dependency only on merged issue evidence; pdd only on installed capability or commit evidence (never a package version comparison): #2897 requires capability prompt-reentry, capability:NAME requires that installed capability, commit:HEX requires that ancestor in the installed package; an older VERSION-only wait stays blocked until it has fix evidence; account/github only on saved reset timestamp; CI/review only on a new result/lease evidence; interpreter only on the existing runtime-ready rule; environment only on its existing due/healthy wake. Unknown evidence remains parked unless hasParkedReply confirms a durably queued explicit reply or retry for this same unknown park. Treat that request as clearing evidence and deliver it once through the existing journal after capacity admission; never send an additional continue notice or grant approval. Keep each wake reservation occupied across failures. Return the summary with ready wakePending in oldest-first order. A PDD wake sends one notice that names the installed fix and tells the saved session to continue. For #2897 it explains that the PR 1 re-entry/current-main integration route now exists. Preserve independent questions and approvals; a recovery notice is never a person answer. A successful wake consumes its rule once. Same files impose no admission hold.

Default maximum park age is 48 hours (policy.hours); default parked count limit is twice working cap (policy.maxParked). After the wake pass, release timed-out parks and oldest surplus parks via release; never delete branches, dirty files or saved sessions. The workflow owner serializes release against wake/reply and revalidates run identity, park timestamp and phase before effects. A durable releasing reservation cannot wake and remains occupied until release finishes; retry it even after a failed/unknown release. A release posts one marked comment and returns the issue to the existing intake queue. A wake at the age boundary wins over release when capacity exists. Never release closing/waking reservations. Summary is {working,parked,blockers,wakePending,limit}. working counts running work, positively observed check custody (optional run.checkHeld in a local observation) and unresolved cleanup/wake/release reservations, never an idle stuck/waiting/paused row merely because it is live; parked counts positively idle parked entries; blocker display names are interpreter, person, needs FIX, needs #N, unknown, account, github, ci, review, environment. limit is the chosen working cap. parkingWords prints those facts and interpreter test-mode streak without network calls.

## Missing supported routes

#3112 authorizes behavioral refinement for route gaps. Export routeQuestionFor(run) and collectRouteQuestions(ledger,runs). routeQuestionFor returns null or {kind,step,question,at,until}. Prefer the explicit run.routeWait. Otherwise classify only unanswered saved questions beginning “Which supported” with positive route-gap evidence: native PDD interface drafting plus an explicit missing route/command/tool -> interface-drafting; native-only verification plus approved-case replay plus a route and explicit missing route or unestablished executable Runtime operation -> native-replay; native PR 1 recovery -> prompt-reentry; other native PDD routes require an explicit statement that the installed route/command/tool is missing -> supported-route. PDD/native/verification/replay words alone never classify a product or person decision. Do not classify product questions, answered questions or ended runs. Step is the current unfinished area step (then area name); at is the question timestamp. Defaults require capability:route-KIND, except prompt-reentry uses #2897. Existing #2897 parking stays compatible. Explicit unrelated blockedOn retains precedence. Route gaps otherwise park with {kind:"pdd-route",until}; display their blocker as “missing PDD route”. No AI inference.

The central coordinator ledger is {records,groups}. Each record has id (JSON identity of runId, kind, step, question and at), kind, runId, run (issue number), issue (URL), step, question (unaltered agent text), at and until. Each group has kind, count (distinct records), recordIds (in insertion order), and optional issue {state,at,url}; issue state is creating, opened or unknown, at is the attempt time and url is null until confirmed. collectRouteQuestions preserves prior records/groups and issue attempts, drains the durable per-run routeReports history as well as current legacy questions, appends unseen identities and updates counts. Retained reports from ended owned runs remain eligible. Repeated ticks/restarts do not increase counts. Different kinds stay separate; foreign/manual runs are filtered by the caller. Records survive wake/release. An installed route clears through the existing pdd capability/commit evidence rules, never a package version or an issue closing. Preserve gates and independent questions. A matching legacy route question can retire only on that installed-route wake; never fabricate an answer.


## Legacy stopped runs (#3123)

A missing saved UUID or old layout field does not reject the whole park. The workflow/chat owners prove each close and retain only unsafe chats with reasons. A closing reservation remains occupied until all required absence checks pass. Old-coordinator runs enter this policy only after the caller proves current same-machine claim ownership and adopts them; transferred claims use the normal handover path. Busy agents remain open.

## Closing progress (#3132)

Before starting parking, require the current live agent to be idle or done;
working, blocked and unknown live statuses defer parking. The injected
checkProgress observation includes current live agent activity as well as check
custody. Such activity reserves working capacity even for a stopped workflow.
Every closing run reserves one working slot in admission and status, including
a done current turn and absent panes, until cleanup confirms the full park.
Do not drop a closing run because its saved blocker disappeared; retry guarded
cleanup on every tick. New activity keeps its reservation and defers closure.

parkingSummary additionally returns closing, an array of {number,reasons}, in
run order, for closing reservations. reasons is a nonempty reason-to-count map
from parking.closeReasons, defaulting to cleanup-pending. parkingWords names
each closing run and these reasons, including closing-retry once cleanup has
remained incomplete for 60000 ms. The runner owns durable attempt observations.
This bound triggers a visible retry reason, never permission to close unsafe work.
