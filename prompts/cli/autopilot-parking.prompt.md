# Autopilot parking

Own src/autopilot-parking.mjs. Behavioral refinement authorized by #3091: keep one existing run, claim, worktree and native session, and reuse the existing check queue, issue groups and workflow resume path.

Export blockerFor(run), parkingSummary(runs,limit), parkingWords(summary,interpreter), and async reconcileParking(state,ports,{wakeRules=[],wake=false,policy={}}={}). Every external effect is injected: list, park, wake, release, blockerCleared, checkProgress, observeBlocker, now. observeBlocker reuses native account health/session observations when no saved blocker exists; a known limit parks until its actual reset timestamp, and an unknown reset remains blocked. The launcher binds them to native guarded workflow/GitHub/clock/process observers. No AI calls, polling loop, second queue, independent resume or direct process signaling.

A named blocker is {kind,until}, with kind interpreter, person, pdd, dependency, account, github, ci, review or environment; until is null or its explicit clearing value. Use saved blockedOn first, then runtimeWait (interpreter), open question or person gate (person), eligible #3064 environmentRetry (environment), or waiting PR (ci). Unclassified work defects do not invent an external blocker. Preserve manual and foreign-coordinator runs. A running/queued check process prevents closing its parent chat. Environment waits keep existing backoff and repair counts.

On each auto tick, close blocked workers via park and retain all disk custody. A parking phase closing remains occupied until close confirms absence; parked consumes no working slot only while check custody is positively idle. A check admitted after parking, including queued or unavailable custody, reserves working capacity without reopening chats; retain this observation as parking.checkHeld until a fresh idle observation clears it. Such runs cannot wake or release, including at timeout or surplus limits. Never infer stopped custody from labels or age. Retry incomplete cleanup. An accepted replacement blocker supersedes the previous clearing condition without resetting park age or saved-session custody. Once parked, do not restore chats until the current blocker clears and normal capacity permits. Wake before fresh work, by parking.at then issue number. person clears on recorded reply/approval (the bound old gate/question no longer present); an unbound person blocker remains parked; dependency only on merged issue evidence; pdd only on installed version >= required release; account/github only on saved reset timestamp; CI/review only on a new result/lease evidence; interpreter only on the existing runtime-ready rule; environment only on its existing due/healthy wake. Unknown evidence remains parked. Keep each wake reservation occupied across failures. Return the summary with ready wakePending in oldest-first order. A successful wake consumes its rule once. Same files impose no admission hold.

Default maximum park age is 48 hours (policy.hours); default parked count limit is twice working cap (policy.maxParked). After the wake pass, release timed-out parks and oldest surplus parks via release; never delete branches, dirty files or saved sessions. The workflow owner serializes release against wake/reply and revalidates run identity, park timestamp and phase before effects. A durable releasing reservation cannot wake and remains occupied until release finishes; retry it even after a failed/unknown release. A release posts one marked comment and returns the issue to the existing intake queue. A wake at the age boundary wins over release when capacity exists. Never release closing/waking reservations. Summary is {working,parked,blockers,wakePending,limit}. working counts non-ended runs except positively parked ones, parked counts positively idle parked entries; blocker display names are interpreter, person, needs VERSION, needs #N, account, github, ci, review, environment. limit is the chosen working cap. parkingWords prints those facts and interpreter test-mode streak without network calls.
