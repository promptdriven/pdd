# Autopilot parking

Own src/autopilot-parking.mjs. Behavioral refinement authorized by #3091: keep one existing run, claim, worktree and native session, and reuse the existing check queue, issue groups and workflow resume path.

Export interpreterWaitFor(run), blockerFor(run), parkingSummary(runs,limit), parkingWords(summary,interpreter), and async reconcileParking(state,ports,{wakeRules=[],wake=false,policy={}}={}). Every external effect is injected: list, park, wake, release, blockerCleared, checkProgress, observeBlocker, alertUnknown, now. alertUnknown returns true only on confirmed delivery. state.parkingAlerts stores confirmed run/cause alert identities. observeBlocker reuses native account health/session observations when no saved blocker exists; a known limit parks until its actual reset timestamp, and an unknown reset remains blocked. The launcher binds them to native guarded workflow/GitHub/clock/process observers. No AI calls, polling loop, second queue, independent resume or direct process signaling.

A named blocker is {kind,until}, with kind interpreter, person, pdd, dependency, account, github, ci, review, environment or unknown; until is null or its explicit clearing value. Use saved blockedOn first, then runtimeWait (interpreter), open question or person gate (person), eligible #3064 environmentRetry (environment), or waiting PR (ci). On every tick also classify stuck/waiting/paused records saved before parking existed. Saved interpreter no-verdict, unknown saved-read and runner-stopped causes take precedence over a generic approval gate. interpreterWaitFor returns the current saved runtimeWait, or derives {at,reason,batch,cause} from that stopped record: at is updatedAt then startedAt then 0, batch is the saved batch identifier when present, cause is unknown for unknown reads/runner-stopped and service otherwise. Reuse parking.interpreterWait only while the current park is for the interpreter and its reason, batch and cause still match the current inferred evidence; keep its original at across unchanged ticks. A wait inferred from a finished check without a saved cause must be re-observed through observeBlocker on every tick, even at the same approval gate. Bind it to interpreterGate and interpreterCheck: the completed check step plus the current saved result identity (batch, completion/start timestamp and states). A changed gate, check step, batch or result replaces that inferred wait; unchanged evidence preserves its identity. A saved verdict retires the inferred interpreter blocker in favor of the current gate. A superseded wait cannot supply a later wait's batch or identity. Save each current wait with the park, including replacements, so cleanup cannot move its timestamp. Explicit independent questions retain person precedence. An automatic approve-pr gate whose check step finished without a saved verdict waits for the interpreter, not approval. Never infer an interpreter wait from an old no-verdict result while an agent or check still works.

Recognize a saved wait for #2897, or a saved question/stop about the missing supported PR 1 recovery/current-main integration route, as {kind:pdd,until:"#2897"}; do not hardcode affected run numbers. Other missing PDD fixes named by issue use #N and require installed capability issue-N. A saved dependency wait that names an issue to merge uses dependency; a saved account/GitHub limit uses its ISO reset time or null when unknown; a saved review lease uses review and a saved CI wait uses ci. Other explicit named blockers retain their clearing values. A wait explicitly for an issue to merge remains a dependency even when that issue also supplies a PDD fix. Saved idle-nudge and stopped-chat resume ceilings keep their existing recovery and alert custody; without a separate saved or observed named blocker or existing park, do not convert them to unknown parking or send another alert. A bare paused state without a saved cause, gate, question or current named blocker remains a deliberate pause; it does not establish an unknown failure. Other unclassified stopped runs park with kind unknown, remain stuck, cannot auto-wake, and send one stuck alert per run/cause through the injected alert port; retry an unconfirmed alert. No migration command or AI is required. Preserve manual and foreign-coordinator runs. A current chat deliberately closed for area-end, run-end, budget or cancel keeps that intent; do not reclassify, re-close, alert or revive it through parking. A running/queued check process prevents closing its parent chat. Environment waits keep existing backoff and repair counts.

On each auto tick, close blocked workers via park and retain all disk custody. A parking phase closing remains occupied until close confirms absence; a missing session or unknown chat custody also retains native admission occupancy even when the stopped workflow is not reported as working; parked consumes no working slot only while check custody is positively idle. A check admitted after parking, including queued or unavailable custody, reserves working capacity without reopening chats; retain this observation as parking.checkHeld until a fresh idle observation clears it. Such runs cannot wake or release, including at timeout or surplus limits. Never infer stopped custody from labels or age. Retry incomplete cleanup. An accepted replacement blocker supersedes the previous clearing condition without resetting park age or saved-session custody. Retain a parked blocker when no replacement cause is saved. Once parked, do not restore chats until the current blocker clears and normal capacity permits. Wake before fresh work, by parking.at then issue number. person clears on a durably queued reply bound to the current parked wait, or recorded reply/approval (the bound old gate/question no longer present); an unbound person blocker remains parked; dependency only on merged issue evidence; pdd only on installed capability or commit evidence (never a package version comparison): #2897 requires capability prompt-reentry, capability:NAME requires that installed capability, commit:HEX requires that ancestor in the installed package; an older VERSION-only wait stays blocked until it has fix evidence; account/github only on saved reset timestamp; CI/review only on a new result/lease evidence; interpreter only on the existing runtime-ready rule; environment only on its existing due/healthy wake. Unknown evidence remains parked. Keep each wake reservation occupied across failures. Return the summary with ready wakePending in oldest-first order. A PDD wake sends one notice that names the installed fix and tells the saved session to continue. For #2897 it explains that the PR 1 re-entry/current-main integration route now exists. Preserve independent questions and approvals; a recovery notice is never a person answer. A successful wake consumes its rule once. Same files impose no admission hold.

Default maximum park age is 48 hours (policy.hours); default parked count limit is twice working cap (policy.maxParked). After the wake pass, release timed-out parks and oldest surplus parks via release; never delete branches, dirty files or saved sessions. The workflow owner serializes release against wake/reply and revalidates run identity, park timestamp and phase before effects. A durable releasing reservation cannot wake and remains occupied until release finishes; retry it even after a failed/unknown release. A release posts one marked comment and returns the issue to the existing intake queue. A wake at the age boundary wins over release when capacity exists. Never release closing/waking reservations. Summary is {working,parked,blockers,wakePending,limit}. working counts running work, positively observed check custody (optional run.checkHeld in a local observation) and unresolved cleanup/wake/release reservations, never an idle stuck/waiting/paused row merely because it is live; parked counts positively idle parked entries; blocker display names are interpreter, person, needs FIX, needs #N, unknown, account, github, ci, review, environment. limit is the chosen working cap. parkingWords prints those facts and interpreter test-mode streak without network calls.
