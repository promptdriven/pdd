# PDD Codex launcher

Own `bin/pdd-codex.mjs`, `src/pdd-codex.mjs`, and `src/accounts/runtime-session.mjs`. Provide a dedicated `pdd-codex` command that launches the user's installed `codex` binary through the PDD Cloud `/v1/codex-gateway/backend-api` gateway without touching stock `codex` or `~/.codex/auth.json`.

## Core behavior

- **Executable entry (`bin/pdd-codex.mjs`):** Check `process.versions.node` major version is at least 22 before dynamically importing `../src/pdd-codex.mjs` with `.then(...)` and assigning `process.exitCode` (zero static imports before the version check, zero top-level `await`, zero hard `process.exit`), forwarding `stdin`, `stdout`, `stderr`, `cwd`, and `env`. Return exit code `127` when spawning `codex` fails with `ENOENT`.
- **Argument handling (`parsePddCodexArgs`):**
  - Parse optional leading `--account <label>` / `--account=<label>` (rejecting empty/whitespace-only or dash-prefixed labels on both forms with exit `2`) and `--pdd-help` before `--` and before the first non-option argument; consume `--` only when separating leading PDD flags from non-dash args or known Codex/wrapper options (preserving `--` when at index 0 or followed by an unknown dash token such as `pdd-codex -- -prompt` or `pdd-codex --account a -- -prompt`) and forward all remaining arguments verbatim to `codex`.
  - Inspect `codexArgs` past leading global Codex flags (`-c`/`--config`, `-m`/`--model`, `-p`/`--profile`, `-C`/`--cd`, `--no-daemon`, etc.) to resolve the real subcommand and detect `--help`/`-h`/`--version`/`-V` before `--`.
  - Local `--version`, `-V`, `--help`, `-h` (top-level or on any subcommand, including `logout --help` and `login --help`), `help`, `completion`, and bare `mcp` (or `mcp help`) pass straight to `codex` without requiring a cloud lease or mutating shared leases.
  - `pdd-codex logout` (without `--help`/`-h`, even after leading global flags) deletes `<runtime>/auth.json` and `<runtime>/lease.json` inside the shared runtime folder, stops any runtime app-server daemon, and revokes the cloud lease via `releaseCloudLease` without touching `~/.codex/auth.json`.
  - `pdd-codex login` (without `--help`/`-h`, even after leading global flags) prints instructions to enroll with `pdd accounts add --provider codex` (or use stock `codex login` for personal accounts) without touching `~/.codex/auth.json`.
  - Offline-safe local subcommands (`mcp add|remove|list|get` including flags before the subcommand, `features`, `apply`/`a`, `archive`, `unarchive`, `delete`, `migrate-rollouts`, `migrate-nfs-db`) run inside a temporary directory whose `config.toml` is symlinked to `~/.codex/config.toml` (with `syncManagedCodexHomeLinks`, `resolveEffectiveSqliteHome`, `buildCodexHomeMirrorCliArgs`, and lock-serialized post-exit `normalizeCodexConfigWriteback`) so edits write straight into `~/.codex/config.toml` and `mcp list`/`get` includes plugin-contributed servers (`cua_repl`, `codex_app`) without requiring a cloud lease or distorting feature flags.
- **Shared machine runtime folder with PID ref-counting (`acquireSharedRuntimeSession` / `releaseSharedRuntimeSession`):**
  - Use one `0700` directory per user under `join(resolvePddStateBase(env), 'codex-runtime')` (`~/.local/state/pdd/codex-runtime/pdd-codex-<uid>`, never under `/tmp` so Linux stock Codex creates helper binaries cleanly; overridable via `PDD_CODEX_RUNTIME_ROOT`), validating ancestor directories (refusing symlinks owned by other non-root users), checking `lstatSync` before and after `mkdirSync` to refuse symlinks or directories owned by another OS user, and refusing a `userCodexHome` at or inside the runtime directory (checked both lexically and via `realpathSync`).
  - Serialize acquisition, release, and lease updates with an atomic `mkdir` lock directory (`owner.json` recording PID, unique lock token, and acquisition time; fast dead-owner recovery after grace; atomic stale-lock rename-and-remove recovery after 30 seconds; jittered backoff; unlock verifies ownership token before removing `lockDir`).
  - Auto-create `~/.codex/`, empty `~/.codex/config.toml`, baseline user folders (`sessions`, `archived_sessions`, `plugins`, `skills`, `rules`, `memories`), and baseline `.tmp/{bundled-marketplaces,marketplaces,plugins}` on brand-new machines via `ensureUserCodexHomeBaseline`, mirror user entries with `syncManagedCodexHomeLinks` while preserving `config.toml`, and atomically ensure `<runtime>/config.toml` symlinks directly to `~/.codex/config.toml` without an unlink window.
  - Track live sessions in `pids/<pid>`, sweeping dead PIDs via `process.kill(pid, 0)` (treating `EPERM` as non-owned/dead). Read `accounts-state.json` active `"ready"` Codex `account_id` and forward it as `currentAccountId` on shared lease requests so `pdd accounts use` / `pdd accounts next` seat selection persists across `pdd-codex` sessions; reuse an existing valid `auto_rotate: true` `lease.json` + `auth.json` (> 5 minutes left) across concurrent sessions (or when unreferenced and matching the active seat) so 60–100 concurrent `pdd-codex` sessions share 1 runtime folder and 1 PDD Cloud lease. Register synchronous `process.on('exit')` emergency cleanup alongside `SIGINT`/`SIGTERM`/`SIGHUP` handlers so `pids/<pid>` (and `pinDir` in pinned mode) are removed even on abrupt exits.
  - Persist non-secret seat ownership metadata (`is_owner`, `owner_login`) in `lease.json` alongside `lease_id`, `account_id`, `label`, and `auto_rotate` (inheriting `is_owner` from matching `accounts-state.json` `active.codex` when omitted by the lease reply, and returning `isOwner`, `ownerLogin`, and `autoRotate` on both fresh and reused sessions).
  - Export read-only `readLiveCodexRuntimeLeases` so `pdd accounts status` can inspect live shared (`pdd-codex-<uid>`) and pinned (`pdd-codex-pin-*`) runtime leases without creating directories, acquiring locks, mutating PID files, following symlinks, reading foreign-owned directories, or opening `auth.json`; skip missing, symlinked, foreign-owned, or unreadable runtime roots, session directories, and `lease.json` entries fail-closed (returning `[]` when no safe live lease exists rather than throwing).
  - When the last live `pdd-codex` process exits, immediately unlink `<runtime>/auth.json` and `<runtime>/lease.json`, stop any runtime app-server daemon, and call `POST /v1/accounts/leases/{lease_id}/release`.
- **Pinned `--account <label>` mode (`acquirePinnedRuntimeSession`):**
  - Use an isolated `0700` temporary directory (`pdd-codex-pin-*`) under the same runtime root (`resolveRuntimeRoot`) with `auto_rotate: false`, recording the launcher `pid` plus `is_owner`/`owner_login` in `<pinDir>/lease.json` so pinned runs never disturb concurrent shared sessions and remain visible to `pdd accounts status` while alive, and delete the temp directory + revoke the pinned lease on exit.
- **Interactive startup seat notice:** Right after acquiring or reusing a PDD Cloud lease (never on pass-through, local offline subcommands, or auto fail-open stock fallback), call `resolveCodexSeatNotice({ codexArgs, isInteractiveTty: Boolean(stdin?.isTTY && stdout?.isTTY), seat })` from [Codex active seat visibility](codex-seat-visibility.prompt.md). When `shouldPrint` is `true`, write `${redactSecrets(notice)}\n` to `stderr` before spawning `codex` so interactive users see the active seat label, access type (when known), and `auto-rotate on`/`off` while non-interactive or machine-output launches (`exec`, `exec --json`, `app-server`, `--json`, or non-TTY pipes) stay completely silent on `stderr`.
- **Auto-wrapper fail-open (`PDD_CODEX_AUTO_FAIL_OPEN=1`):** Strip all `PDD_*` environment variables on every pass-through and fail-open child spawn so tokens (`PDD_TOKEN`, `PDD_ACCOUNTS_TOKEN`, `PDD_CODEX_AUTO_FAIL_OPEN`) never reach stock `codex`. When invoked with `PDD_CODEX_AUTO_FAIL_OPEN=1` and without `--account`, forward `logout` and `login` (without `status`) to stock `codex`, and fall back cleanly to stock `codex` ONLY on explicit transient/unavailable lease errors (`timeout`, `network_error`, `missing_auth_token`, `no_ready_account`, `no_account_available`, `all_cooling`, `not_enrolled`, `offline`, `service_unavailable`, `rate_limited`, `lease_unavailable`, network fetch error codes `ECONNREFUSED`/`ENOTFOUND`/`ETIMEDOUT`/`EAI_AGAIN`/`ECONNRESET`/`UND_ERR_CONNECT_TIMEOUT`, or HTTP `401`/`403`/`5xx`); never fail open on security/validation/reauth codes (`unsafe_runtime_dir`, `symlink_refused`, `invalid_settings`, `invalid_lease`, `invalid_codex_config`, `reauth_required`, `unsafe_path`, `invalid_args`, `unsupported_delivery_mode`, `lock_timeout`, `toml_parser_unregistered`) or uncoded non-network `Error`s. Prepare the `~/.codex` baseline only after lease acquisition (or reusable lease verification) succeeds so fail-open runs leave `~/.codex` untouched, and throw `code: "reauth_required"` whenever a Cloud lease reply reports `state: "reauth_required"` or a reauth-required account.
- **Gateway routing, subshell isolation, and background heartbeat:**
  - Strip all `PDD_*` variables plus `OPENAI_API_KEY`, `CODEX_API_KEY`, `CODEX_ACCESS_TOKEN`, `OPENAI_BASE_URL`, `PDD_CODEX_GATEWAY_GRANT`, and `CODEX_CONNECTORS_TOKEN` from the child environment, set `CODEX_HOME=<runtimeDir>`, resolve gateway endpoints via `resolveCodexGatewayEndpoints`, and pass the revocable `pddg_*` grant token via `CODEX_CONNECTORS_TOKEN` to the spawned `codex` process so stock Codex's built-in `codex_apps` MCP client authenticates cleanly to `<backendApiUrl>/ps/mcp` without 401 errors.
  - Pass verified `-c` flags via `buildCodexGatewayCliArgs` (`cli_auth_credentials_store="file"`, `chatgpt_base_url`, `openai_base_url`, `model_provider="openai"` when user or active-profile config sets another provider and `--oss` is absent, `sqlite_home` via `resolveEffectiveSqliteHome` without clobbering explicit user `sqlite_home` or `CODEX_SQLITE_HOME`, `features.daemon_auto_start=false`, `features.shell_snapshot=false`, forward-compatible `allow_symlinked_codex_home=true`, cross-layer `shell_environment_policy` inline-table `filters` or merged legacy `exclude` across user config, profiles, ancestor repo `.codex/config.toml` honoring `-C`/`--cd`, and CLI `-c` overrides — stripping raw CLI `shell_environment_policy.exclude` overrides via `stripCodexCliEnvExcludeArgs` after merging so user flags cannot drop `PDD_*` or `CODEX_HOME` exclusions — hiding `REQUIRED_CODEX_SUBSHELL_EXCLUDES` so `$CODEX_HOME` stays unset like stock `codex` and built-in skills work normally, `runtimeCodexHome`-mapped `marketplaces.<name>.source` and `hooks.state` trust entries via `buildCodexHomeMirrorCliArgs`, rolling-deploy `nativeBackendApi` switch based on whether the server lease returned `codex_backend_api_url`, and compatibility aliases `model_providers.pdd_pool` / `model_providers.pdd_codex_gateway`). Run lock-serialized `normalizeCodexConfigWriteback` after `codex` exits (only acquiring the shared runtime lock when a runtime prefix actually appears in `config.toml`, and resolving dotfile symlinks before atomic rename) so any newly persisted runtime paths in `hooks.state` or `marketplaces.*.source` normalize cleanly back to `~/.codex` while leaving unchanged configs untouched. Never leak gateway URLs into `~/.codex/config.toml`.
  - While `codex` runs, periodically call `heartbeatCloudLease` (`POST /v1/accounts/leases/{lease_id}/heartbeat`) on a jittered `.unref()`'d timer, reading the active `lease.json` on each tick, deduplicating concurrent session heartbeats via `last_heartbeat_at`, persisting refreshed expiries (and any updated rotated seat metadata `account_id`, `label`, `is_owner`, `owner_login` returned by the heartbeat) under the runtime lock (checking `stopped`), and invalidating revoked/expired (`401`/`403`/`404`) `lease.json` + `auth.json` + runtime app-server daemon under the runtime lock only while `!stopped` and `lease.json`'s `lease_id` still matches `leaseId` before stopping cleanly.
