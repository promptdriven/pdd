# PDD Codex launcher

Own `bin/pdd-codex.mjs` and `src/pdd-codex.mjs`. Provide a dedicated `pdd-codex` command that launches the user's installed `codex` binary through the PDD Cloud `/v1/codex-gateway/backend-api` gateway without touching stock `codex` or `~/.codex/auth.json`.

## Core behavior

- **Executable entry (`bin/pdd-codex.mjs`):** Check `process.versions.node` major version is at least 22 before importing `src/pdd-codex.mjs`. Avoid static imports before the version check. Exit with the integer returned by `runPddCodexCli`.
- **Argument handling (`parsePddCodexArgs`):**
  - Parse optional leading `--account <label>` / `--account=<label>` and `--pdd-help` before `--` and before the first non-option argument; consume `--` only when separating leading PDD flags (preserving `--` when passed at index 0 such as `pdd-codex -- -prompt`) and forward all remaining arguments verbatim to `codex`.
  - Inspect `codexArgs` past leading global Codex flags (`-c`/`--config`, `-m`/`--model`, `-p`/`--profile`, `-C`/`--cd`, `--no-daemon`, etc.) to resolve the real subcommand and detect `--help`/`-h`/`--version`/`-V` before `--`.
  - `pdd-codex logout` (even after leading global flags) deletes `<runtime>/auth.json` and `<runtime>/lease.json` inside the shared runtime folder, stops any runtime app-server daemon, and revokes the cloud lease via `releaseCloudLease` without touching `~/.codex/auth.json`.
  - `pdd-codex login` (even after leading global flags) prints instructions to enroll with `pdd accounts add --provider codex` (or use stock `codex login` for personal accounts) without touching `~/.codex/auth.json`.
  - Local `--version`, `-V`, `--help`, `-h` (top-level or on any subcommand), `help`, `completion`, and bare `mcp` (or `mcp help`) pass straight to `codex` without requiring a cloud lease.
  - Offline-safe local subcommands (`mcp add|remove|list|get`, `features`, `apply`/`a`, `archive`, `unarchive`, `delete`, `migrate-rollouts`, `migrate-nfs-db`) run inside a temporary directory whose `config.toml` is symlinked to `~/.codex/config.toml` (with `syncManagedCodexHomeLinks`, `resolveEffectiveSqliteHome`, `buildCodexHomeMirrorCliArgs`, and post-exit `normalizeCodexConfigWriteback`) so edits write straight into `~/.codex/config.toml` and `mcp list`/`get` includes plugin-contributed servers (`cua_repl`, `codex_app`) without requiring a cloud lease or distorting feature flags.
- **Shared machine runtime folder with PID ref-counting (`acquireSharedRuntimeSession` / `releaseSharedRuntimeSession`):**
  - Use one `0700` directory per user under `join(resolvePddStateBase(env), 'codex-runtime')` (`~/.local/state/pdd/codex-runtime/pdd-codex-<uid>`, never under `/tmp` so Linux stock Codex creates helper binaries cleanly; overridable via `PDD_CODEX_RUNTIME_ROOT`), refusing symlinks or directories owned by another OS user and refusing a `userCodexHome` at or inside the runtime directory (checked both lexically and via `realpathSync`).
  - Serialize acquisition, release, and lease updates with an atomic `mkdir` lock directory (`owner.json` recording PID, unique lock token, and acquisition time; fast dead-owner recovery after grace; atomic stale-lock rename-and-remove recovery after 30 seconds; jittered backoff; unlock verifies ownership token before removing `lockDir`).
  - Auto-create `~/.codex/`, empty `~/.codex/config.toml`, baseline user folders (`sessions`, `archived_sessions`, `plugins`, `skills`, `rules`, `memories`), and baseline `.tmp/{bundled-marketplaces,marketplaces,plugins}` on brand-new machines via `ensureUserCodexHomeBaseline`, mirror user entries with `syncManagedCodexHomeLinks` while preserving `config.toml`, and atomically ensure `<runtime>/config.toml` symlinks directly to `~/.codex/config.toml` without an unlink window.
  - Track live sessions in `pids/<pid>`, sweeping dead PIDs via `process.kill(pid, 0)` (treating `EPERM` as non-owned/dead). Reuse an existing valid `auto_rotate: true` `lease.json` + `auth.json` (> 5 minutes left) across concurrent sessions so 60–100 concurrent `pdd-codex` sessions share 1 runtime folder and 1 PDD Cloud lease.
  - When the last live `pdd-codex` process exits, immediately unlink `<runtime>/auth.json` and `<runtime>/lease.json`, stop any runtime app-server daemon, and call `POST /v1/accounts/leases/{lease_id}/release`.
- **Pinned `--account <label>` mode (`acquirePinnedRuntimeSession`):**
  - Use an isolated `0700` temporary directory (`pdd-codex-pin-*`) under the same runtime root (`resolveRuntimeRoot`) with `auto_rotate: false` so pinned runs never disturb concurrent shared sessions, and delete the temp directory + revoke the pinned lease on exit.
- **Gateway routing, subshell isolation, and background heartbeat:**
  - Strip `OPENAI_API_KEY`, `CODEX_API_KEY`, `CODEX_ACCESS_TOKEN`, `OPENAI_BASE_URL`, `PDD_CODEX_GATEWAY_GRANT`, and `CODEX_CONNECTORS_TOKEN` from the child environment, set `CODEX_HOME=<runtimeDir>`, and pass the revocable `pddg_*` grant token via `CODEX_CONNECTORS_TOKEN` to the spawned `codex` process so stock Codex's built-in `codex_apps` MCP client authenticates cleanly to `<backendApiUrl>/ps/mcp` without 401 errors.
  - Pass verified `-c` flags via `buildCodexGatewayCliArgs` (`cli_auth_credentials_store="file"`, `chatgpt_base_url`, `openai_base_url`, `model_provider="openai"` when user config sets another provider and `--oss` is absent, `sqlite_home` via `resolveEffectiveSqliteHome` without clobbering explicit user `sqlite_home` or `CODEX_SQLITE_HOME`, `features.daemon_auto_start=false`, `features.shell_snapshot=false`, `allow_symlinked_codex_home=true`, cross-layer `shell_environment_policy` inline-table `filters` or merged legacy `exclude` hiding `PDD_*`, provider tokens, and `CODEX_HOME` so `$CODEX_HOME` stays unset like stock `codex` and built-in skills work normally, `runtimeCodexHome`-mapped `marketplaces.<name>.source` and `hooks.state` trust entries via `buildCodexHomeMirrorCliArgs`, rolling-deploy `nativeBackendApi` switch based on whether the server lease returned `codex_backend_api_url`, and compatibility aliases `model_providers.pdd_pool` / `model_providers.pdd_codex_gateway`). Run `normalizeCodexConfigWriteback` after `codex` exits so any newly persisted runtime paths in `hooks.state` or `marketplaces.*.source` normalize cleanly back to `~/.codex` while leaving unchanged configs untouched. Never leak gateway URLs into `~/.codex/config.toml`.
  - While `codex` runs, periodically call `heartbeatCloudLease` (`POST /v1/accounts/leases/{lease_id}/heartbeat`) on a jittered `.unref()`'d timer, reading the active `lease.json` on each tick, deduplicating concurrent session heartbeats via `last_heartbeat_at`, persisting refreshed expiries under the runtime lock, and invalidating revoked/expired (`401`/`403`/`404`) `lease.json` + `auth.json` + runtime app-server daemon under the runtime lock before stopping cleanly.
