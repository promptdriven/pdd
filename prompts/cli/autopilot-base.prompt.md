# Automatic run base

Own `src/autopilot-base.mjs`. The authorized scope is issue #3071 points 1–3. Preserve manual workflow base selection, approval, trust, checks, merge authority and stacked PR behavior. This module only reads; it never merges or changes branches or documents.

`selectAutopilotBase({cwd,defaultBranch}, ports={})` returns one branch name. Read `pdd.json` from cwd through `readConfig(cwd)` (native default: JSON filesystem read; a missing file means an empty config). Use `autopilot.base` when present; otherwise use the supplied repository default. A configured base must be a nonempty string naming a branch, excluding HEAD, options and full refs. Validate `refs/heads/BRANCH` with Git through `execFile`. Invalid config or an unavailable default fails without inventing a branch. Slash-separated names are allowed.

`checkAutopilotBase({run,pr}, ports={})` returns `{exitCode,message}`. `run` is the saved workflow run; `pr` is a positive PR number string. Refuse missing run identity, saved base or a PR not published by that run. Before any automatic merge, read that PR fresh from its saved repository, and require its actual base to equal `run.baseBranch`; stacked code PRs must first be retargeted through the existing merge route. The saved base remains the audit authority even if configuration changes later. Read the current default branch and all releases fresh. Choose the non-draft release with the newest published_at, including prereleases; no releases means only the default ancestry check applies. Use GitHub compare for default...saved-base and release-tag...saved-base. Each must have behind_by zero and status identical or ahead. Missing, malformed or failed observations refuse with a finite reason. Refuse an old or divergent base with a reason naming the branch and the default or release tag it lacks. When the PR payload includes `head` (pre-merge on a code PR, `stage !== "prompt-pr"`), require a 40-hex `pull.head.sha` and check merge evidence before returning exit 0: (1) pdd's saved full-suite receipt (`readSuiteReceipt` / `judgeSuiteReceipt`, `#3087`) must match `pull.head.sha` on a clean checkout with `outcome === "completed"`, `exitCode === 0`, and passing `counts` (`pass > 0`, `fail === 0`, `cancelled === 0`); (2) for `bug` and `feature` workflows, the repository must have a committed verification recipe on the base checkout (or else hold the merge waiting for the single verification-recipe `small-change` PR with one grouped question across waiting runs); and (3) for `bug` and `feature` code PRs, `<runDir>/real-validation.json` must pass `judgeRealValidation` for `pull.head.sha` with a fresh verifier session, recipe used, old-code reproduction/baseline result, new-code pass result, and evidence paths (`small-change` stays as today). After a merge the same read checks that the merged PR went to the saved base. A successful read reports the PR, base, default and release tag (or no release). Exit 0 means these base and merge-evidence checks pass; exit 1 means refused or held.

All program calls use injected `execFile(file,args,{cwd})`; all config reads use `readConfig`. Native defaults use local filesystem and the counted native GitHub process adapter. No error includes raw external output or secrets. GitHub requests are read-only, with explicit repository paths and encoded refs. No cache is used for merge safety.

## Dependencies

- [Workflow runs](workflow-runs.prompt.md): required native generation context for the saved run repository, PR records and baseBranch supplied by the launcher.
- [GitHub calls](github-calls.prompt.md): required native generation context for the default counted process adapter.
- [Shared full-suite queue](test-suite-queue.prompt.md): required context for `readSuiteReceipt`.
- [Workflow PR evidence](workflow-pr-evidence.prompt.md): required context for `judgeRealValidation`, `judgeSuiteReceipt` and `findVerificationRecipe`.
