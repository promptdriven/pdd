# Unified stateless proof and feature map verification

Own `src/core/prove.mjs` and `src/core/verify-paths.mjs`. Provide one stateless, repository-agnostic and language-agnostic proof engine (`runProve`) backed by the universal `pdd.json` `"verify"` feature map (`loadVerifyConfig`, `parseVerifyConfig`, `matchVerifyPaths`, `detectHostCapabilities`, `matchCapabilities`).

## Domain decisions

| Condition | Outcome | Exit |
|---|---|---|
| Invalid CLI arguments (`--timeout` out of `1..120`, missing `--test`/`--expect`) | `Failed` | `2` |
| Lint error, diff error, shadow binary, or failing test/verify/formal assertion | `Failed` | `1` |
| Missing runner (`126`/`127`, `ENOENT`, `hardSetupFailure`), stuck/timed-out command, missing capability, unmapped surface, or untrusted config/script edit | `Not proved` | `3` |
| All checks, matched verify paths, formal verification, and tests green | `Proved` | `0` |

- **Three distinct outcomes:** Every invocation resolves cleanly to `Proved` (exit `0`), `Failed` (exit `1`), or `Not proved` (exit `3`); invalid CLI arguments return exit `2`. Missing recipes, absent host capabilities, missing test runners, hard environment setup failures, and stuck or timed-out commands produce `Not proved` with explicit reasons and actionable fix guidance, and never report `Proved` or `Failed`.
- **Universal Feature Map (`pdd.json` `"verify"`):** Declares optional `test` command, optional `report` path, optional `formal_command` (any language/solver formal command such as `crosshair check`, `cargo kani`, or `dafny`), optional `mutation_command`, and `paths[]` entries `{id, name?, scope?, tier?, when, run, needs?}` (max 100 entries, unique IDs; optional `tier` is `"simulated"`, `"real-host"`, or `"adversarial"`). `when` globs compile via the strictly linear DP glob matcher (`compileGlobMatcher`). `needs` accepts open capability strings (`tty`, `browser`, `docker`, `ios-simulator`, `account:<name>`, or custom strings) matched lazily against detected or injected host capabilities with zero hardcoded capability schema fields or repository names.
- **Universal environment-aware runner discovery (`detectRepoTestCommand`):** Explicit merge-base `pdd.json` `verify.test` always wins. When auto-detecting a repository test command, prefer repo-local environments before bare global commands:
  - **Node (`package.json`):** Lockfile-aware selection when `scripts.test` is defined (`pnpm-lock.yaml` -> `pnpm test`, `yarn.lock` -> `yarn test`, `bun.lock` or `bun.lockb` -> `bun run test`, else `npm test`); without a real `scripts.test`, fall back to `npx vitest run` when `vitest` is declared or `bun test` when a Bun lockfile exists.
  - **Python (`pyproject.toml`, `pytest.ini`, `setup.cfg`, `conftest.py`):** Prefer safe untracked non-symlink repo-local `.venv/bin/pytest`, then `venv/bin/pytest`, then `uv run pytest` (when `uv.lock` or `[tool.uv]` and `uv` is available), then `poetry run pytest` (when `poetry.lock` or `[tool.poetry]` and `poetry` is available), then `python3 -m pytest` (when `pytest` is absent on `PATH` and `python3` can import `pytest`), else `pytest`. Prepend `PYTHONPATH=src ` whenever a `src/` directory exists.
  - **Polyglot fallbacks:** `go test ./...` (`go.mod`), `cargo test` (`Cargo.toml`), `bundle exec rspec` (`Gemfile` with `.rspec`, `spec/`, or `rspec`), `swift test` (`Package.swift`), `./gradlew test` (`gradlew`), `mvn test` (`pom.xml`), and `ctest` (`CTestTestfile.cmake` or `CMakeLists.txt`).
- **Honest missing-runner classification and warning-safe summaries:** Any missing test runner or hard environment setup failure (`exitCode` `126`/`127`, `ENOENT`, spawn error, non-timeout signal or exit `129..192`, `hardSetupFailure`, or missing-runner stderr such as `No module named pytest` or `command not found`) on `verify.test`, auto-detected tests, or `verify.paths` recipes resolves to `Not proved` (exit `3`) with actionable fix guidance and marks the affected proof tier `Not proved` — never `Failed` (exit `1`). `summarizeTestOutput` ignores warning lines (`PytestWarning:`, `DeprecationWarning:`, `UserWarning:`, `WARN`, `WARNING:`) and prefers canonical test-runner summary lines (`=== N passed ===`, `# tests N`, `test result:`, `ok`/`FAIL`, `Tests run:`, etc.); process exit status remains the sole pass/fail truth.
- **Multi-part integration guard (`#3575`):** When `product/plan.md` defines `>=2` distinct product parts (from `product/plan.md` `## Runs`/`## Parts`/`## Prompts`/`## Boundaries` using canonical columns or `Service`/`App`/`Component`/`Module`/`Consumer`/`Provider` aliases, and optional `product/map.md` `## Parts` tables or bullet lists) and merge-base `pdd.json` `verify.paths` has no recipe covering cross-part integration (`scope: "integration"`/`"journey"`/`"cross-part"`, integration/journey/cross-part/e2e in `id`/`name`, `when` covering `product/plan.md` / `product/**`, or `when` globs spanning `>=2` distinct product parts), `runProve` emits an explicit `Not proved` reason (`pdd.json:1 [multi-part-integration-missing]`) formatted as a 4-part agent-teaching diagnostic (`invariant`, `Fix:`, `Rerun: \`pdd prove\``). If `product/plan.md` is non-empty alongside `product/map.md` or `contracts/*.md` and `>=2` distinct subdirectories under `prompts/`, `src/`, or `services/` yet fewer than 2 parts parse, fail closed with `product/plan.md:1 [multi-part-plan-unparseable]`. Unwired or unparseable product boundaries (`[product-boundary-unwired]`, `[product-boundaries-unparseable]`) also produce `Not proved`. Single-part and non-product repositories are unaffected.
- **Base-trusted config and tamper defenses:** Zero-flag `runProve` loads `verify` config (including `verify.formal_command` and optional `verify.mutation_command` parsed/fingerprinted for tamper detection) strictly from the merge base (`git show <baseSha>:pdd.json`), enforces merge-base lint rule severities/disables and base-trusted `lint.commands` / `lint.mutation_command` (ignoring untrusted working-tree `pdd.json` or `rules/lint/*.json` disables/weakenings/command edits), and checks `package.json` `scripts.test` plus any npm/pnpm/yarn/bun script or repo-relative script referenced by merge-base `verify.test`, `verify.formal_command`, `verify.mutation_command`, or `verify.paths` against `baseSha`. Uncommitted or branch-only edits to `verify`, lint overrides/commands, referenced `package.json` scripts, or referenced repo scripts produce `Not proved` — and when referenced `package.json` scripts, referenced repo scripts, or shadow binaries were tampered with, `runProve` refuses to execute repository test/verify/formal commands. Any tracked, untracked, or on-disk shadow binary under `node_modules/.bin/`, `.venv/bin/`, or `venv/bin/` fails closed (`[diff-shadow-bin]`, `Failed`) before executing repository test commands.
- **Honest proof-tier labels (`#3633`):** Every verify-mode run computes and reports 3 honest proof-tier labels (`simulated`, `real-host run`, and `adversarial run`) strictly from commands that actually executed during that run (`classifyVerifyPathTier`, `summarizeProofTiers`, `formatProofTiersLine`). `simulated` reflects `verify.test` (or auto-detected unit tests) plus any `tier: "simulated"` (`scope: "simulated"` / `"unit"`) verify paths; `real-host run` reflects executed real-host verify paths (default verify paths or explicit `tier: "real-host"`); `adversarial run` reflects executed `tier: "adversarial"` (`scope: "adversarial"` / `"break-it"`) verify paths. Any tier that did not execute, timed out, aborted as stuck, or hit a missing-runner / hard setup failure is reported honestly as `Not proved`. Both JSON (`receipt.proofTiers`) and human output (`Proof tiers: simulated=<...>, real-host run=<...>, adversarial run=<...>`) surface all 3 labels without changing overall exit codes or scanning test source with static regexes.
- **Streaming execution and progress-aware stuck watcher:** Shell commands execute via async streaming `spawn` (honoring injected `ports.spawnSync` when provided by synchronous tests) in detached process groups on POSIX so live stdout/stderr progress is observed and cleanup kills the full process group cleanly (`SIGTERM` then `SIGKILL`). Explicit `--timeout MIN` (`1..120` whole minutes) enforces a hard wall-clock limit per step and reports `Not proved` with a `--timeout MIN` hint. When `--timeout` is omitted, no rigid wall-clock cutoff applies: commands that keep emitting new output lines run without LLM calls; if output stays silent across the idle window (default 5 minutes, configurable for tests) or repeats identical normalized lines in a loop, invoke a lightweight read-only LLM stuck-check on the last ~50 redacted lines (injectable via `ports.checkStuck`, defaulting to an installed read-only agent CLI when available and disabled offline or when `PDD_PROVE_LLM_WATCH=0`). Continue when the check judges genuine slow progress; kill cleanly and report `Not proved` with the aborted phase, completed phases, and frozen log tail when stuck/looping or when an offline idle-silence cutoff expires.
- **Zero-flag verification mode (fast checks first):** Resolves the local merge base offline (failing closed as `Not proved` if base comparison is unavailable), runs fast deterministic checks first — offline `lintRepoProject` (with merge-base lint trust), `runDiffSpotlight`, base-trust/tamper/shadow-bin/cleanliness checks, matched base-trusted `verify.paths[]` recipes whose `needs` are satisfied, and shared code-bound formal verification (`runFormalVerification` from [Formal verification](formal-verify.prompt.md)) — before running the full repository test suite (`verify.test` or auto-detected runner), recording `completedPhases` in the receipt so aborted runs clearly report every completed phase alongside the frozen log tail. Formal verification reports `Formal: proved_solver_code (...)`, `Formal: bounded (...)`, `Formal: proved_spec_model (not code-bound)`, `Formal: not-applicable`, or `Formal: missing (advisory: ...)`, returning `Not proved` for disconnected `proved_spec_model` proofs or missing/timed-out runners and `Failed` on failing formal tests or refused code-bound claims. Flags `Not proved` on diff test-integrity regressions (`newSkips`, `assertionDrops`, `removedTests`, `tableDrops`), mock-only I/O/subprocess boundary tests (`[diff-mock-only-boundary]`), and touched Stories with unbound acceptance criteria (`[story-unbound-criteria]`), and emits a structured `pdd.prove.v1` provenance JSON receipt (`--json`, including `formal` and `completedPhases`) or human summary.
- **Bug-contrast mode (`--test CMD --expect TEXT`):**
  1. Overlays colocated test files (`src/**/*.test.*`, `*.spec.*`, `*_test.go`, `test_*.py`, `*_test.py`, `*_test.rs`, `test/**`, `tests/**`, `__tests__/**`, `fixtures/**`) plus any explicit `--overlay GLOB` matches, mirroring deleted test files into the base worktree so deleting a failing test never yields a fake pass.
  2. Resolves `--base REF` strictly offline from local Git refs without network fetches.
  3. Mirrors modified, deleted, and untracked files into isolated disposable base and head worktrees (`git worktree add --detach`) while validating every path segment against symlink escapes and opening destinations with `O_NOFOLLOW`, so the caller's checkout is never mutated. When `--setup` is omitted and the diff against merge base does not touch dependency manifests or lockfiles (`package.json`, lockfiles, `pyproject.toml`, `requirements*.txt`, `setup.py`, `setup.cfg`, `Pipfile*`), safely symlinks existing non-symlink repo-root dependency directories (`node_modules`, `.venv`, `venv`) into the disposable worktrees (skipping any path already present) and unlinks those symlinks explicitly before removing the worktrees on exit.
  4. Scrubs credential and session environment variable families (`GH_*`, `GITHUB_*`, `CLAUDE*`, `ANTHROPIC_*`, `OPENAI_*`, `CODEX_*`, `HERDR_*`, `PDD_*`, `AWS_*`, `*_TOKEN`, `*_SECRET`, `*_API_KEY`, `*_PASSWORD`) before running `--setup` and `--test` in the disposable base and head worktrees, always removing both worktrees on exit.
  5. Detects setup, missing-dependency, import, syntax, compile errors, and signalled processes on base or head (`ERR_MODULE_NOT_FOUND`, `Cannot find module`, `ModuleNotFoundError`, `ImportError`, `SyntaxError`, `ENOENT`, `command not found`, exit `126`/`127`, `[build failed]`, `ERROR collecting`, `error[E...]`, non-timeout signals) by scanning stderr before stdout and normalizing leading diagnostic prefixes (`# `, `E `) once; classifies them as `Not proved` (`setup-error`), never as a causal proof; clears `SyntaxError`/`ImportError`/`FileNotFoundError` ONLY when the process did not suffer an independent hard failure (never clearing exit `126`/`127`, signals, exit `129..192`, or spawn errors) AND `--expect` names that error class with detail (never the bare class name alone) AND matches on that exact normalized diagnostic error line (never a separate banner). Only a non-setup base failure whose output contains `--expect` paired with a passing head run yields `Proved`. Timeouts and stuck detections resolve cleanly to `Not proved` with frozen tail diagnostics and a `--timeout MIN` hint when applicable. Zero-flag verification inspects `git status --porcelain` before executing tests/recipes (recording `dirty`, `dirtyFiles`, and `proofScope`: `"commit"`, `"working-tree"`, or `"unknown"`), fails closed as `Not proved` if `git status` itself fails, and supports per-step environment isolation via `ports.envForStep({ phase, recipeId, command, baseEnv })`.

## Public contract

- `parseVerifyConfig(raw, {sourcePath})`: pure parser returning `{configured, source, test, report, formalCommand, mutationCommand, paths, errors}`.
- `loadVerifyConfig(rootOrObject, {gitRef})`: loads `pdd.json` safely from disk (no symlinks) or from `git show <gitRef>:pdd.json`, returning `{configured, source, test, report, formalCommand, mutationCommand, paths, errors, loadStatus}` where `loadStatus` is one of four values: `'ok'` (parsed clean config), `'absent'` (verified directory, Git commit, or object input has no `pdd.json` or no `verify` block), `'invalid'` (malformed JSON or schema errors), or `'unreadable'` (unreadable path or unavailable Git commit object).
- `matchVerifyPaths(verifyConfig, touchedFiles)`: returns `{matched, changedSurfaces, unmappedSurfaces}`.
- `detectHostCapabilities(requiredNeeds, {env, capabilities, probe, isTTY})`: lazily checks only requested capabilities and returns `{available, checked}`.
- `matchCapabilities(needs, capabilityState)`: returns `{satisfied, missing}`.
- `detectRepoTestCommand(root, {env, probe})`: discovers the repository test runner command using repo-local environments before bare global commands, returning a shell command string or `null`.
- `summarizeTestOutput(stdout, stderr, setupError, timedOut, stuckReason)`: extracts a concise runner summary string while ignoring warning lines (`PytestWarning:`, `DeprecationWarning:`, `WARN`, etc.).
- `runProve({cwd, base, test, expect, overlay, setup, timeoutMinutes, idleTimeoutMs, repeatLoopThreshold, json, capabilities, env}, ports)`: async proof engine resolving to `{exitCode, outcome, receipt}` and writing human text or JSON receipt to `stdout`/`stderr`.
