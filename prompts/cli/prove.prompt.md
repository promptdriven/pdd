# Unified stateless proof and feature map verification

Own `src/core/prove.mjs` and `src/core/verify-paths.mjs`. Provide one stateless, repository-agnostic and language-agnostic proof engine (`runProve`) backed by the universal `pdd.json` `"verify"` feature map (`loadVerifyConfig`, `parseVerifyConfig`, `matchVerifyPaths`, `detectHostCapabilities`, `matchCapabilities`).

## Domain decisions

- **Three distinct outcomes:** Every invocation resolves cleanly to `Proved` (exit `0`), `Failed` (exit `1`), or `Not proved` (exit `3`); invalid CLI arguments (including combining `--coverage` or `--mutation-check` with `--test`/`--expect` bug-contrast mode) return exit `2`. Missing recipes or absent host capabilities produce `Not proved` with explicit reasons and never report `Proved`.

| Mode / Flags | Execution scope | Receipt additions | Exit `3` (`Not proved`) triggers |
| --- | --- | --- | --- |
| Default `pdd prove [--base REF]` | Offline lint, diff spotlight, repo tests, merge-base `verify.paths`, code-bound formal suite | Standard `pdd.prove.v1` (`coverage` and `mutation` omitted) | Missing base/recipe/capability, untrusted config/script edit, timeout, diff test-integrity drop, `proved_spec_model` |
| Opt-in `--coverage` | Default checks plus per-file and diff-line coverage split across `formal`, `vectors`, and `all` (`runProveCoverage`) | `receipt.coverage` (`tool`, `suites`, `unionFormalVectors`, `files`, `uncoveredDiffLines`, `summary`) | Coverage tool unavailable or timed out for touched production code |
| Opt-in `--mutation-check` | Default checks plus 1–3 isolated non-destructive guard mutations against the formal suite (`runProveMutationCheck`) | `receipt.mutation` (`status`, `attempted`, `killed`, `survived`, `syntaxErrors`, `killRate`, `mutations`, `summary`) | Any formal-covered guard mutation survives (`[mutation-survived]`), syntax-only crashes yield 0 valid assertions, or mutation runner errors/times out |
| `--test CMD --expect TEXT` | Isolated base-vs-head bug-contrast in temporary worktrees | `mode: "bug-contrast"` | Setup/compile/signal error, timeout, wrong failure symptom |

- **Opt-in `--coverage` and `--mutation-check` isolation:** Neither flag alters default zero-flag `pdd prove` behavior, receipt keys, or exit codes when omitted. Both flags execute strictly inside isolated temporary directories outside the caller's checkout and never modify working-tree files even on crash or signal interruption. Both flags may be combined in one invocation (`pdd prove --coverage --mutation-check`), reusing collected formal line coverage to pinpoint formal-covered guards for mutation control. When `baseVerify`/shadow-bin/script tampering prevents executing repository commands, `--coverage` and `--mutation-check` also do not execute untrusted commands.
- **Universal Feature Map (`pdd.json` `"verify"`):** Declares optional `test` command, optional `report` path, optional `formal_command` (any language/solver formal command such as `crosshair check`, `cargo kani`, or `dafny`), optional `mutation_command`, and `paths[]` entries `{id, name?, scope?, tier?, when, run, needs?}` (max 100 entries, unique IDs; optional `tier` is `"simulated"`, `"real-host"`, or `"adversarial"`). `when` globs compile via the strictly linear DP glob matcher (`compileGlobMatcher`). `needs` accepts open capability strings (`tty`, `browser`, `docker`, `ios-simulator`, `account:<name>`, or custom strings) matched lazily against detected or injected host capabilities with zero hardcoded capability schema fields or repository names.
- **Multi-part integration guard (`#3575`):** When `product/plan.md` defines `>=2` distinct product parts (from `product/plan.md` `## Runs`/`## Parts`/`## Prompts`/`## Boundaries` using canonical columns or `Service`/`App`/`Component`/`Module`/`Consumer`/`Provider` aliases, and optional `product/map.md` `## Parts` tables or bullet lists) and merge-base `pdd.json` `verify.paths` has no recipe covering cross-part integration (`scope: "integration"`/`"journey"`/`"cross-part"`, integration/journey/cross-part/e2e in `id`/`name`, `when` covering `product/plan.md` / `product/**`, or `when` globs spanning `>=2` distinct product parts), `runProve` emits an explicit `Not proved` reason (`pdd.json:1 [multi-part-integration-missing]`) formatted as a 4-part agent-teaching diagnostic (`invariant`, `Fix:`, `Rerun: \`pdd prove\``). If `product/plan.md` is non-empty alongside `product/map.md` or `contracts/*.md` and `>=2` distinct subdirectories under `prompts/`, `src/`, or `services/` yet fewer than 2 parts parse, fail closed with `product/plan.md:1 [multi-part-plan-unparseable]`. Unwired or unparseable product boundaries (`[product-boundary-unwired]`, `[product-boundaries-unparseable]`) also produce `Not proved`. Single-part and non-product repositories are unaffected.
- **Base-trusted config and tamper defenses:** Zero-flag `runProve` loads `verify` config (including `verify.formal_command` and optional `verify.mutation_command` parsed/fingerprinted for tamper detection) strictly from the merge base (`git show <baseSha>:pdd.json`), enforces merge-base lint rule severities/disables and base-trusted `lint.commands` / `lint.mutation_command` (ignoring untrusted working-tree `pdd.json` or `rules/lint/*.json` disables/weakenings/command edits), and checks `package.json` `scripts.test` plus any npm/pnpm/yarn script or repo-relative script referenced by merge-base `verify.test`, `verify.formal_command`, `verify.mutation_command`, or `verify.paths` against `baseSha`. Uncommitted or branch-only edits to `verify`, lint overrides/commands, referenced `package.json` scripts, or referenced repo scripts produce `Not proved` — and when referenced `package.json` scripts, referenced repo scripts, or shadow binaries were tampered with, `runProve` refuses to execute repository test/verify/formal commands. Any tracked, untracked, or on-disk shadow binary under `node_modules/.bin/`, `.venv/bin/`, or `venv/bin/` fails closed (`[diff-shadow-bin]`, `Failed`) before executing repository test commands.
- **Honest proof-tier labels (`#3633`):** Every verify-mode run computes and reports 3 honest proof-tier labels (`simulated`, `real-host run`, and `adversarial run`) strictly from commands that actually executed during that run (`classifyVerifyPathTier`, `summarizeProofTiers`, `formatProofTiersLine`). `simulated` reflects `verify.test` (or auto-detected unit tests) plus any `tier: "simulated"` (`scope: "simulated"` / `"unit"`) verify paths; `real-host run` reflects executed real-host verify paths (default verify paths or explicit `tier: "real-host"`); `adversarial run` reflects executed `tier: "adversarial"` (`scope: "adversarial"` / `"break-it"`) verify paths. Any tier that did not execute is reported honestly as `Not proved`. Both JSON (`receipt.proofTiers`) and human output (`Proof tiers: simulated=<...>, real-host run=<...>, adversarial run=<...>`) surface all 3 labels without changing overall exit codes or scanning test source with static regexes.
- **Zero-flag verification mode:** Resolves the local merge base offline (failing closed as `Not proved` if base comparison is unavailable), runs deterministic offline `lintRepoProject` (with merge-base lint trust) + `runDiffSpotlight`, runs `verify.test` (or auto-detects Node/Vitest, Go, Rust, or Pytest), runs every base-trusted `verify.paths[]` recipe whose `when` globs match touched files and whose `needs` are satisfied, runs shared code-bound formal verification (`runFormalVerification` from [Formal verification](formal-verify.prompt.md)) whenever formal test files, formal-tested production modules, `## Rules to check` / `## Domain decisions` invariants, or merge-base `verify.formal_command` apply (reporting `Formal: proved_solver_code (...)`, `Formal: bounded (...)`, `Formal: proved_spec_model (not code-bound)`, `Formal: not-applicable`, or `Formal: missing (advisory: ...)` when invariant rules changed without formal tests yet; returning `Not proved` for disconnected `proved_spec_model` proofs or missing/timed-out runners, and `Failed` on failing formal tests or refused code-bound claims), flags `Not proved` on diff test-integrity regressions (`newSkips`, `assertionDrops`, `removedTests`, `tableDrops`), mock-only I/O/subprocess boundary tests (`[diff-mock-only-boundary]`), and touched Stories with unbound acceptance criteria (`[story-unbound-criteria]`), and emits a structured `pdd.prove.v1` provenance JSON receipt (`--json`, including `formal`) or human summary.
- **Bug-contrast mode (`--test CMD --expect TEXT`):**
  1. Overlays colocated test files (`src/**/*.test.*`, `*.spec.*`, `*_test.go`, `test_*.py`, `*_test.py`, `*_test.rs`, `test/**`, `tests/**`, `__tests__/**`, `fixtures/**`) plus any explicit `--overlay GLOB` matches, mirroring deleted test files into the base worktree so deleting a failing test never yields a fake pass.
  2. Resolves `--base REF` strictly offline from local Git refs without network fetches.
  3. Mirrors modified, deleted, and untracked files into isolated disposable base and head worktrees (`git worktree add --detach`) while validating every path segment against symlink escapes and opening destinations with `O_NOFOLLOW`, so the caller's checkout is never mutated.
  4. Scrubs credential and session environment variable families (`GH_*`, `GITHUB_*`, `CLAUDE*`, `ANTHROPIC_*`, `OPENAI_*`, `CODEX_*`, `HERDR_*`, `PDD_*`, `AWS_*`, `*_TOKEN`, `*_SECRET`, `*_API_KEY`, `*_PASSWORD`) before running `--setup` and `--test` in the disposable base and head worktrees, always removing both worktrees on exit.
  5. Detects setup, missing-dependency, import, syntax, compile errors, and signalled processes on base or head (`ERR_MODULE_NOT_FOUND`, `Cannot find module`, `ModuleNotFoundError`, `ImportError`, `SyntaxError`, `ENOENT`, `command not found`, exit `126`/`127`, `[build failed]`, `ERROR collecting`, `error[E...]`, non-timeout signals) by scanning stderr before stdout and normalizing leading diagnostic prefixes (`# `, `E `) once; classifies them as `Not proved` (`setup-error`), never as a causal proof; clears `SyntaxError`/`ImportError`/`FileNotFoundError` ONLY when the process did not suffer an independent hard failure (never clearing exit `126`/`127`, signals, exit `129..192`, or spawn errors) AND `--expect` names that error class with detail (never the bare class name alone) AND matches on that exact normalized diagnostic error line (never a separate banner). Only a non-setup base failure whose output contains `--expect` paired with a passing head run yields `Proved`. Timeouts resolve cleanly to `Not proved` with a `--timeout MIN` hint. Zero-flag verification inspects `git status --porcelain` before executing tests/recipes (recording `dirty`, `dirtyFiles`, and `proofScope`: `"commit"`, `"working-tree"`, or `"unknown"`), fails closed as `Not proved` if `git status` itself fails, and supports per-step environment isolation via `ports.envForStep({ phase, recipeId, command, baseEnv })`.

## Public contract

- `parseVerifyConfig(raw, {sourcePath})`: pure parser returning `{configured, source, test, report, formalCommand, mutationCommand, paths, errors}`.
- `loadVerifyConfig(rootOrObject, {gitRef})`: loads `pdd.json` safely from disk (no symlinks) or from `git show <gitRef>:pdd.json`, returning `{configured, source, test, report, formalCommand, mutationCommand, paths, errors, loadStatus}` where `loadStatus` is one of four values: `'ok'` (parsed clean config), `'absent'` (verified directory, Git commit, or object input has no `pdd.json` or no `verify` block), `'invalid'` (malformed JSON or schema errors), or `'unreadable'` (unreadable path or unavailable Git commit object).
- `matchVerifyPaths(verifyConfig, touchedFiles)`: returns `{matched, changedSurfaces, unmappedSurfaces}`.
- `detectHostCapabilities(requiredNeeds, {env, capabilities, probe, isTTY})`: lazily checks only requested capabilities and returns `{available, checked}`.
- `matchCapabilities(needs, capabilityState)`: returns `{satisfied, missing}`.
- `runProve({cwd, base, test, expect, overlay, setup, timeoutMinutes, coverage, mutationCheck, json, capabilities, env}, ports)` and async non-blocking `runProveAsync(input, ports)`: returns `{exitCode, outcome, receipt}` (or a Promise thereof for `runProveAsync`, which runs subprocesses in isolated process groups so `SIGINT`/`SIGTERM`/`SIGHUP` immediately kills active children, cleans up temp directories, and re-signals) and writes human text or JSON receipt to `stdout`/`stderr`.
