# PDD Claude launcher

Own `bin/pdd-claude.mjs` and `src/pdd-claude.mjs`. Provide a dedicated `pdd-claude` command that launches the user's installed `claude` binary through the PDD Cloud `/v1/claude-gateway` gateway without modifying `~/.claude/settings.json`, `~/.claude.json`, or the user's personal `claude` login.

## Domain decisions

- **Never mutate `~/.claude/settings.json`:** `pdd-claude` keeps `CLAUDE_CONFIG_DIR` untouched so all stock Claude Code features (chats and `--resume` under `~/.claude/projects`, `~/.claude.json`, plugins under `~/.claude/plugins`, skills, hooks, `CLAUDE.md`, `statusline.sh`, MCP servers, and Claude in Chrome `--chrome`) work with zero folder mirroring or path rewriting.
- **Session auth via private `0600` `--settings <file>` overlay:** Because Claude Code's `~/.claude/settings.json` `env` block overrides process environment variables and multiple `--settings` flags do not merge (last flag wins), `pdd-claude` extracts any user-provided `--settings` flags, parses the final user `--settings` value (JSON object string or readable JSON file path), merges PDD's gateway `env` overlay (`CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_API_KEY: ""`, `ANTHROPIC_AUTH_TOKEN: ""`, `CLAUDE_CODE_USE_BEDROCK: "0"`, `CLAUDE_CODE_USE_VERTEX: "0"`, `CLAUDE_CODE_USE_FOUNDRY: "0"`, and top-level `apiKeyHelper: ""`) into a single per-invocation `0600` file under `<runtimeDir>/sessions/`, passes `--settings <path>` to `claude` (never inline JSON on CLI so tokens never appear in `ps`), and deletes the session settings file immediately on exit.
- **Subshell safety without breaking permissions:** Strip `PDD_*` and ambient Anthropic auth/routing env vars (`CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`) from the spawned `claude` environment. Never set `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` because Claude Code disables bypass/auto permission modes when that variable is set and already strips `CLAUDE_CODE_OAUTH_TOKEN` from Bash subshells natively.
- **Legacy residue cleanup:** On session acquisition, call `restoreLocalClaudeGatewayConfig({ env, removeManagedFile: false }, ports)` (and `{ env }` on `logout`) to remove any legacy PDD `pddg_*` `CLAUDE_CODE_OAUTH_TOKEN`, managed `claude-gateway` `ANTHROPIC_BASE_URL`, or PDD-fingerprinted `sk-ant-oat*` tokens left in `~/.claude/settings.json` without touching genuinely user-managed settings.
- **Auto-wrapper fail-open (`PDD_CLAUDE_AUTO_FAIL_OPEN=1`):** Strip all `PDD_*` environment variables on every pass-through and fail-open child spawn so tokens (`PDD_TOKEN`, `PDD_ACCOUNTS_TOKEN`, `PDD_CLAUDE_AUTO_FAIL_OPEN`) never reach stock `claude`. When invoked with `PDD_CLAUDE_AUTO_FAIL_OPEN=1` and without `--account`, fall back cleanly to stock `claude` without mutating user settings ONLY on explicit transient/unavailable lease errors (`timeout`, `network_error`, `missing_auth_token`, `no_ready_account`, `no_account_available`, `all_cooling`, `not_enrolled`, `offline`, `service_unavailable`, `rate_limited`, `lease_unavailable`, network fetch error codes, or HTTP `401`/`403`/`5xx`); never fail open on security/validation/reauth codes (`unsafe_runtime_dir`, `symlink_refused`, `invalid_settings`, `invalid_lease`, `reauth_required`, `unsafe_path`, `invalid_args`, `unsupported_delivery_mode`, `lock_timeout`) or uncoded non-network `Error`s.

## Core behavior

- **Executable entry (`bin/pdd-claude.mjs`):** Check `process.versions.node` major version is at least 22 before dynamically importing `../src/pdd-claude.mjs` with `.then(...)` and assigning `process.exitCode` (zero static imports before the version check, zero top-level `await`, zero hard `process.exit`). Return exit code `127` when spawning `claude` fails with `ENOENT`.
- **Argument handling (`parsePddClaudeArgs`):**
  - Parse optional leading `--account <label>` / `--account=<label>` (rejecting empty/whitespace-only or dash-prefixed labels with exit `2`) and `--pdd-help` before `--` and before the first non-option argument; consume `--` only when separating leading PDD flags from non-dash args or known Claude/wrapper options (preserving `--` when at index 0 or followed by an unknown dash token such as `pdd-claude -- -prompt` or `pdd-claude --account a -- -prompt`) and forward all remaining arguments to `claude`.
  - Inspect `claudeArgs` past leading global Claude value/variadic/boolean flags to resolve the real subcommand and detect `--help`/`-h`/`--version`/`-v` before `--` (never treating positional prompts after session-only flags like `-p`/`-r`/`-w`/`-c` as subcommands, and never treating flag values after a prompt as top-level `--help`/`-v`/`--bare`). Reject `--bg` / `--background` with exit `2` because detached Claude exits immediately and revokes its leased session.
  - Local `--version`, `-v`, `--help`, `-h` (top-level or on any subcommand, including `logout --help` and `auth --help`), and offline/non-session subcommands (`mcp`, `plugin`, `plugins`, `doctor`, `auto-mode`, `update`, `upgrade`, `install`, `import`, `purge`, `agents`, `attach`, `logs`, `stop`, `kill`, `rm`, `respawn`, `gateway`, `auth status`, `auth help`) pass straight to `claude` without requiring a cloud lease or injecting `--settings`.
  - `pdd-claude logout` (without `--help`/`-h`) deletes `<runtime>/lease.json` and any stale session settings files inside the shared runtime folder, calls `releaseCloudLease` for the active lease, and runs `restoreLocalClaudeGatewayConfig` without touching personal `~/.claude` credentials or Keychain.
  - `pdd-claude login`, `pdd-claude auth login`, `pdd-claude auth logout`, and `pdd-claude setup-token` (without `--help`/`-h`) print clear instructions (`pdd accounts add --provider claude` to enroll, `pdd-claude logout` to end the PDD pool session, or `command claude auth login` / `command claude auth logout` for personal accounts) without mutating `~/.claude` or Keychain.
  - Extract user `--settings <file-or-json>` / `--settings=<file-or-json>` flags (before `--`, skipping values of other Claude value flags), validate and parse the last user `--settings` value (exiting `2` with a clear error if unreadable or invalid JSON), merge with PDD's gateway overlay, and prepend one `--settings <sessionSettingsPath>` to the forwarded arguments.
- **Shared machine runtime folder with PID ref-counting (`acquireSharedClaudeRuntimeSession` / `releaseSharedClaudeRuntimeSession`):**
  - Use one `0700` directory per OS user under `join(resolvePddStateBase(env), 'claude-runtime', 'pdd-claude-<uid>')` (overridable via `PDD_CLAUDE_RUNTIME_ROOT`), validating ancestor symlinks as well as the runtime root, runtime dir, `pids/`, and `sessions/` via `lstatSync` before and after `mkdirSync`, refusing symlinks (including ancestor symlinks owned by other non-root users) or directories owned by another OS user.
  - Serialize acquisition, release, and lease updates with an atomic `mkdir` lock directory (`owner.json` recording PID, unique lock token, and acquisition time; dead-owner recovery after grace; atomic stale-lock recovery after 30 seconds; ownership-verified unlock).
  - Track live sessions in `pids/<pid>`, sweeping dead PIDs (strict `/^\d+$/`) via `process.kill(pid, 0)`. Reuse an existing valid `auto_rotate: true` `lease.json` (> 5 minutes remaining) across concurrent `pdd-claude` windows so many sessions share 1 PDD Cloud Claude lease, fail fast if the leased account is `reauth_required`, write each invocation's merged `--settings` file to its own `0600` file under `sessions/`, and keep `exit` and `SIGINT`/`SIGTERM`/`SIGHUP` cleanup hooks active from session acquisition through `finally` release.
  - When a session exits, unlink its per-session `session.settingsPath` unconditionally FIRST (both in `runPddClaudeCli`'s `finally` block and at the start of `releaseSharedClaudeRuntimeSession`, before any directory validation or async release so leased OAuth tokens never linger on disk on error paths); when the last live `pdd-claude` process exits, also unlink `<runtime>/lease.json` and call `POST /v1/accounts/leases/{lease_id}/release`.
- **Pinned `--account <label>` mode (`acquirePinnedClaudeRuntimeSession`):**
  - Use an isolated `0700` temporary directory (`pdd-claude-pin-*`) under the same runtime root with `auto_rotate: false` and `currentAccountId: null` so pinned runs never disturb concurrent shared sessions or send a stale `current_account_id`, fail fast if the pinned account is `reauth_required`, and delete the temp directory and revoke the pinned lease on exit.
- **Background heartbeat (`startClaudeLeaseHeartbeat`):**
  - Periodically call `heartbeatCloudLease` (`POST /v1/accounts/leases/{lease_id}/heartbeat`) on a jittered `.unref()`'d timer (no-op if `intervalMs <= 0`), reading `lease.json` on each tick, deduplicating concurrent heartbeats via `last_heartbeat_at`, persisting refreshed expiries under the runtime lock (checking `stopped`), and clearing `lease.json` on `401`/`403`/`404` only when `!stopped` and `lease.json`'s `lease_id` still matches `leaseId`.
