# Draft missing Runtime interfaces

Own `src/interface-draft.mjs`. Preserve prompt prose. Leave existing blocks unchanged unless an explicit extension or refresh is requested. Export `runInterfaceDraft({words,all,json,cwd,contract,extend,refresh}, ports)`, `interfaceFindings({root,paths})`, `runtimeCoverage({root,paths})`, `missingInterfaces(root)` and `runAutomaticApproval({path,root,tests}, ports)`.

Draft only Git-visible regular in-repository prompt files in the runtime workspace. Resolve explicit paths from cwd. Refuse unsafe paths, malformed blocks, unknown paths and --all combined with paths before any write. With --all select all workspace prompts, excluding nested fixture projects. Without --all require at least one path. Continue across independent draft failures and report each result. Never choose native-only for the user. With contract, extend or refresh, require one explicit prompt, not --all. Extend requires contract and cannot combine with refresh. Validate the contract path through the same regular Git-visible workspace file boundary before writes.

Infer entry names and complete input/result schemas from explicit JSON interface declarations in the prompt or declared schema/contract dependencies. Resolve contract references with the shared contract reader. Existing module exports may supply clear operation names, but never invent types from names. No AI, authentication, program execution or network.

Also derive a single pure operation from explicit prose transport declarations: its named operation, required named input field and type, and required named result field and type in closed objects. Do not infer schemas from examples, function names or implementation answers. A numeric transport field remains number even when the function rejects non-integers. If the prose explicitly requests representative JSON shapes for non-number rejection, admit number, string, boolean, null, arrays of numbers and empty objects through disjoint oneOf branches; do not claim arbitrary nested-object coverage. Extract explicitly named error codes. If error wording does not provide all codes, ask for errors rather than silently choosing none. Treat additional schema declarations or effect statements outside the recognized transport as unresolved facts: ask for the complete result/input schema or resources/calls rather than omitting them. Conflicting purity statements leave effects unresolved. Supplementary claims (also/additionally/in addition), unknown named fields/flags, and unrecognized action claims leave the transport uncertain; include the literal unresolved sentence as a question. Never treat a no-effects statement as authority to discard another effect claim. Use the prose route only with no declared dependencies and a single operation. The 4/2 drafting ceilings are this command’s default execution budget, disclosed for review; they are not inferred domain facts. Require an explicit statement that there are no external resources, programs or saved data before declaring empty calls/resources. For this single pure operation use drafting execution ceilings max_steps 4 and max_model_calls 2; these are disclosed draft budgets, not new input restrictions or approval. Include row draft_budget with source command-default and limits, and print its review requirement. Such prose drafts require a person and cannot use automatic approval. Explicit JSON contracts retain their authored limits; missing limits there remain questions.

When facts remain missing, keep available operations as partial with draft_gaps, and return structured questions per missing field: pointer and question. Ask separately for missing entry input_schema/result_schema, errors, calls, resources and limits; distinguish an absent operation from unknown schemas. Ambiguous declarations require the author to select one. Each incomplete row includes a next_step naming `pdd interface draft PROMPT --refresh --contract FILE`, because the incomplete block has already been saved. Resolve the recovery prompt operand relative to the invoking cwd, and quote it for shell-safe display. Text prints the questions and next step. Never claim such a row is complete or Runtime-admitted.

`--contract FILE` supplies one JSON interface declaration from a regular Git-visible workspace file. This is the supported path for complex prose, file/network/program effects and exact admission repairs. Preserve authored entries, calls, resources (including operations and schemas), limits and conventions, using the Runtime resource format in RUNBOOK §21. Refuse incomplete or locally invalid supplied declarations before changing the prompt; name their JSON pointer and rule. Every resource needs name, kind, read/write access and nonempty uniquely named operations; every operation needs read/write access and complete closed object arguments_schema/result_schema, including oneOf alternatives of closed objects. Every call needs a unique operation, target prompt path, target_operation and positive integer max_calls. Refuse unknown nested entry, call, resource and resource-operation fields while retaining the Runtime binding metadata (instance and resource_operations) used for factory/method entries. A read resource cannot contain a write operation. Entry errors are unique nonblank codes. Conventions rows have only a valid existing interface JSON pointer path and a nonblank convention name. Retain interface v2 schema_version, instance_types and entry copy_out declarations; instance types name a write collection and every factory/method names a declared type. Extension merges new instance types by name and permits opting into v2 without changing old entries. Unknown top-level fields are refused; effect declarations belong in resources, not an ignored effects field. Do not put draft_gaps or authoring-only question metadata into a complete Runtime block. Do not narrow union inputs to get admission. Serialize full drafts using the implicit full form (omit kind); the strict Runtime parser refuses an explicit kind: full. Keep kind: partial only on incomplete local drafts. This transport spelling does not change the full contract meaning.

Without an existing block, insert the contract. `--extend --contract FILE` merges by entry operation, resource name and call operation; identical declarations are retained, conflicting existing declarations are refused with a pointer, and only new declarations are appended. Existing limits and conventions must remain equal if supplied. Retain old declaration values and order, including approved operations; set the combined block status to draft, with a current prose hash. An extension never approves either old or new behavior. `--refresh` explicitly reopens an existing full/partial block as a draft and updates its prose hash; with --contract it installs the complete replacement declaration for changed behavior. Without --contract it changes only status/hash and removes a redundant kind: full and refuses unresolved gaps or malformed schemas. A plain draft call never refreshes or extends an existing block. Preserve all prose bytes and bytes outside the single interface block. Any failure leaves the prompt untouched. Store drafting provenance under .pdd/, outside Git: original prose, draft interface and Git head identities. Prose-default/extension/refresh provenance must not qualify for automatic approval of new behavior.

Lint every selected block locally through preflight and shared contract expansion. Return per-path state (drafted, existing or refused), problems and lint_clean, plus questions and next_step only when facts are missing. Local lint is not Runtime admission. Use pdd lint STORY for admission and report its exact field/rule diagnostics. Draft never uploads or runs checks. Print drafted, existing, lint-clean and refused counts. JSON contains the same results and exit_code. Exit 0 only when every selected block lints clean; exit 4 for block or drafting problems; exit 2 for usage/repository/path problems. Drafts are not approved.

Automatic approval accepts only a complete draft made by this command whose committed prose and all existing source still match its provenance. Reject native-only, gaps, an edited interface, new prose and strict approval mode for the selected prompt. Committing unchanged drafted blocks does not make them new behavior. Compare source with the recorded original tree while checks use the current source and current head. Other unchanged blocks from the same bulk draft may remain draft or already be approved; verify their stored draft identity and committed original prose instead of treating those metadata additions as new behavior. Require a native test command that names existing committed tests; run it from the repository through the execution port. Require exit 0 and then a complete prompt check on every existing Story test that reaches this prompt, using the normal runtime client. Include every discovered test variant of each affected Story, even variants that could not be parsed. Refuse unreadable or invalid variants before checking. No missing tests, cached passes, unknown/not-run/refused rows, partial checks or absent passing counts qualify. Recheck source identities after both runs. Evidence includes command, native exit, current source and prose hashes, prompt-check rows and route automatic-check-pass. Use the shared approval writer only after this evidence is complete; roll back a prompt write if journal recording fails. Never convert this to a person's approval or call it from draft/setup. Prompt and native checks remain separate evidence.

## Inventory results

`missingInterfaces(root)` returns sorted paths of workspace prompts with no block. `interfaceFindings({root,paths?})` returns `{code,path,section?,message}` rows for absent, malformed, stale or schema-invalid blocks, including draft gaps. Its default paths are workspace prompts outside nested fixture projects. `runtimeCoverage({root,paths?})` uses the same default scope and returns `{checkable,total,native_only}`. Total counts every selected prompt; checkable counts valid current full or partial blocks with entries; native_only counts valid current native-only declarations. Invalid, stale, missing and incomplete blocks remain only in total. A stale hash must not hide draft gaps: report both findings, so local lint still refuses the unresolved contract. Neither helper makes a network call or claims a server lint pass.

Native test commands for automatic approval are `node --test TEST...`, `npm test` or `npm run SCRIPT`. Node paths must name committed tests (a test/tests directory or a .test/.spec filename). npm scripts must be test or test:* and must exist in the committed package. Require a completed TAP report with a positive test count, all tests passed and zero failures. Retain those native counts with the command and exit code; a no-op or build is not native-test evidence. Run the chosen command as arguments, with no shell interpolation. Hash source bytes without decoding binary files.
