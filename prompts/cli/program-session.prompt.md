# Program sessions

Own src/program-session.mjs. Export module functions
`openProgramSession({root, file, program, data, appMap, overlay}, ports)` and
`closeProgramSession(session, ports)`. Open returns the interpreter's no-Story
session and metadata needed for calls; close stops that session with the existing
confirmed-stop protocol. file is the repository-relative entry, program its stable
name, data the programData result. Share these functions with app dispatch.
The result always includes at least `{id,url,serve}`, including on reuse: id is
runtime session identity, url is the app page URL (the single URL C prints), and
serve provides runtime origin and the signed-in request function needed to proxy
HTTP routes as try-http.mjs does. Additional CLI/typed metadata is allowed.

appMap and overlay are optional C inputs; CLI callers omit both. Preserve the
joined appMap object unchanged in the interpreter session request under its
existing `app_map` field. overlay is
the synchronous source-preparation callback accepted by captureSource's
prepareSource port, returning generated `{path,bytes}` upload files such as the
joined map and seed. Pass that callback unchanged into source capture and upload
its generated bytes with the captured source, retaining capture's privacy,
limits and identity rules. It is not a new serialized runtime request field.
Without either optional argument, preserve the CLI no-Story request behavior.

Reuse one session for unchanged program source/data/login. Capture only the entry
graph and compare reached prompt and dependency identity before reuse. On source
change replace automatically, carrying confirmed world; never require --new.
A fresh request invalidates saved answers and starts from selected initial data.
Unchanged input and data may reuse a confirmed result at0 calls only when the
current world equals that result's data_before, not data_after. Repeating a
mutating command with the same argv must send again and apply its mutation
again. Replay preserves the saved program exit code, including nonzero codes. Never cache
failed/refused/unknown results or reuse another login's session. Retain pending
request IDs before dispatch; read ambiguous accepted work by GET only.
No synthetic Story/scenario is uploaded; the interpreter derives default fake
bindings for the graph. Session requests use entry, initial_world and optional
simulation, never seed. Default session max_calls is300, independent of the per-call --max-calls option;
never silently replenish a session or raise its allowance. Call requests always
send max_calls and boolean fresh. Session answers retain optional kind, entries
and expires_at when provided; do not require unavailable NEW server fields.
Preserve worlds, receipts, errors and call_chain unchanged. Local answer identity
includes per-call cap; no clock-dependent graph result may satisfy local cache,
including real clock.now whose time is not stored in world. Interpreter/model
cache identity remains server-owned; never invent a version endpoint.
Confirmed stopped/unknown session admission permits replacement carrying confirmed
world; session-busy exits125. Never replace and repeat uncertain accepted work.

## Own fake prompts

For resources declared by reachable prompts, discover only matching
`prompts/fakes/<resource>.prompt.md`. Include selected fake prompt closure and
hashes in source capture/session identity through existing privacy/prepareSource
hooks, composing with C's overlay without dropping either callback's files.
Unrelated fake prompts stay outside upload. Explicit simulation bindings win.
For kind http or port, auto-bind each resource operation only to the same-named
fake entry, or its sole entry when unambiguous, with canonically equal argument/
input and result schemas. Ambiguity, missing operation or incompatible schemas
refuses locally with a plain actionable explanation. Automatic custom replacement supports http and port only. Other resource kinds
retain interpreter defaults; never invent unsupported wire actions.

The supported closed simulation binding is exactly
`{action,target,operation,max_calls,request_template,request_mapping,response_template,response_mapping}`.
The simulation key is `<resource-name>.<operation-name>`; action is `http.prompt` only for kind http,
or `port.prompt` only for kind port. target is the repository fake prompt path;
operation names the selected fake entry. For equal schemas use request_template
and response_template `{}`, and request_mapping and response_mapping each
`[{"from":"","to":""}]` (whole-value identity). max_calls is an integer1–20
and must bound fake invocation. Automatic bindings use min(20, declaring prompt
limits.max_steps), including when replacing the default service. When several
reachable owners share a simulation key, use the maximum of their bounded limits
if the target and schemas agree; otherwise report the existing binding ambiguity.
Explicit bindings keep their supplied max_calls unchanged. Never execute a real service. Native discovery,
admission and capture consume0 AI calls; fake execution belongs to server cap.
