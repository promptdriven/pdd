# A person's approved new Story rule

Own `src/agent-story-rule.mjs`. Export synchronous `planAgentStoryRule({root,saved,rule})`, `applyAgentStoryRule({root,stateDir,plan,approved=false})` and `resumeAgentStoryRule({root,stateDir,caseId,saved?})`. This module implements the person's explicit Save plus terminal approval of one missing rule. Planning is read-only. No prompt, model setting, approval status or unrelated Story changes. The caller asks the person and supplies approved:true only for their y/yes; no browser field supplies approval.

## Read-only plan

Use the saved-case planner to require exactly one unknown checked criterion. `rule` must match its `{text,source_text,source_id}`. Refuse multiple missing rules, duplicate authored texts, a rule already present, unsafe paths, inconsistent local tests or a Story without a numbered Acceptance list. The bounded single sentence approved by the person is rule.text; normalize only the proposed source criterion's text to that sentence for the new case. Preserve all step inputs, starting world and expected values. The question is exactly `This is not in the Story yet. Add it as a new rule: '<text>'? y/N`.

Append the rule as numbered item N+1 immediately after the existing numbered Acceptance list, preserving the other Story bytes and line endings. Verify native Story parsing yields exactly the old criteria followed by this sentence. Canonical criterion ID is ac-(N+1).

For each Git-visible unscoped scenario belonging to this Story, require its criterion texts to match the old full Story exactly, unique source IDs/texts, known check IDs and exact checks for every criterion. Migrate its criteria to canonical ac-N source order and add criteria_scope for only these old items. Remap check criterion IDs. Patch only those JSON spans: preserve every byte of inputs, starting worlds, steps and expected values, including negative zero and large numeric literals. Existing valid scoped scenarios are unchanged, but must pass duplicate-key, scenario/step/check structure, known check-ID and exact-check-per-selected-criterion validation before they are skipped. Reject ambiguous duplicate JSON keys or inconsistent scoped metadata rather than guessing. Never read secret-looking files or follow symlinks. Documents are bounded to 1 MiB and Story text to 64 KiB. Count serialized transaction bytes as each change is accumulated, including metadata and JSON escaping; stop at the 64 MiB journal budget before retaining more changes, rather than reading and retaining every test before measuring the final plan.

Ask the case planner for a separate case against the trusted future Story text. It supplies the complete case bytes/path/receipt without writing. A plan contains schema, canonical repo, case_id, payload_sha256, story_path, rule, criterion_id, question, case_path, receipt and changes `{kind,path,before,after,before_sha256,after_sha256,mode}`. payload_sha256 is the saved-case fingerprint of the original queued payload, before any proposed-rule normalization. Require a lowercase 64-hex fingerprint in every plan/journal. Changes are new case first, old test migrations next, Story last. The plan's approved question and all changes form one fixed transaction; the new case must be included before Story growth. Return `{status:'ready',result,plan}` or plain `{status:'refused',result}`. No directories are created while planning.

## Explicit approval and resumable writes

Without approved:true, apply returns declined and writes nothing. With approval, require a genuine unchanged plan from this module instance, canonical matching root and all current files equal their before bytes (new case absent). Refuse stale plans before creating a journal or changing files. StateDir is supplied by the caller, absolute, outside the repository, owner-private and free of symlink components. Journal identity is a hash of canonical repo and case ID, never a server pathname. Create a mode-0600 approved journal atomically and durably containing the fixed plan and checksum. Anchor journal publication to a verified directory descriptor when available and recheck the private directory before any bytes are written and before publication. Directory fsync is attempted where supported; portable filesystems do not provide a universal power-loss guarantee. No raw file contents or proposed text appear in error diagnostics.

Resume reads only a regular private bounded journal at that identity, validates schema/checksum/root/case and all planned transformations, and never asks or invents approval. When resume receives saved, require agentSavedCaseFingerprint(saved) to equal plan.payload_sha256 before any file mutation, completion marking or completed-result return; a changed queued case refuses even if the local collector receipt was lost. Omission remains supported for trusted direct recovery. Before any resumed write, every affected file must equal its exact before or after bytes; missing/edited/unrelated files refuse without writes. Already-completed changes are skipped. Recheck identities and hashes before and after writes. New case publication is exclusive; existing target replacement uses a same-directory temporary file followed by a guarded atomic rename. Preserve existing file modes. Never overwrite an unrelated collision, follow a known symlink, or intentionally replace an edited file. Directory identity changes are failures; on platforms without atomic compare-and-replace against a hostile filesystem writer, guarded checks detect ordinary drift but cannot promise adversarial race immunity.

Write new case first, migrations next, Story last. A crash between file replacements can resume from exact before/after hashes using the approved journal. After all files match their after hashes, atomically persist a completed journal marker and final receipt. The journal checksum covers completion state and receipt as well as the plan. The journal is retained for deduplication. A repeated completed resume requires every affected file still match its after hash: a missing or edited completed file refuses without recreating it. A crash after all writes but before marking completion may verify all after hashes and persist the marker on resume. A repeated completed resume returns already_added with the same receipt, never appends another rule or file. I/O interruption after journaling returns pending with case_id; drift/bad journals return refused. Successful added/already_added results include result/path/receipt; receipt adds rule and criterion_id to the case planner receipt. The caller owns reporting/import-result retries. An absent journal returns absent and never creates one.

- [Saved case planner](agent-saved-case.prompt.md), required generation/runtime context: agentSavedCaseFingerprint owns original queued-payload identity; planAgentSavedCase owns queued-case validation, canonical own-case output/path, future-Story dry runs and case receipts.
- [Runtime preflight](runtime-preflight.prompt.md), required generation/runtime context: gitFiles, isSecretPath, storyCriteria and TEST_SCHEMA own visibility/privacy/native Story parsing and canonical scope admission.
- Node filesystem/path/crypto/util built-ins provide bounded guarded reads, JSON span bookkeeping, hashes, private journaling and local atomic publication. No network or provider is used.
