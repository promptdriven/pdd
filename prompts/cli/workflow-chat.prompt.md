# Area chats in Herdr

Own `src/workflow-chat.mjs`. An area chat is one native Codex or Claude session in its own tab of the Herdr session `pdd`. pdd starts it and then leaves. pdd never watches it.

- Use only the session `pdd` (`herdr --session pdd …`). Never touch the person's default session or another session.
- If the `pdd` server is not running, start `herdr --session pdd server` in the background. Remove agent-session markers (`CLAUDECODE`, `CLAUDE_CODE_*` session values, `CODEX_THREAD_ID`, `HERDR_*`, `PDD_AGENT_SESSION`) from its environment, so chats in it save their transcripts. Wait for it only while that server process is alive.
- `homeVariable(agent)` is `CLAUDE_CONFIG_DIR` for Claude and `CODEX_HOME` for Codex. `expandHome(dir, env)` returns null for an empty value, the home folder (`HOME`, else `os.homedir()`) for `~`, `<home>/x` for `~/x`, and any other value as it is. `isFolder(dir)` says whether a folder is there. Every place that starts or resumes a chat, or reads its sessions, expands the saved config folder first, so a run saved with the `~` text still works.
- `startChat({run, area, message}, ports)`: use the [run layout](workflow-herdr-layout.prompt.md) (a repository workspace for each verified common Git directory, a workspace per run, and a new tab per area named after the area). Write the first message to `<run folder>/<area>-start.md`. In the tab, run one short shell line: `env PDD_AGENT_SESSION=1 [CLAUDE_CONFIG_DIR=…|CODEX_HOME=…] claude --dangerously-skip-permissions --session-id <new uuid> "$(cat '<file>')"`, or for Codex `codex --no-daemon --dangerously-bypass-approvals-and-sandbox -c 'projects={"<worktree>"={trust_level="trusted"}}' "$(cat '<file>')"`. The config folder is the run's `configDir`: the `CLAUDE_CONFIG_DIR` or `CODEX_HOME` of the terminal that started the run. So every area chat of a run uses the same account, even when someone approves from another terminal. Return the chat record (tab, pane, terminalId, workspace, label, start time, session `{agent,id}` when known, config folder). Prepare that identity before the pane launch. If its reply fails, attach that same record as `error.chat` with `startUnconfirmed: true`; the caller saves it because the command may have dispatched.
- Module function `sendToChat(chat, text, ports)` owns bounded readiness and one ordered Herdr submission; see [Message delivery](#message-delivery). Return `{ok:true}` on acknowledgement or `{ok:false, code}` on failure, with `uncertain:true` only when submission may have happened.
- `chatSession(chat, ports)`: read `herdr agent get <pane>`. Return `{alive, status, sessionId}`; when Herdr fails, `{alive: false, status: null, sessionId: null, code, message}` with Herdr's error code (`agent_not_found` when no agent runs in the pane).
- `openChat({run, chat}, ports)`: if the tab is gone, make a new tab in the run workspace, except for an unconfirmed launch: inspect its saved agent first. If the tab and agent/pane are both confirmed missing, return restartAvailable without creating a tab, launching or resuming. The caller archives that stale start and offers an explicit new open to start this area again in the same run. A live agent or an unavailable inspection retains the original identity and refuses replacement. If no agent runs in the pane, resume the native session there (`claude --resume <id>`, `codex resume <id>`, with the same full-access flags), and set `chat.resumedAt` to now. An inspection failure other than confirmed `agent_not_found` must throw before any native launch/resume; unavailable Herdr is not proof of an empty pane. For a retained `startUnconfirmed` chat, an observed live agent confirms the original launch. Without it, refuse another launch/resume and tell the person to inspect that same pane; never send a fresh first message blindly after a lost reply. A failed resume request marks that same chat unconfirmed too. Successful positive observation clears the unconfirmed flag. Focus the tab. Terminal attachment with `herdr session attach pdd` is separate from opening effects and observation persistence: the runner must persist observations and release its run lock before attachment. An optional awaited `ports.beforeAttach(chat)` caller hook may perform that handoff after all opening effects and observations, before attach; a rejected hook prevents attach. Without the hook, direct `openChat` calls retain normal attachment behavior. Attach completion or failure must not trigger later unprotected chat/run writes. Attach only when the caller has a terminal and is not inside Herdr. Otherwise print where the chat is.
- `closeChats(run, ports)`: close each chat tab, then the run workspace, then the repository workspace when no other run uses it. Failures are warnings. Chat labels are `<repo name>#N NAME › AREA`.

Pass input preAgentRefusal to the layout only for a saved first-start run with no chats, completed steps or
PRs and the canonical linked_worktree_source chat failure (or its exact saved startup warning on legacy runs).
The layout owns inventory-backed recovery; neither chat startup nor recovery allocates another Git worktree.
Forward the command execFile port to the layout's verified repository-parent lookup.

Herdr transport reads complete stdout/stderr before interpreting JSON or a nonzero exit. Responses larger than a pipe buffer must retain their full content, and a nonzero response must keep its structured error code. Attaching to a session waits for stream closure before reporting its exit status.

Full-access flags stay. Do not pin tool versions. No workflow or native-session lifetime timeouts; the message-readiness deadline below is the local exception. Shell-quote every path and the resume id in the shell line. A native session id (from Herdr, a session file or the run record) is stored or used only when it is a UUID; `chatCommand` refuses any other resume id.

## Explicit fresh session

Export module function `restartChat({run,chat,message,pending}, ports={})`, returning the active chat record after replacement or rollback; a safely ended historical attempt returns its saved original custody without asserting that it is usable. The [runner](workflow-runner.prompt.md#open-a-saved-area-or-replace-its-session) owns selection, continuation content, run locking, archives and persistence. This module owns native ownership verification and replacement effects; ordinary start/open retains its existing behavior. Use the same saved agent/config and assigned worktree, full-access flags and shell quoting. Never pass a resume id for the fresh launch.

```mermaid
flowchart TD
    P{Saved pending attempt?} -->|Yes| R[Inspect and reconcile same attempt]
    P -->|No| V{Ownership and caller safe?}
    V -->|No| F([Refuse; saved run unchanged])
    V -->|Yes| C[Checkpoint intent; request owned close]
    C --> A{Acknowledged and absent?}
    A -->|No| U
    A -->|Yes| N[Prepare one tab and native identity]
    N --> L[Checkpoint dispatch; launch once]
    L --> K{Nonthrowing launch reply?}
    K -->|Yes| D([Launched])
    K -->|No| U
    R --> O{Known safe outcome?}
    O -->|Same launch observed| D
    O -->|Prelaunch proven; area current| N
    O -->|Historical attempt safely ended| E([Ended; no fresh launch])
    O -->|Original usable| B([Rolled back])
    O -->|Inspection unavailable or ambiguous| U([Retry same command; cancel available])
```

A failed checkpoint stops before the next native effect. Never retry a native request internally after uncertainty. Any nonthrowing `pane run` reply confirms launch, as for ordinary startChat; do not require an empty JSON object. Recovery is an explicit later --new invocation, not a fresh attempt.

Before intent, inspect complete workspace/tab/pane inventories and agent state once. Require the saved workspace to be the run's linked worktree (`checkout_path` equals assigned `run.root`, `repo_key` equals `run.commonDir`), the tab in that workspace, and its single pane to match saved pane, cwd and any saved terminal id. Refuse missing/changed/extra-pane ownership, malformed inventories and inspection failures. This module owns caller safety: refuse whenever injected `ports.env` (default process env) has `PDD_AGENT_SESSION` set. Also refuse the caller's selected pdd pane, or an undetermined pane when inside Herdr, with another-terminal advice. Identify the pdd caller using `HERDR_PANE_ID` and the `pdd` session component of `HERDR_SOCKET_PATH`; the same pane id in another session is not the target. Do not duplicate these checks in the runner. An unconfirmed original launch requires positive observation of that same saved agent before replacement; absence never clears uncertainty. Preserve any positively observed valid native UUID in the archived original; an alive original need not expose a UUID or invalidate an already saved valid Claude id.

Close only this verified area tab, retaining peer tabs and both workspaces. Record closeRequested before close and record its acknowledgement separately from absence; `closed` requires fresh inventories confirming both tab and pane absent, plus either an acknowledged close or the lost-acknowledgement recovery proof below that the original native session cannot still be running. A lost/malformed close reply is not an acknowledgement. Reuse the verified layout under its existing lock; no new Git worktree or workspace cleanup. Before tab creation persist createRequested with the complete preallocation inventory and the area label, so a later inspection can identify a created tab despite a lost reply. The visible tab label stays exactly the area name, without an attempt UUID; saved inventory and verified ownership distinguish this attempt from peers. Before dispatch prepare/checkpoint the exact replacement identity (tab, pane, workspace, terminal, area, agent, configDir, startedAt, label, messageFile and known native UUID). Claude preallocates a UUID; Codex retains null until observed. Never pass a resume id on the fresh launch. A thrown/lost launch reply retains this same `error.chat` with startUnconfirmed:true.

<details>
<summary>Recovery and rollback by durable phase</summary>

`restartChat` also accepts an optional `pending` saved envelope in its existing object input. Reconcile custody from that record and fresh inventories, never from a new identity invented on retry. Its area/original identify the recovery target even when legitimate workflow progress has advanced run.area; inspect and reconcile that recorded chat, never substitute the newer current chat. If the recorded area is no longer current, this restriction wins over every phase continuation below: only restore a verified usable original or end the historical attempt after safe inspection; never allocate or dispatch a fresh historical-area native session. Do not resume a stopped historical agent merely to make rollback usable. A historical prepared attempt that never requested launch closes only its exact verified owned empty shell tab before ending; require authoritative shell process information and no Codex/Claude process. Unknown process information preserves pending custody; never close an unknown or agent-bearing pane. A previously dispatched historical launch may be positively observed and recorded without any new dispatch. Ambiguous or unavailable inspection stays retryable, preserving custody and the newer current chat. Use one native ownership/observation path for initial replacement and recovery; keep only checks needed for the observed phase.

- `intent`: no close was dispatched. If the original is still owned and usable, roll back to it, retain the archive, and finish this invocation without closing it. Otherwise retain a retryable attempt until inspection can establish ownership.
- `closeRequested`: close may have happened. If the exact original remains owned and usable, roll back without reissuing close. If its tab/pane are absent, distinguish a saved acknowledged close from a lost acknowledgement. The former may continue prelaunch; for the latter inspect the saved original native session/agent as well as inventories, and establish that it cannot still be running before continuing. Unavailable or inconclusive inspection refuses retryably; mere tab absence is insufficient.
- `closed`: closure is confirmed and allocation has not been requested. Continue the same explicit attempt through createRequested.
- `createRequested`: allocation may have happened, launch has not. Reconcile the saved inventory and allocation identity: adopt the unique owned new tab/pane for this attempt and checkpoint prepared; if complete inspection proves no allocation occurred, create once for this same attempt. Ambiguous/unavailable inventory cannot authorize another allocation. Never adopt a peer tab.
- `prepared`: launch has not been requested. Verify the exact prepared tab/pane is owned and has no agent, then launch its same identity once. If that prepared tab is confirmed gone and no launch was requested, safely recreate its prelaunch container under the same attempt, preserving the preallocated native identity; never reuse this rule for launchRequested.
- `launchRequested`: dispatch may have happened. Positive observation of the exact saved replacement agent/session confirms launched without another launch. Inspect native session evidence and its exact identity when the pane is absent. Never allocate or dispatch another fresh session from absence alone. If authoritative inspection establishes that dispatch never occurred, continue that same prepared identity; if a saved session exists but stopped, resume that exact native session in a verified owned container instead of sending a new first message. If the available agent cannot establish its exact native identity, retain a retryable refusal rather than inventing an id or launching again.

A `pane_not_found` inspection reply establishes missing only when the same complete inventory also proves the selected pane absent; treat it then like `agent_not_found`. If inventory still contains the pane, refuse retryably; never infer absence from the error alone.

Before any phase continuation, including proven-unsent recovery, check `recovery.resumeRequested`: when true, only positive observation of the exact saved resume-target agent/session can finish the attempt without dispatch; absent or unavailable observation retains pending custody and cancel, with neither fresh dispatch nor another resume. Otherwise, before launchRequested recovery can dispatch or resume, apply the shared startup grace `START_GRACE_MS` used by status, measured from the latest finite timestamp among replacement startedAt, replacement resumedAt and `recovery.latestLaunchRequest.at`; older envelopes without request metadata use the latest finite replacement startedAt/resumedAt. Legacy envelopes remain valid: derive their initial request identity from the existing attempt id; never reset their grace to the retry time or reject them for lacking new fields. Positive observation of the exact saved replacement always confirms without dispatch; the following proven-unsent branch applies only when no agent is positively observed. Until it expires, absent observation of the newly launched agent remains pending with the resolving --new command, even when its exact native session file exists; never inject resume into a possibly starting agent. At expiry, authoritative Herdr `pane process-info --pane <id>` establishes that launch never ran only when the exact owned replacement pane is alive and all these facts hold: `pane_id` matches, positive `shell_pid` equals `foreground_process_group_id`, and nonempty `foreground_processes` contains only that shell PID with a recognized shell `name` (bash, zsh, sh, dash, fish, ksh or tcsh), with no Codex/Claude process. For a current area, checkpoint `recovery.unsentProof` tied to the inspected latest request and a new `recovery.latestLaunchRequest` before sending the same prepared launch once under the run lock, retaining its native identity; a failed checkpoint sends nothing. A present Codex/Claude process always forbids another launch, even without a native UUID. Missing, malformed or unknown process information is not proof: retain safe pending custody and name the resolving --new command and cancel. A lost reply to this recovery dispatch remains uncertain; repeating --new cannot resend from the earlier proof. Any further dispatch requires the startup grace measured from the latest finite anchor defined above and new authoritative proof that this latest request never ran; no lifetime retry cap applies. Otherwise the exact-session recovery rules below apply.

Before any recovery resume, persist `recovery.resumeRequested:true` in the same envelope. Its exact saved native-session target is original for intent/closeRequested rollback and replacement for launchRequested recovery; never allocate a new native identity. On subsequent recovery, the resumeRequested guard above applies, including after a lost reply.

Rollback marks rolledBack, restores the verified usable original as active and preserves immutable archive custody. Where the original is confirmed closed, continue the explicit prelaunch attempt only if its area remains current. Otherwise mark terminal `ended` without a fresh launch, without installing a nonexistent chat as usable, and without changing the newer current chat. Unavailable external inspection may temporarily prevent either result: retain the exact phase and offer only `pdd workflow open ISSUE --new` as the resolving command, with cancel still available. This protocol adds no approval gate and never requires manual record edits. All retries return after recovery; they do not immediately replace the recovered chat again.

<details>
<summary>Required checkpoint and message artifact interface</summary>

`ports.checkpoint(record)` is required and awaited; it resolves only after runner persistence. The JSON-serializable envelope is `{id,area,phase,at,original,replacement?,recovery?}`. `id` is a new UUID for the attempt, `area` is the selected area's name, `at` is its initial epoch milliseconds, and `phase` is exactly `intent`, `closeRequested`, `closed`, `createRequested`, `prepared`, `launchRequested` or `launched`, with terminal `rolledBack` for a recovered usable original and `ended` for a safely ended historical attempt. `recovery`, when present, is `{closeAcknowledged?,allocationLabel?,tabIdsBefore?,resumeRequested?,latestLaunchRequest?,unsentProof?}`: closeAcknowledged and resumeRequested are optional Booleans (absence means not acknowledged or not yet requested, respectively), allocationLabel is the area tab label, and tabIdsBefore is the complete preallocation tab-id list. Save acknowledgement immediately after a successful close response, before further inspection. Save allocationLabel and tabIdsBefore before allocation. `latestLaunchRequest` is `{id,at}`: a fresh UUID identifying each fresh-launch request and its finite epoch-millisecond intent time, checkpointed before the initial launch and before every proven-unsent recovery dispatch. Create this metadata only when committing to the next dispatch, never merely for inspection or a retry that remains pending. `unsentProof` is `{requestId,requestAt,observedAt,paneId,shellPid,foregroundProcessGroupId,shellName}`: the inspected request UUID and intent epoch milliseconds, finite epoch-millisecond observation time, exact replacement pane id, positive shell PID and matching foreground process group id, and recognized shell name from the authoritative process-info response. For older envelopes without request metadata, use the existing attempt id as requestId and the latest finite replacement startedAt/resumedAt as requestAt; retain their saved replacement identity. If no finite anchor exists, remain pending rather than inventing one. Proof must be obtained after the inspected request's startup grace. Save the proof with the new request intent before dispatch; its old requestId then remains audit custody only and cannot authorize another request. Failure of this checkpoint sends nothing. `at` remains the immutable initial attempt time, and fresh dispatch intent never changes the prepared replacement identity or its startedAt/resumedAt. The prepared identity stays in replacement. `original` is the complete saved chat plus `originalMessageFile` (its prior path) and `messageFile` (the immutable archived path); retain original session/config/identity fields. `replacement` is absent until prepared and required in prepared, launchRequested and launched; rolledBack and ended may retain it as custody metadata. launchRequested carries `replacement.startUnconfirmed:true`; launched clears that flag only after a nonthrowing launch reply or positive observation of the same installed launchRequested identity; observation recovery never dispatches again. No callback takes a bare phase string or mutates unrelated run fields.

Before intent and before touching `<area>-start.md`, copy the original first-message file's exact bytes to `<runDir>/abandoned-chats/<id>-start.md` with exclusive creation, and point `original.messageFile` there. Missing/unreadable original bytes refuse before close; never substitute the continuation text. Write the fresh continuation to `<runDir>/<area>-restart-<id>-start.md`; never overwrite an original or archived message artifact. A failed checkpoint prevents the next native effect and retains earlier effects and the last durable custody record. Eligibility and ownership refusals before intent leave the saved run unchanged, with at most these local artifacts. After intent is durably saved, checkpoint or transport failure retains that exact pending custody for recovery; it is not an eligibility refusal. No failed checkpoint permits the next close, allocation or launch. The final launchRequested checkpoint rechecks cancellation before dispatch. Cancellation observed there prevents launch. Cancellation arriving after that final check but before native dispatch remains a narrow race because legacy cancel does not take this lock; do not claim the check makes those two effects atomic. All filesystem, clock, UUID and Herdr effects use injected boundaries for native testing; these contracts add no unsupported Interpreter interface or check-only export.

## Message delivery

A pane-launch acknowledgement does not establish agent readiness. For `sendToChat`, the startup window ends 30,000 ms after the latest finite `startedAt` or `resumedAt`; missing timestamps supply no startup grace. At entry, capture the nonnegative remaining window and an elapsed-clock baseline. Every later wait/check must satisfy both that original elapsed budget and the persisted startup deadline, so a wall-clock change never extends the window. Use injected wall-clock `now`, monotonic millisecond `elapsedNow` and `sleep(ms)` ports, with production clock/delay defaults. A retry never restarts either budget. The first inspection and its known-ready submission are allowed at any chat age. After a not-ready observation or confirmed submission rejection, do not start another inspection or retry submission when either bound has expired. Wait up to 250 ms between inspections, shortened only by the remaining budget.

```mermaid
flowchart TD
    I[Inspect original pane] --> R{Known agent status?}
    R -->|idle, working or done| S[Validate custody, then submit once]
    R -->|Alive unknown outside startup| S
    R -->|blocked| B[Return agent_blocked]
    R -->|Absent, or unknown during startup| W{Startup time remains?}
    R -->|Inspection error| F[Return precise failure]
    W -->|Yes| D[Bounded wait]
    D --> I
    W -->|No| N[Return actionable not-ready result]
```

During startup, an alive agent with Herdr status `idle`, `working` or `done` is ready; an absent agent or unknown/missing/unrecognized status may wait only within the original window. `blocked` returns `agent_blocked` immediately at any age. A `working` agent does not wait for its turn to finish. Expiry after waiting returns `chat_still_starting`; a first confirmed absence outside the window returns `agent_not_found`. Outside startup, preserve existing delivery to an alive agent even when its status is unknown, missing or unrecognized. Other inspection failures return their actual code immediately and are never proof of readiness.

Immediately before each transport attempt, await optional `ports.beforeSubmit()`. It returns true only after its caller has validated the original target and durably recorded submission intent; false returns `{ok:false,code:"chat_target_changed"}` without transport. Callback failure must also send nothing. Invoke it again before an allowed retry after a confirmed rejection; never call it merely for an inspection. The runner owns the callback's journal and target policy.

Send `herdr agent prompt <pane> <text>` as its single ordered paste-and-Enter submission. This generic transport preserves its supplied text, including gate-message line breaks; user-input normalization belongs only to `changeRun`. Do not add separate terminal key/paste calls, arbitrary paste delays or `--wait`. Herdr acknowledgement proves submission, not that the agent acted on it.

A submission rejected with `agent_not_found` may return to readiness inspection only within the same bounds. A confirmed `agent_blocked` returns that code. Never retry any potentially dispatched submission automatically: return its actual code and `uncertain:true`. No readiness path starts, resumes, replaces, focuses or closes an agent, tab or server, or changes its saved identity.

## Dependencies

- [Herdr layout](workflow-herdr-layout.prompt.md): required authoring/generation/verification context for workspace ownership, allocation and its existing lock. The runner's replacement protocol is the caller contract above, not a recursively loaded dependency.
- Native `herdr`, `now`, `elapsedNow` and `sleep` ports supply transport, wall time, monotonic elapsed time and delay; optional `beforeSubmit` supplies the caller-owned durable precondition. The scoped Interpreter entry describes the real module function's JSON-visible arguments/results; it does not bind native Herdr, clock, terminal or session effects. Native stub and private-Herdr tests must establish readiness and submission behavior.
