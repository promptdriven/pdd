# Standalone saved cases from the Try page

`src/agent-saved-case.mjs` owns import of a person's explicit Try-page Save as test into a separate scenario. Export pure `agentSavedCaseFingerprint(saved)`, pure `agentSavedCasePath({story,name,id})`, pure `serializeAgentScenario(value)`, read-only `planAgentSavedCase({root,saved,receipt=null,storyTextOverride})`, and synchronous `importAgentSavedCase({root,saved,receipt=null})`. serializeAgentScenario validates bounded finite JSON and returns pretty UTF-8 JSON text with a final newline while preserving negative zero. The importer returns `{status,result,path?,receipt?,rules?}` with status added/already_added/needs_rule/refused. It never changes a Story, appends to an existing scenario, calls the runtime, approves a criterion or saves an unsaved chat suggestion. The caller alone classifies explicit page saves and persists receipts; CLI save-last keeps its separate legacy importer.

## Identity and canonical criterion scope

Require saved.id to be a nonempty trimmed string of at most 128 characters and 256 UTF-8 bytes without controls. saved.name is optional, at most 200 characters and without controls. Resolve Story from saved.story_path or test.story_path, requiring both to agree when present. A Story is a canonical repository-relative Git-visible Markdown file, not a symlink or secret-looking path, with a numbered acceptance list. Reject duplicate authored criterion texts as ambiguous.

The fingerprint validates identity and finite JSON, then hashes UTF-8 serializeAgentScenario({id:saved.id,name:saved.name??null,story_path:saved.story_path??saved.test.story_path,test:saved.test}) with full lowercase SHA-256 hex. It preserves negative zero and binds a queued payload to its approved journal, without filesystem reads or writes.

The path planner returns `tests/<story>-<case>-<hash>.json`. story is the basename without .md; case is name or saved-case. Each slug uses NFKD, removes combining marks, changes non-ASCII-alphanumerics to hyphens, trims hyphens, lowercases, and keeps at most 64 characters (fallback story/saved-case). hash is the first 10 lowercase hex characters of SHA-256 of the exact UTF-8 saved.id. The planner throws a plain validation error for malformed inputs; never use server paths or original_path to choose a destination. All output names fit a normal filesystem component.

Validate a structurally supported finite JSON-native scenario of at most 1 MiB with exact schema_version prompt-runtime.program-scenario.v1, nonempty valid criteria, object initial_world, and nonempty steps with unique nonempty step IDs, object inputs and nonempty checks. Checks use native criterion_id/target/path/op and optional value/json_path/html/measure keys, supported result/world/calls/error targets and native operators, valid JSON pointers, and required comparison values. Full prompt/schema/path admission remains the check engine’s responsibility. Reject unsupported root/step properties, duplicate source criterion IDs, missing referenced criteria and nonempty check_exemptions. Keep all accepted source fields and data exactly, including initial_world, simulation, context, step order, input, expected_error and check expected values; only Story/criteria/scope and check criterion IDs are remapped. Do not scrub or infer expected answers. No partial validation creates directories or files.

For every checked source criterion, match its text exactly to the current Story's canonical parsed criteria. Output only the checked criteria as `{id:'ac-N',text}` in Story order and set criteria_scope to those same IDs in that order. Remap every check's criterion_id. Unchecked source criteria are not output scope. Unknown checked text returns needs_rule with rules [{text,source_text,source_id}]: text is a bounded single sentence for the person's future confirmation, source_text preserves its original meaning for the caller. No unknown criterion is added automatically and no file/directory is written on needs_rule.

The planner validates the safe current Story first, then optionally uses a trusted future Story string (at most 64 KiB) solely for canonical criterion mapping. It returns status planned plus `{repo,path,text,receipt,story_path,sourceHash,storyHash}`; sourceHash hashes the exact current Story bytes, and storyHash hashes the UTF-8 chosen future/current text. It never creates directories or writes. B10's separately authorized transaction may stage these bytes after checking sourceHash. The ordinary importer does not accept a Story override. Existing identical files may return already_added; all refusal/needs_rule outcomes remain read-only.

## Exclusive import and recovery

Only write inside a real tests directory under the canonical root. Refuse symlink ancestors, final symlinks, nonregular files, paths outside the root and changing Story text. Verify the Story and directory identities before creation and after writing. Create directories only after full scenario/criterion validation. Create the target exclusively with no-follow and nonblocking flags; never overwrite, rename over, append to, or choose another file on a collision. Write bounded complete UTF-8 JSON, flush it, then return an added result and receipt `{case_id,repo,path,sha256}` over the exact output bytes. Preserve negative zero when serializing finite JSON data.

Prefer file creation relative to an opened, verified directory descriptor using /proc/self/fd or /dev/fd where supported. For portable Node platforms lacking directory-descriptor child paths, use guarded exclusive path creation with O_NOFOLLOW, verifying identities immediately before opening, after opening before writing any content, and after writing. This portable fallback cannot make ancestor renames atomic against an adversarial concurrent process; it detects drift and removes only this invocation's created inode. It never intentionally follows a known symlink or overwrites an existing file. Surface this race limitation honestly in review; do not claim openat-style guarantees on all platforms.

An existing regular target is already_added only when its exact bytes equal the newly derived document; otherwise refuse without writes. A supplied receipt must match case_id, canonical repo, derived path and expected digest; a stale, forged or changed-case receipt refuses instead of selecting another destination. A receipt pointing to a missing/edited file refuses. Without a receipt, deterministic filename plus identical bytes permits recovery after successful creation but lost receipt persistence. Changed/missing/unsafe files never produce a false success. Cleanup after a failed create/write removes only an inode created by this invocation; preserve unrelated files. Results use plain fixed guidance and safe generated paths, never raw payload values or exception details.

## Dependencies

- [Preflight](runtime-preflight.prompt.md): isSecretPath and storyCriteria own privacy exclusions and native-compatible Story parsing; TEST_SCHEMA names the scenario version. The parent integrates native criteria_scope admission separately.
- Native prompt-runtime program_scenario.scoped_story_criteria defines canonical ordered ac-N slices; it compares output criteria exactly to the selected authored Story criteria.
- Node filesystem/path/crypto/child_process built-ins provide bounded reads, Git visibility, identity, exclusive writes and SHA-256. No external package, subprocess other than Git listing, provider or runtime is needed.
