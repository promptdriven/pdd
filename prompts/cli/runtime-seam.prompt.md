# PDD to Runtime seam

Own `src/runtime-seam.mjs` and the stable launcher entry `src/try-doors.mjs`. `src/runtime-seam.mjs` is the sole module in pdd outside `src/runtime/` permitted to import `src/runtime/`, and it is the compatible entry for pdd code and tests: while direct `src/runtime/` functions require their ports, `src/runtime-seam.mjs` fills every host port with pdd's behavior. Every pdd module in `src/`, `bin/`, and `scripts/` accesses Runtime commands, local format and workspace readers, check-plan and outcome helpers, and constants exclusively through `./runtime-seam.mjs`.

The seam keeps stable pdd-owned file paths for anything pdd writes into a user's files or passes to a child process:

- `src/try-doors.mjs` re-exports `runShim` from `./runtime-seam.mjs` so `.pdd/try/bin/<program>` launchers keep a stable pdd-owned module path across upgrades and package extraction.
- `runTry(input, ports)` in `src/runtime-seam.mjs` defaults `ports.tryLauncherUrl` to the `file:` URL of `src/try-doors.mjs` before delegating to the Runtime package entry, preserving an explicit `ports.tryLauncherUrl` when provided.

## Request metadata and host ports

Because `src/runtime/` imports nothing outside `src/runtime/`, `src/runtime-seam.mjs` builds caller request metadata and host ports lazily on invocation. Legacy and canonical port spellings (`readEvidenceEligibility` and `evidenceEligibility`; `rememberSecrets` / `redactSecrets` and `redaction`; `agents.{loadDefinitions,list,ask}` and `{loadAgentDefinitions,discoverAgents,askAgent}`) are normalized before installing seam defaults so an explicit caller override under either name wins, and every seam default uses nullish fallback (`??`) so an own `undefined` property never erases a default. A single shared host `redaction` port (`{ remember, redact, known }`) backed by the host secret-redaction module keeps host and Runtime redaction on one registry:

- `runJobs(input, ports)`: loads the host client companion graph (the host product module and the host command catalog) inside the guarded call and supplies `client.commands` (`{ test, lint, simulate }`) from the host command catalog (`NAMES`).
- `buildCheckPlan(input, ports)`: supplies `ports.headerPrompts` from the host file-owner module.
- `composeProductTry(input, ports)` and `selectJourneys(tests, selector, ports)`: supply `ports.parseProductDocuments` and `ports.parseProductWorldWriters` synchronously from the host product-documents module (the pure parser leaf re-exported by the host product module) and `ports.selectTests` from the host test-selection module.
- `findTests(input, ports)`, `captureSource(root, options, ports)`, `createStrictSourceAccess(root, workspace, ports)`, `selectTests(found, words, options)`, `whyNoTests(root, visible, found, ports)`, and `readAgentScenarios(input, ports)`: supply `{isStoryPath, hasAcceptance, expectedTestPath, matchTests, orphanSummary, selectTests, whyNoTests, NO_TESTS}` from the host test-selection module, binding preflight's `captureSource`, `findTests`, `allowsRuntimePath`, and `interfaceBlocks` onto `selectTests` and `whyNoTests`.
- `outcomeExitCode(outcomes, options, ports)` and `exitCodeFor(outcomes, options, ports)`: supply `ports.outcomeOverall` from Runtime outcome into the host exit-code module; `summaryLine`, `storyLines`, `renderJson`, and `renderText` supply `ports.promptTestsLabel` (`PROMPT_TESTS_LABEL`) from the host PR-word module.
- `createTryGuide(options)`: supplies `ports.redaction` from the host secret-redaction module, `ports.evidenceEligibility` synchronously from the host workflow-eligibility module (`readEvidenceEligibility`, re-exported by the workflow runner), and selection ports from the host test-selection module.
- `buildProjectCard(input)`: supplies `evidenceEligibility` (`readEvidenceEligibility`) synchronously from the host workflow-eligibility module when omitted.
- `runCheck(input, ports)`: loads all check port-provider and host companion modules (the host secret-redaction module, the host file-owner module, the workflow runner, workflow-runs, workflow-results, the SVG layout module, the screen-comparison module, the host product module) unconditionally when invoked and supplies on every call: `client.version` from the host package manifest when omitted (direct `src/runtime/` callers without `client.version` or `ports.clientVersion` get `null`, never a hardcoded literal), a lazy `ports.workflowBaseSha({ root, env })` callback backed by `ports.allRuns` / workflow-runs (`allRuns`) evaluated inside `runBatch` at check-plan time (preserving an explicit `input.workflow` only when supplied by the caller), `ports.headerPrompts` from the host file-owner module, `ports.redaction` from the host secret-redaction module, `ports.evidenceEligibility` from the workflow runner (`readEvidenceEligibility`), `ports.allRuns`, `ports.assessNativeEvidence`, `ports.usableResult`, and `ports.resultLines` from workflow-runs and workflow-results, `ports.lintSvgLayouts` from the SVG layout module, and `ports.compareScreen` and `ports.formatScreenComparison` from the screen-comparison module.
- `askAgent(input, ports)`: delegates to Runtime's `askAgent`, lazily loading `runAgentProcess` from the host agent-adapters module when `input.run` (`ports.run` / `ports.runAgentProcess` / `ports.agents?.run`) is omitted.
- `runTry(input, ports)`: supplies `ports.tryLauncherUrl`, `ports.redaction` from the host secret-redaction module, `ports.loadAgentDefinitions` from the host agent-config module, `ports.agentBridge` delegating to `createAgentBridge` (so the host agent-adapters module loads when the agent bridge opens, before `"Connecting your agent to the Try page…"` and `GET /model`, while preserving an explicit `ports.agentBridge` including `false`), fallback `ports.discoverAgents` from the host agent-adapters module and `ports.askAgent` backed by seam `askAgent`, `ports.evidenceEligibility` from the workflow runner, `ports.parseProductDocuments` and `ports.parseProductWorldWriters` from the host product module, and `ports.askApproval`, `ports.lineReader`, and `ports.promptPath` from the host prompt-approval module.
- `createAgentBridge(context, test, tryId, options, link, seamPorts)`: loads the host agent-adapters module (`discoverAgents`, `runAgentProcess`) before network access and supplies default `redaction`, `loadAgentDefinitions`, `discoverAgents`, `runAgentProcess` (`agents.run`), `askAgent`, and `guidePorts.evidenceEligibility` without cloning `context`.
- `readTryOwner(input, ports)`, `createTryTools(input, ports)`, and `runMcp(input, ports)`: supply `ports.tryLauncherUrl` (`runMcp` also supplies `ports.clientVersion` from the host package manifest), `ports.redaction` from the host secret-redaction module, `ports.evidenceEligibility` (the workflow runner via `await import()` in async entries and the host workflow-eligibility module in synchronous `createTryTools`), and `ports.parseProductDocuments` and `ports.parseProductWorldWriters` (the host product module via `await import()` in async entries and the host product-documents module in synchronous `createTryTools`) so MCP owner tools and Try reopening support whole-product simulations without passing top-level-`await` ESM graphs to `createRequire`.
- `openCli(context, test, sessionId, options)`, `openServe(context, test, sessionId, options)`, `runShim(descriptorPath, argv, ports)`, `saveLast(input)`, and `runDoorCall(descriptor, input, ports)`: `openCli` supplies `context.ports.tryLauncherUrl` and selection ports when `context` is present; `openServe` supplies selection ports on `context.ports` when `context` is present; `runShim` loads the host client companion graph (the host product module, the host secret-redaction module, the host prompt-approval module) and supplies `ports.redaction`, `ports.lineReader`, and selection ports; `saveLast` supplies `ports.lineReader` and selection ports; `runDoorCall` supplies `ports.redaction` and selection ports.
- `readContractHistory(input, ports)` and `runContracts(input, ports)`: supply `ports.evidenceEligibility` synchronously from the host workflow-eligibility module (`readEvidenceEligibility`) and selection ports from the host test-selection module; `runContracts` also loads `runtimeClientSlice()`, while async CLI dispatch loads the host product module and the workflow runner via `await import()` inside its error guard so `pdd contracts` preserves its client companion module set and load-failure handling without `createRequire` on top-level-`await` graphs.
- `migrateRuntimeWorkspace(input, ports)`: supplies `ports.evidenceEligibility` from the workflow runner (`readEvidenceEligibility`) and selection ports from the host test-selection module.
- `saveDoorCaseResult(root, saved, options)`, `saveDoorCase(root, saved, options)`, `acquireCaseWriteOwnership(input, ports)`, `applyPendingCase(input, ports)`, `applyPendingCaseWithHandoff(input, ports)`, `savedStoryEvidence(input, ports)`, `createSavedStoryEvidenceReader(ports)`, and `runtimeWorkspaceMigrationStore(input, given)`: supply selection ports from the host test-selection module.
- `runInterfaceDraft(input, ports)` and `draftInterfaces(input, ports)`: supply selection ports from the host test-selection module.
- `runAutomaticApproval(input, ports)`: loads its approval-policy and check companion providers in base order (the host approval-policy module, the host prompt-approval module, the host product module, the host secret-redaction module, the host file-owner module, the workflow runner, workflow-runs, workflow-results, the host agent-config module, the SVG layout module, the screen-comparison module) and invokes Runtime's `runAutomaticApproval` inside an outer `try/catch` error boundary that writes `${error.message || 'Approval failed.'}\n` to `ports.stderr ?? process.stderr` and resolves to `4` on any load or setup failure before Runtime's own guard. Supplies `readApprovalPolicy`, `approvalActor`, `readPromptApprovals`, and `recordPromptApproval` from the host approval-policy module, `approvePromptText` and `promptPath` from the host prompt-approval module, and seam check ports (`client`, `headerPrompts`, lazy `workflowBaseSha`, `allRuns`, `assessNativeEvidence`, `usableResult`, `resultLines`, `redaction`, `evidenceEligibility`, `lintSvgLayouts`, `compareScreen`, `formatScreenComparison`, selection ports, exit-code ports, and `promptTestsLabel`), preserving an explicit `workflow` only when supplied by the caller.
- `checkRuntimeHealth(input, ports)`, `health(input, ports)`, `loadRuntimeClient()`, `runtimeOrigin(env)`, and `runtimeClientSlice()`: `checkRuntimeHealth`, `health`, and `loadRuntimeClient` supply `ports.redaction` from the host secret-redaction module; `runtimeOrigin` delegates synchronously to the Runtime package entry; `runtimeClientSlice()` loads Runtime client synchronously via the Runtime package entry and overlays the seam-bound `acquireCaseWriteOwnership`, `applyPendingCase`, `applyPendingCaseWithHandoff`, `checkRuntimeHealth`, `createSavedStoryEvidenceReader`, `health`, `readContractHistory`, `runtimeOrigin`, `runtimeWorkspaceMigrationStore`, `saveDoorCase`, `saveDoorCaseResult`, and `savedStoryEvidence` bindings without importing host modules from the seam at module-evaluation time.
- Package API commands and port-consuming readers (`check`, `lint`, `read`, `retry`, `local`, `simulate`, `jobs`, `health`, `mcp`, `draftInterfaces`, `contracts`, `source.identity`, `saved.results`, and `render`): defined on `src/runtime-seam.mjs` over the seam's own host-port-injecting wrappers (`runCheck`, `runTry`, `runJobs`, `checkRuntimeHealth`, `runMcp`, `runInterfaceDraft`, `runContracts`, `captureSource`, `savedStoryEvidence`, `renderText`, `renderJson`, `storyLines`, `summaryLine`)—never re-exported raw from the Runtime package entry—so every new API name carries identical `client.version`, `client.commands`, `workflowBaseSha`, `redaction`, `headerPrompts`, `evidenceEligibility`, native Story assessment, SVG layout, screen comparison, selection, exit-code, and `promptTestsLabel` ports. Pure stateless readers and metadata (`exactValue`, `format`, `workspace`, `version`, `causeText`, `cleanText`) re-export directly from the Runtime package entry.

Also forward selection ports (`isStoryPath`, `hasAcceptance`, `expectedTestPath`, `matchTests`, `orphanSummary`, `selectTests`, `whyNoTests`, `NO_TESTS`), exit-code ports (`exitFor`, `exitCodeFor`), and `promptTestsLabel` (`PROMPT_TESTS_LABEL`) lazily on call from the host test-selection module, the host exit-code module, and the host PR-word module into `runCheck`, `runTry`, `runAutomaticApproval`, `createAgentBridge`, `readTryOwner`, `createTryTools`, `runMcp`, `runContracts`, `migrateRuntimeWorkspace`, `saveLast`, `openCli`, `openServe`, `runShim`, `runDoorCall`, `saveDoorCaseResult`, `saveDoorCase`, `acquireCaseWriteOwnership`, `applyPendingCase`, `applyPendingCaseWithHandoff`, `savedStoryEvidence`, `createSavedStoryEvidenceReader`, and the scoped slice loaders (`runtimePreflightSlice`, `runtimeOutcomeSlice`, `runtimeOutputSlice`), while exposing pure constants (`NO_TESTS`, `STATE_EXIT_CODES`, `COMMAND_EXIT_CODE`, `PROMPT_TESTS_LABEL`, `PROMPT_TESTS_WORDS`) directly so evaluating `src/runtime-seam.mjs` loads zero extra pdd or Runtime modules.
