# PDD to Runtime seam

Own `src/runtime-seam.mjs` and the stable launcher entry `src/try-doors.mjs`. `src/runtime-seam.mjs` is the sole module in pdd permitted to import `@promptdriven/runtime-client`, and it is the compatible entry for pdd code and tests: while direct `@promptdriven/runtime-client` functions require their ports, `src/runtime-seam.mjs` fills every host port with pdd's behavior. Every pdd module in `src/`, `bin/`, and `scripts/` accesses Runtime commands, local format and workspace readers, check-plan and outcome helpers, and constants exclusively through `./runtime-seam.mjs`.

| Seam Layer | Exports | Responsibility |
| :--- | :--- | :--- |
| Discovery & source capture | `findTests`, `preflight`, `captureSource`, `createStrictSourceAccess`, `selectTests`, `whyNoTests` | Bind host selection ports, compile Short JSON and omitted-`criteria` scenarios on pass 1 without injecting unselected sibling tests into `captured.files`, and reconcile `dirty_files` |
| Commands & local lint modes | `runCheck`, `check`, `lint`, `read`, `retry`, `local`, `runProgram`, `run`, `reconcileCheckReceipt`, `reconcileCheckBatch`, `reconcileStaleReservations`, `projectCheckReconciliation`, `runContracts`, `contracts`, `runJobs`, `jobs` | Inject host workflow/evidence/lint/screen ports, forward `--fresh`, `--batch-timeout`, and `--read --details`, support `--affected --files` offline dry-run, `--retry-unresolved BATCH` (reconcile + re-run all non-passed scenarios), bounded fail-open auto-reconciliation of stale prior reservations before dispatching new checks (zero work on clean runs), explicit single-scenario `.json` sibling-criteria handling, handle `--reconcile` (read-only CHECK request UUID receipt or saved batch reservation reconciliation) and `--reconcile-stale`, size shallow prompt graph `--max-calls`, handle local `--emit-v1` and `--bind-criteria`, and rewrite legacy-ID mismatch diagnostics |
| Prompt Interpreter & case persistence | `runTry`, `simulate`, `openCli`, `openServe`, `runShim`, `saveLast`, `saveDoorCaseResult`, `applyPendingCase` | Supply stable `try-doors.mjs` launcher URL, forward `--fresh`, agent bridges, compatibility Try approval stubs, and repository-bounded Short JSON compilation for Prompt Interpreter sessions and saved cases |
| Rendering, health & slices | `render`, `renderText`, `renderJson`, `summaryLine`, `storyLines`, `health`, `runtime*Slice` | Bind `PROMPT_TESTS_LABEL`, secret redaction, and lazy slice loaders with zero eager host imports at module load |

The seam keeps stable pdd-owned file paths for anything pdd writes into a user's files or passes to a child process:

- `src/try-doors.mjs` re-exports `runShim` from `./runtime-seam.mjs` so `.pdd/try/bin/<program>` launchers keep a stable pdd-owned module path across upgrades and package extraction.
- `runTry(input, ports)` in `src/runtime-seam.mjs` defaults `ports.tryLauncherUrl` to the `file:` URL of `src/try-doors.mjs` before delegating to the Runtime package entry, preserving an explicit `ports.tryLauncherUrl` when provided.

## Request metadata and host ports

Because `@promptdriven/runtime-client` imports no host modules, `src/runtime-seam.mjs` builds caller request metadata and host ports lazily on invocation. Legacy and canonical port spellings (`readEvidenceEligibility` and `evidenceEligibility`; `rememberSecrets` / `redactSecrets` and `redaction`; `agents.{loadDefinitions,list,ask}` and `{loadAgentDefinitions,discoverAgents,askAgent}`) are normalized before installing seam defaults so an explicit caller override under either name wins, and every seam default uses nullish fallback (`??`) so an own `undefined` property never erases a default. A single shared host `redaction` port (`{ remember, redact, known }`) backed by the host secret-redaction module keeps host and Runtime redaction on one registry:

- `runJobs(input, ports)`: loads the host command catalog inside the guarded call and supplies `client.commands` (`[NAMES.test, NAMES.lint, NAMES.run]`) from the host command catalog (`NAMES`).

- `composeProductTry(input, ports)` and `selectJourneys(tests, selector, ports)`: supply `ports.parseProductDocuments` and `ports.parseProductWorldWriters` synchronously from the host product-documents module (the pure parser leaf re-exported by the host product module) and `ports.selectTests` from the host test-selection module, compiling Short JSON scenario documents in `composeProductTry` inputs before composition.
- `findTests(input, ports)`, `preflight(input)`, `captureSource(root, options, ports)`, `createStrictSourceAccess(root, workspace, ports)`, `selectTests(found, words, options)`, `whyNoTests(root, visible, found, ports)`, and `readAgentScenarios(input, ports)`: supply `{isStoryPath, hasAcceptance, expectedTestPath, matchTests, orphanSummary, selectTests, whyNoTests, NO_TESTS}` from the host test-selection module, binding preflight's `captureSource`, `findTests`, and `allowsRuntimePath` onto `selectTests` and `whyNoTests`, and compile Short JSON scenarios and omitted-`criteria` `prompt-runtime.program-scenario.v1` scenarios deterministically on the first pass via the host Short scenario compiler (`findTests` and `createStrictSourceAccess` compile discovered scenarios and strict source reads; `preflight`, `runCheck`, `runTry`, `readContractHistory`, and `runContracts` supply compiled `v1` text to internal preflight/contract reads with symlink-resolved path lookup, preserving each Short JSON scenario's raw authored line count on disk during preflight and lint complexity checks—including actual `pdd lint`, `pdd lint --local`, and `pdd test` CLI runs—so `oversized Story` warnings count raw authored lines rather than expanded `compiledText` lines: emitting no line-limit warning when raw authored lines are `<= 1000`, warning exactly once with the real raw authored line count when raw authored lines exceed `1000` (citing the `pdd` skill reference guides `stories.md` and `verification.md` or `pdd help prompting`, not repo-relative `skills/pdd/references/` paths), including explicit `pdd.scenario.short.v1` files scoped to the active lint selection or `lintLocalHygiene` `tests` filter without duplicating `pdd test` preflight warnings or leaking unselected tests on `--affected`/`--lf`/`--journeys`, and keeping regular `program-scenario.v1` files and `captureSource` pretty-printed compilation unchanged; `captureSource` compiles selected scenarios via `prepareSource` while serving unselected sibling Story footprint reads through a scoped snapshot overlay so unselected sibling tests never enter `captured.files`, and reconciles `dirty_files` and `source_dirty` against authored Git HEAD blobs; standard `program-scenario.v1` files that declare explicit `criteria` pass through unchanged without rewriting explicit criterion IDs in memory).
- `outcomeExitCode(outcomes, options, ports)` and `exitCodeFor(outcomes, options, ports)`: supply `ports.outcomeOverall` from Runtime outcome into the host exit-code module; `summaryLine`, `storyLines`, `renderJson`, `renderText`, and `refusalView` supply `ports.promptTestsLabel` (`PROMPT_TESTS_LABEL`) from the host PR-word module and append an actionable `result_value_pointer` / `result_schema` hint when `impossible-result-value-pointer` lacks one.
- `createTryGuide(options)`: supplies `ports.redaction` from the host secret-redaction module, `ports.evidenceEligibility` synchronously from the host workflow-eligibility module (`readEvidenceEligibility`, re-exported by the workflow runner), and selection ports from the host test-selection module.
- `buildProjectCard(input)`: supplies `evidenceEligibility` (`readEvidenceEligibility`) synchronously from the host workflow-eligibility module when omitted.
- `runCheck(input, ports)`: rejects `--write` without `--emit-v1` with exit `2`, handles local `--emit-v1` and `--bind-criteria` offline (`0` AI or network calls), `--reconcile` (UUID receipt or local batch ID), and `--reconcile-stale` before loading check providers, computes a graph-aware default `--max-calls` ceiling when `--max-calls` is omitted on multi-step check runs, normalizes hosted `story-criterion-mismatch` refusal diagnostics for matching legacy criterion IDs, lazily loads `screen-compare.mjs` only when `--screen` is requested, lazily loads `workflow-results.mjs` only when `--lint` targets explicit words, lazily binds `workflow-eligibility.mjs` and `workflow-runs.mjs` on demand, and loads `svg-layout.mjs` and `repo-hygiene-lint.mjs` only on lint/check paths (never `--read`/`--retry`/`--reconcile-stale`/`--request`/`--explain-bindings`/`--screen`). Supplies `client.version` from the host package manifest when omitted, `workflowBaseSha`, `headerPrompts`, explicit `resolveOwners` (binding `promptClaims: () => []` by default in `runCheck` and `runtimePreflightSlice().lintLocalHygiene` so prose mentions never cause ownership noise or extra scan candidates), `redaction`, `evidenceEligibility`, `allRuns`, `lintSvgLayouts` (combining SVG layout, `lintRepoProject` with `onProjectLintResult` on unfiltered repo-wide scans only, and Short JSON scenario lint), optional `compareScreen`/`formatScreenComparison`, and 429/5xx/`Retry-After` backoff flooring without setting `pollMs` (preserving `@promptdriven/runtime-client`'s native SSE, `Prefer: wait`, and adaptive polling).

- `readTryOwner(input, ports)`, `createTryTools(input, ports)`, and `runMcp(input, ports)`: supply `tryLauncherUrl` (`runMcp` also supplies `clientVersion`), `redaction`, lazy `evidenceEligibility`, `parseProductDocuments`, `parseProductWorldWriters`, and Short JSON `saveDoorCase` + `applyPendingCaseWithHandoff` without wrapping MCP JSON-RPC `stdout` in hint normalization or eagerly loading `workflow-eligibility.mjs`.

- `checkRuntimeHealth(input, ports)`, `health(input, ports)`, `loadRuntimeClient()`, `runtimeOrigin(env)`, and `runtimeClientSlice()`: `checkRuntimeHealth`, `health`, and `loadRuntimeClient` supply `ports.redaction` from the host secret-redaction module; `runtimeOrigin` delegates synchronously to the Runtime package entry; `runtimeClientSlice()` loads Runtime client synchronously via the Runtime package entry and overlays the seam-bound `acquireCaseWriteOwnership`, `applyPendingCase`, `applyPendingCaseWithHandoff`, `checkRuntimeHealth`, `createSavedStoryEvidenceReader`, `health`, `readContractHistory`, `reconcileCheckBatch`, `reconcileCheckReceipt`, `reconcileStaleReservations`, `runtimeOrigin`, `runtimeWorkspaceMigrationStore`, `saveDoorCase`, `saveDoorCaseResult`, and `savedStoryEvidence` bindings without importing host modules from the seam at module-evaluation time.

- `--affected --files`, `--retry-unresolved`, auto-reconcile stale reservations, and single-scenario targeting (delegating pure decisions to [Test ergonomics](test-ergonomics.prompt.md)):
  - On `runCheck`: evaluate `planTestErgonomicsOptions({ words, options })` before check providers or authentication. Reject invalid mixes with exit `2`, zero state writes, zero auth, and zero network calls.
  - When `mode === 'affected-files'`: resolve the repository Git root, discover tests (`excludeFixtureProjects: true`), compute `buildCheckPlan({ ..., full: true, base, affected: true, allowMissingInterfaces: true })` and `selectCheckTests(plan, { affected: true })`, and run `--files` strictly on the selected affected test paths with `0` AI calls, `0` network calls, `0` auth calls, and `0` state writes (`--json` augments `--files` JSON with `affected: true`, `ai_calls: 0`, `check_selection`, `check_plan`, `affected_stories`, and `omitted_stories`; text prints the affected selection summary before the file manifest).
  - When `mode === 'retry-unresolved'`: validate the saved batch under `PDD_STATE_DIR` (or `~/.pdd/runtime`) belongs to this repository and has Check intent, reconcile expired/unresolved reservations for that batch (and any stale prior repo reservations) with bounded fail-open timeout, re-read saved rows and local terminal receipts, classify via `selectUnresolvedBatchTests` (skipping confirmed `passed` rows and selecting all `partial`, `unknown`, `not_run`, `failed`, `refused`, and open rows), return exit `0` with `0` AI calls when every row already passed, otherwise dispatch a fresh check batch for ONLY `retry_tests` with `forwarded_options` (attaching `retried_from`, `skipped_passed_tests`, and `reconciled_batch` in `--json` mode).
  - Before dispatching any new check batch in `runCheck`, perform a fast local scan of `<stateDir>/batches/` for unresolved prior reservations belonging to this repository and consult `planAutoReconcile`. When `should_reconcile` is `false` (non-dispatch mode or `0` stale entries), perform zero reconciliation calls and add zero delay. When `should_reconcile` is `true`, invoke `reconcileStaleReservations` under a bounded `timeout_ms` abort timer (default `10000` ms, overridable via `ports.autoReconcileTimeoutMs` or `PDD_AUTO_RECONCILE_TIMEOUT_MS`); fail open with a stderr warning on timeout or error so new check runs are never blocked, and print one concise stderr line when reservations are cleared.
  - When explicit `.json` scenario path(s) are targeted on a split Story (`classifyTargetedScenarioCriteria` confirms `can_pass_as_targeted_slice` for every targeted scenario whose checks all passed), upgrade only those sibling-covered `criteria-not-checked` rows to `passed` (`targeted_scenario: true`, `sibling_covered_criteria`) and recompute exit code (`0` when all targeted scenarios passed) without modifying `.pdd/cache/test/stories.json` or relaxing single-file Story completeness.
- `--fresh`, `--reconcile`, and `--reconcile-stale` handling:
  - On `runCheck`: intercept `--reconcile` and `--reconcile-stale` before any `POST /v1/lint` or `POST /v1/check`. For `--reconcile`, validate string canonical UUID or local batch ID (`YYYYMMDD-HHMMSS-xxxx`), invoke `reconcileCheckReceipt` read-only for UUIDs (returning `0` when `available === true`, `3` otherwise, or explicit `exitCode` `2`/`5`) or `reconcileCheckBatch` for batch IDs (returning `0` when `remaining_unresolved_count === 0`, `3` otherwise, or explicit `exitCode` `2`/`5`). For `--reconcile-stale`, validate flag-only usage with no extra options or Stories, invoke `reconcileStaleReservations`, and return `0` when `remaining_unresolved_count === 0`, `3` otherwise, or explicit `exitCode` `2`/`5`. Validate `--fresh` (rejecting `--reconcile-stale` alongside other incompatible check flags) and bypass local pass cache reuse while attaching `fresh: true` on `POST /v1/check`.
  - On `runTry`: validate `--fresh` and refuse `--fresh` without `--new` with exit `2` when a saved Story/whole-project/product Try is already open; delegate `--fresh` payload forwarding and door descriptor persistence directly to `@promptdriven/runtime-client`.
- CHECK reconciliation helpers (`reconcileCheckReceipt(input, ports)`, `reconcileCheckBatch(input, ports)`, `reconcileStaleReservations(input, ports)`, and `projectCheckReconciliation(input, ports)`): delegate directly to `@promptdriven/runtime-client` (or caller-injected override ports on `ports`), validating string canonical UUID input on `reconcileCheckReceipt` (`{ code: 'invalid-request-id', exitCode: 2 }`) and string batch ID input on `reconcileCheckBatch` (`{ code: 'invalid-batch-id', exitCode: 2 }`) before auth/network and binding `seamRuntimePorts` with shared host `redaction`.

Also forward selection ports (`isStoryPath`, `hasAcceptance`, `expectedTestPath`, `matchTests`, `orphanSummary`, `selectTests`, `whyNoTests`, `NO_TESTS`), exit-code ports (`exitFor`, `exitCodeFor`), and `promptTestsLabel` (`PROMPT_TESTS_LABEL`) lazily on call from the host test-selection module, the host exit-code module, and the host PR-word module into `runCheck`, `runTry`, `createAgentBridge`, `readTryOwner`, `createTryTools`, `runMcp`, `runContracts`, `migrateRuntimeWorkspace`, `saveLast`, `openCli`, `openServe`, `runShim`, `runDoorCall`, `saveDoorCaseResult`, `saveDoorCase`, `acquireCaseWriteOwnership`, `applyPendingCase`, `applyPendingCaseWithHandoff`, `savedStoryEvidence`, `createSavedStoryEvidenceReader`, and the scoped slice loaders (`runtimePreflightSlice`, whose `lintLocalHygiene` also appends `lintRepoAntiPatterns` warnings for direct library callers, `runtimeOutcomeSlice`, `runtimeOutputSlice`), while exposing pure constants (`NO_TESTS`, `STATE_EXIT_CODES`, `COMMAND_EXIT_CODE`, `PROMPT_TESTS_LABEL`, `PROMPT_TESTS_WORDS`) directly so evaluating `src/runtime-seam.mjs` loads zero extra pdd or Runtime modules.
