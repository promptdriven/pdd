# PDD to Runtime seam

Own `src/runtime-seam.mjs` and the stable launcher entry `src/try-doors.mjs`. `src/runtime-seam.mjs` is the sole module in pdd permitted to import `@promptdriven/runtime-client`, and it is the compatible entry for pdd code and tests: while direct `@promptdriven/runtime-client` functions require their ports, `src/runtime-seam.mjs` fills every host port with pdd's behavior. Every pdd module in `src/`, `bin/`, and `scripts/` accesses Runtime commands, local format and workspace readers, check-plan and outcome helpers, and constants exclusively through `./runtime-seam.mjs`.

The seam keeps stable pdd-owned file paths for anything pdd writes into a user's files or passes to a child process:

- `src/try-doors.mjs` re-exports `runShim` from `./runtime-seam.mjs` so `.pdd/try/bin/<program>` launchers keep a stable pdd-owned module path across upgrades and package extraction.
- `runTry(input, ports)` in `src/runtime-seam.mjs` defaults `ports.tryLauncherUrl` to the `file:` URL of `src/try-doors.mjs` before delegating to the Runtime package entry, preserving an explicit `ports.tryLauncherUrl` when provided.

## Request metadata and host ports

Because `@promptdriven/runtime-client` imports no host modules, `src/runtime-seam.mjs` builds caller request metadata and host ports lazily on invocation. Legacy and canonical port spellings (`readEvidenceEligibility` and `evidenceEligibility`; `rememberSecrets` / `redactSecrets` and `redaction`; `agents.{loadDefinitions,list,ask}` and `{loadAgentDefinitions,discoverAgents,askAgent}`) are normalized before installing seam defaults so an explicit caller override under either name wins, and every seam default uses nullish fallback (`??`) so an own `undefined` property never erases a default. A single shared host `redaction` port (`{ remember, redact, known }`) backed by the host secret-redaction module keeps host and Runtime redaction on one registry:

- `runJobs(input, ports)`: loads the host command catalog inside the guarded call and supplies `client.commands` (`{ test, lint, simulate }`) from the host command catalog (`NAMES`).
- `buildCheckPlan(input, ports)`: supplies `ports.headerPrompts` from the host file-owner module.
- `composeProductTry(input, ports)` and `selectJourneys(tests, selector, ports)`: supply `ports.parseProductDocuments` and `ports.parseProductWorldWriters` synchronously from the host product-documents module (the pure parser leaf re-exported by the host product module) and `ports.selectTests` from the host test-selection module.
- `findTests(input, ports)`, `captureSource(root, options, ports)`, `createStrictSourceAccess(root, workspace, ports)`, `selectTests(found, words, options)`, `whyNoTests(root, visible, found, ports)`, and `readAgentScenarios(input, ports)`: supply `{isStoryPath, hasAcceptance, expectedTestPath, matchTests, orphanSummary, selectTests, whyNoTests, NO_TESTS}` from the host test-selection module, binding preflight's `captureSource`, `findTests`, and `allowsRuntimePath` onto `selectTests` and `whyNoTests`.
- `outcomeExitCode(outcomes, options, ports)` and `exitCodeFor(outcomes, options, ports)`: supply `ports.outcomeOverall` from Runtime outcome into the host exit-code module; `summaryLine`, `storyLines`, `renderJson`, `renderText`, and `refusalView` supply `ports.promptTestsLabel` (`PROMPT_TESTS_LABEL`) from the host PR-word module and append an actionable `result_value_pointer` / `result_schema` hint when `impossible-result-value-pointer` lacks one.
- `createTryGuide(options)`: supplies `ports.redaction` from the host secret-redaction module, `ports.evidenceEligibility` synchronously from the host workflow-eligibility module (`readEvidenceEligibility`, re-exported by the workflow runner), and selection ports from the host test-selection module.
- `buildProjectCard(input)`: supplies `evidenceEligibility` (`readEvidenceEligibility`) synchronously from the host workflow-eligibility module when omitted.
- `runCheck(input, ports)`: loads the check port-provider modules (the host secret-redaction module, the host file-owner module, the host workflow-eligibility module, workflow-runs, workflow-results, the SVG layout module, the repo-hygiene-lint module, the screen-comparison module) unconditionally when invoked and supplies on every call: `client.version` from the host package manifest when omitted (direct `@promptdriven/runtime-client` callers without `client.version` or `ports.clientVersion` get `null`, never a hardcoded literal), a lazy `ports.workflowBaseSha({ root, env })` callback backed by `ports.allRuns` / workflow-runs (`allRuns`, then `env.PDD_BASE_SHA`, then Git `merge-base` against `origin/HEAD`, `origin/main`, `origin/master`, `main`, or `master` when `HEAD` is not on `main` or `master`) evaluated inside `runBatch` at check-plan time (preserving an explicit `input.workflow` only when supplied by the caller), `ports.headerPrompts` from the host file-owner module, `ports.redaction` from the host secret-redaction module, `ports.evidenceEligibility` from the host workflow-eligibility module (`readEvidenceEligibility`), `ports.allRuns`, `ports.assessNativeEvidence`, `ports.usableResult`, and `ports.resultLines` from workflow-runs and workflow-results, default `ports.lintSvgLayouts` combining `lintSvgLayouts` from the SVG layout module with `lintRepoAntiPatterns` from the repo-hygiene-lint module (preserving an explicit `ports.lintSvgLayouts` override when supplied), and `ports.compareScreen` and `ports.formatScreenComparison` from the screen-comparison module. When `options['--affected']` is `true` without conflicting arguments or custom `ports.captureSource` / `ports.checkPlanPorts.git` hooks, the seam excludes unowned non-Story native test files (`isTestOwnedPath(path)` except `.json`) and unowned `.github/` automation files from implementation-ownership uncertainty and exits `0` locally (`0 affected Stories. 0 AI calls.`) with zero authentication or network calls whenever Git scope succeeds and zero Stories are affected without conservative uncertainty.
- `askAgent(input, ports)`: delegates to Runtime's `askAgent`, lazily loading `runAgentProcess` from the host agent-adapters module when `input.run` (`ports.run` / `ports.runAgentProcess` / `ports.agents?.run`) is omitted.
- `runTry(input, ports)`: supplies `ports.tryLauncherUrl`, `ports.redaction` from the host secret-redaction module, `ports.loadAgentDefinitions` from the host agent-config module, `ports.agentBridge` delegating to `createAgentBridge` (so the host agent-adapters module loads when the agent bridge opens, before `"Connecting your agent to the Try page…"` and `GET /model`, while preserving an explicit `ports.agentBridge` including `false`), fallback `ports.discoverAgents` from the host agent-adapters module and `ports.askAgent` backed by seam `askAgent`, `ports.evidenceEligibility` from the host workflow-eligibility module, `ports.parseProductDocuments` and `ports.parseProductWorldWriters` from the host product-documents module, and `ports.askApproval`, `ports.lineReader`, and `ports.promptPath` from the host prompt-approval module.
- `createAgentBridge(context, test, tryId, options, link, seamPorts)`: loads the host agent-adapters module (`discoverAgents`, `runAgentProcess`) before network access and supplies default `redaction`, `loadAgentDefinitions`, `discoverAgents`, `runAgentProcess` (`agents.run`), `askAgent`, and `guidePorts.evidenceEligibility` without cloning `context`.
- `readTryOwner(input, ports)`, `createTryTools(input, ports)`, and `runMcp(input, ports)`: supply `ports.tryLauncherUrl` (`runMcp` also supplies `ports.clientVersion` from the host package manifest), `ports.redaction` from the host secret-redaction module, `ports.evidenceEligibility` from the host workflow-eligibility module, and `ports.parseProductDocuments` and `ports.parseProductWorldWriters` from the host product-documents module so MCP owner tools and Try reopening support whole-product simulations without loading full workflow or product runtime graphs.
- `openCli(context, test, sessionId, options)`, `openServe(context, test, sessionId, options)`, `runShim(descriptorPath, argv, ports)`, `saveLast(input)`, and `runDoorCall(descriptor, input, ports)`: `openCli` supplies `context.ports.tryLauncherUrl` and selection ports when `context` is present; `openServe` supplies selection ports on `context.ports` when `context` is present; `runShim` loads the host secret-redaction module and the host prompt-approval module and supplies `ports.redaction`, `ports.lineReader`, and selection ports; `saveLast` supplies `ports.lineReader` and selection ports; `runDoorCall` supplies `ports.redaction` and selection ports.
- `readContractHistory(input, ports)` and `runContracts(input, ports)`: supply `ports.evidenceEligibility` synchronously from the host workflow-eligibility module (`readEvidenceEligibility`) and selection ports from the host test-selection module; `runContracts` also loads `runtimeClientSlice()`, while async CLI dispatch imports `src/runtime-seam.mjs` inside its error guard.
- `migrateRuntimeWorkspace(input, ports)`: supplies `ports.evidenceEligibility` from the host workflow-eligibility module (`readEvidenceEligibility`) and selection ports from the host test-selection module.
- `saveDoorCaseResult(root, saved, options)`, `saveDoorCase(root, saved, options)`, `acquireCaseWriteOwnership(input, ports)`, `applyPendingCase(input, ports)`, `applyPendingCaseWithHandoff(input, ports)`, `savedStoryEvidence(input, ports)`, `createSavedStoryEvidenceReader(ports)`, and `runtimeWorkspaceMigrationStore(input, given)`: supply selection ports from the host test-selection module.
- `checkRuntimeHealth(input, ports)`, `health(input, ports)`, `loadRuntimeClient()`, `runtimeOrigin(env)`, and `runtimeClientSlice()`: `checkRuntimeHealth`, `health`, and `loadRuntimeClient` supply `ports.redaction` from the host secret-redaction module; `runtimeOrigin` delegates synchronously to the Runtime package entry; `runtimeClientSlice()` loads Runtime client synchronously via the Runtime package entry and overlays the seam-bound `acquireCaseWriteOwnership`, `applyPendingCase`, `applyPendingCaseWithHandoff`, `checkRuntimeHealth`, `createSavedStoryEvidenceReader`, `health`, `readContractHistory`, `runtimeOrigin`, `runtimeWorkspaceMigrationStore`, `saveDoorCase`, `saveDoorCaseResult`, and `savedStoryEvidence` bindings without importing host modules from the seam at module-evaluation time.
- Package API commands and port-consuming readers (`check`, `lint`, `read`, `retry`, `local`, `simulate`, `jobs`, `health`, `mcp`, `contracts`, `source.identity`, `saved.results`, and `render`): defined on `src/runtime-seam.mjs` over the seam's own host-port-injecting wrappers (`runCheck`, `runTry`, `runJobs`, `checkRuntimeHealth`, `runMcp`, `runContracts`, `captureSource`, `savedStoryEvidence`, `renderText`, `renderJson`, `storyLines`, `summaryLine`)—never re-exported raw from the Runtime package entry—so every new API name carries identical `client.version`, `client.commands`, `workflowBaseSha`, `redaction`, `headerPrompts`, `evidenceEligibility`, native Story assessment, SVG layout, screen comparison, selection, exit-code, and `promptTestsLabel` ports. Pure stateless readers and metadata (`exactValue`, `format`, `workspace`, `version`, `causeText`, `cleanText`) re-export directly from the Runtime package entry.

Also forward selection ports (`isStoryPath`, `hasAcceptance`, `expectedTestPath`, `matchTests`, `orphanSummary`, `selectTests`, `whyNoTests`, `NO_TESTS`), exit-code ports (`exitFor`, `exitCodeFor`), and `promptTestsLabel` (`PROMPT_TESTS_LABEL`) lazily on call from the host test-selection module, the host exit-code module, and the host PR-word module into `runCheck`, `runTry`, `createAgentBridge`, `readTryOwner`, `createTryTools`, `runMcp`, `runContracts`, `migrateRuntimeWorkspace`, `saveLast`, `openCli`, `openServe`, `runShim`, `runDoorCall`, `saveDoorCaseResult`, `saveDoorCase`, `acquireCaseWriteOwnership`, `applyPendingCase`, `applyPendingCaseWithHandoff`, `savedStoryEvidence`, `createSavedStoryEvidenceReader`, and the scoped slice loaders (`runtimePreflightSlice`, whose `lintLocalHygiene` also appends `lintRepoAntiPatterns` warnings for direct library callers, `runtimeOutcomeSlice`, `runtimeOutputSlice`), while exposing pure constants (`NO_TESTS`, `STATE_EXIT_CODES`, `COMMAND_EXIT_CODE`, `PROMPT_TESTS_LABEL`, `PROMPT_TESTS_WORDS`) directly so evaluating `src/runtime-seam.mjs` loads zero extra pdd or Runtime modules.

The seam holds no mutable request state and loads zero additional pdd or Runtime modules when `src/runtime-seam.mjs` itself evaluates; each caller loads only its requested slice or command graph. Both static imports and dynamic `import('./runtime-seam.mjs')` callers receive the same namespace. ## Dependencies

- `@promptdriven/runtime-client`: installed Runtime client package providing the exported Runtime bindings and their contracts.
- [Command catalog](command-catalog.prompt.md): required generation context for `NAMES` (`client.commands`).
- [File owner lookup](file-owner.prompt.md): required generation context for `headerPrompts`.
- [Shared secret redaction](secret-redaction.prompt.md): required generation context for the shared host `redaction` port (`remember`, `redact`, `known`).
- [Agent configuration](agent-config.prompt.md) and [Agent adapters](agent-adapters.prompt.md): required generation context for `loadAgentDefinitions`, `discoverAgents`, and `runAgentProcess`.
- [Prompt approval](prompt-approve.prompt.md): required generation context for Try approval ports.
- [Workflow runner](workflow-runner.prompt.md), [Workflow runs](workflow-runs.prompt.md), and [Workflow results](workflow-results.prompt.md): required generation context for evidence eligibility, workflow base SHA, and native Story lint assessment ports.
- [Product workflow](product.prompt.md): required generation context for `parseProductDocuments` and `parseProductWorldWriters` ports.
- [Test selection](test-selection.prompt.md), [PDD exit codes](runtime-exit.prompt.md), and [Prompt tests PR words](prompt-tests-words.prompt.md): required generation context for selection, exit-code, and PR-word ports and compatibility exports.
- [SVG layout lint](svg-layout.prompt.md), [Repo hygiene lint](repo-hygiene-lint.prompt.md), and [Screen comparison](screen-compare.prompt.md): required generation context for local drawing and repository hygiene check ports.
