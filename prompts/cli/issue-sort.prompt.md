# Sort issues before work

Own validation, freshness, routing decisions and groups. The coordinator supplies
semantic decisions in the same request as dependency review. PDD makes no model
call. Claims, trust and dependency review keep their existing meaning.

A sort record has schema_version pdd.issue-sort.v1, issue (full GitHub URL), base
(previous sort comment IDs), inputs (unique key/revision rows), belongs
({kind:area|repository|old-code|unknown,area,repository}), status
({state:still-happens|partly-fixed|fixed|unclear,release,fix,evidence}), genuine
({kind:bug|feature|docs|duplicate|not-genuine|unclear,duplicateOf,reason}), paths
(examined repo paths), rootCause (human-readable summary or short slug, or empty),
severity (high|medium|low), and question (empty or one question). Optional
structured grouping fields on a sort record are owningModule (canonical prompt/src
or skill module path), component, symbol, errorCode, route, duplicateOf (canonical
open issue URL or #N) and a legacy unify field (accepted for old records but ignored
for grouping), plus optional reproduce ({confirmed, owningModule?, symbol?,
component?, errorCode?, route?, duplicateOf?, summary?}) recorded after the reproduce step.
Optional touchedAreas lists unique {area,evidence} rows with nonempty area names and
nonempty evidence string lists (files, commands or error text). It lists every
area touched. Legacy single-area records remain readable; multiple matched areas
without complete touchedAreas evidence must ask for an owner. Optional splitOrder
is {first,evidence}: first names a touched area and evidence is a nonempty string
list explaining the required work order. Missing or conflicting order asks; never
invent dependencies. These extensions do not weaken source freshness.
Validate each touchedAreas element as an object before reading its fields.
Malformed records, including null or malformed elements, return false from
validSort rather than throwing. Snapshot reads retain invalid trusted heads as
blocking evidence; outsider records cannot block selection or abort the read.
Mixed routing is owned by [mixed areas](issue-mixed.prompt.md). Routes may also
have action split and optional parts (resolved area rows); no work starts on a
mixed parent. A trusted whole choice routes all parts to one external area owner
with one note naming every part and its evidence. Split creates independently
closable parts. A parent with confirmed parts holds until both are completed;
then ordinary paced auto/observe closure applies with both child completion links as evidence, independent of its stale
pre-split sort. Never group mixed parents or part issues by root cause.
Require evidence and a usable fixing locator for fixed: a GitHub PR/commit URL, a 7-to-64-digit hexadecimal commit identifier, or a file path with a line number. Reject a plain claim such as fixed or done. Require a different full
issue URL for duplicate, and a reason for not-genuine or old-code. Reject malformed
records before effects. A record must include its issue row, current area/release
row, its current label row (without PDD work labels), and every trusted requirement comment for its issue. Every examined input
must still have its recorded revision. Every named path must have its canonical blob/HEAD source row. Incomplete required observations hold the issue. An external repository can never become local work, even if an area names Autopilot. Unrelated issues do not stale a record.
Trusted intact records supersede only their named base records. Conflicting heads
wait. New comments, source, release or area changes queue another sort.

The sortPlan input admits the full normalized dependency snapshot, including issue metadata, saved reviews, impacts, edges, capture time and warnings. Preserve the existing required input fields. Metadata alone cannot authorize work.

`sortPlan({snapshot})` returns {queued,routes,groups}. Each route has issue,
action (work|close|assign|link|question|hold), area, owner, reason, record (or null),
umbrella (issue URL or empty), members (issue URLs), and evidence (string list).
Only open trusted issues in the root repo are considered. Unknown assignees,
human assignees and live claims hold; expired claims keep existing rules.
An assigned issue cannot be a current group member or umbrella, including in
retained groups and recovered umbrella candidates. Remove it from the active
group plan; the remaining unassigned issues follow ordinary grouping rules.
Retain historical recheck evidence without authorizing effects on assigned issues.
A stale sort on an assigned sibling does not require a new sort or hold free work.
Fixed, duplicate, old-code and not-genuine take closure precedence over owner.
Otherwise resolve areas with autopilot-areas, using trusted title and issue body for keyword rules. Another owner is assign or link;
unknown owner is one question. Current unresolved local status is a question.
Every retained group member needs a current selected sort before its leader (`umbrella`) can be ready, regardless of area. Only unowned idle local work routes can newly join a group. Human-assigned issues and Runtime-owned issues (`isRuntimeOwned`) never join a group. Compare each new or changed sort with all open saved sort records and saved groups, without a separate full issue reread. Two issues join the same candidate group when they share the same canonical owningModule (from autopilot-areas) plus a shared component, symbol, errorCode or route signal, or when one names an open local work issue in duplicateOf (or genuine.duplicateOf on an open local work issue). rootCause is descriptive text and never forms a group or matches a saved group. A duplicate relationship is the only signal that can group issues without the same owningModule. Cap group size at 2 to 5 issues: split larger clusters deterministically in issue-number order into chunks of 2 to 5 issues (rebalancing a trailing remainder of 1 with the preceding chunk into 4 and 2). Never create a synthetic Global fix umbrella issue; the lowest-numbered member is always group.umbrella and group.members lists all members (2 <= members.length <= 5). Confirm every member after reproduce with a member-specific reproduce result that names its canonical owningModule and confirms the group signal. Split absent, failed, or different members. A missing leader result stops publication for that run and keeps its issue identity and claim; release other member claims by their saved identities before normal admission can form a new group. Save member-evidence.json rows as {issue, reproduce:{confirmed, owningModule, component?, symbol?, errorCode?, route?, duplicateOf?, summary}, test:{passed, name, summary}}. A code PR closes a member only when its own reproduction matches the group and its own passing test is present. A saved group has rootCause, area, umbrella (a real member issue), members, and optional owningModule, signal, splitOut, reproduced, merged (fixing PR URL), recheck ({issue,heads}), and notified. Legacy saved groups whose umbrella is not a member may remain attached to a live old run; do not start a second run or change that run's issue identity. Once no live old run owns it, reform the group with a real member leader through ordinary admission. Persist these in sortContext.groups. A claimed issue, person assignment, Runtime-owned issue, unknown execution or open PR cannot newly join an unrelated group, while members claimed together for the same group stay in their group.
After a group fix merges, the saved group names the fixing PR and each member's old sort heads when recheck is needed. A previously sorted sibling with changed or incomplete inputs holds its known group until another sort. Its stale decision can hold work but cannot authorize an effect.
Non-leader members wait for their group leader (`umbrella`); group selection must not create a dependency
cycle or bypass any member's prerequisites, including a prerequisite closed as not planned. Check paths through issues outside the group too. The dependency graph retains
its own links and reviews.
`projectSortGraph(snapshot,graph)` adds each node's sort action, area, owner,
umbrella, members, rootCause and ready flag. Graph groups expose size through members.length, cause and umbrella. Ready is false for an unsafe group; it does not
replace ordinary eligibility. `sortClosingReferences({snapshot,issue,code,graph,memberEvidence})`
returns references for valid open nonleader members of the current ready group. On a code PR (code: true), it emits Closes #N only for each member with a matching confirmed reproduction and its own passing test in memberEvidence; otherwise it emits Refs <member>. PR 1 (code: false) always emits Refs <member>. It omits failed or split members. The runner separately requires the leader's own matching reproduction and passing test before publishing a code PR with Closes for the leader.
Require the current projected graph's group-ready flag before adding these lines;
an invalid or unobserved group supplies no extra references.
