# Sort issues before work

Own validation, freshness, routing decisions and groups. The coordinator supplies
semantic decisions in the same request as dependency review. PDD makes no model
call. Claims, trust and dependency review keep their existing meaning.

A sort record has schema_version pdd.issue-sort.v1, issue (full GitHub URL), base
(previous sort comment IDs), inputs (unique key/revision rows), belongs
({kind:area|repository|old-code|unknown,area,repository}), status
({state:still-happens|partly-fixed|fixed|unclear,release,fix,evidence}), genuine
({kind:bug|feature|docs|duplicate|not-genuine|unclear,duplicateOf,reason}), paths
(examined repo paths), rootCause (a short kebab-case tag or empty if unknown),
severity (high|medium|low), and question (empty or one question).
Optional touchedAreas lists unique {area,evidence} rows with nonempty area names and
nonempty evidence string lists (files, commands or error text). It lists every
area touched. Legacy single-area records remain readable; multiple matched areas
without complete touchedAreas evidence must ask for an owner. Optional splitOrder
is {first,evidence}: first names a touched area and evidence is a nonempty string
list explaining the required work order. Missing or conflicting order asks; never
invent dependencies. These extensions do not weaken source freshness.
Validate each touchedAreas element as an object before reading its fields.
Malformed records, including null or malformed elements, return false from
validSort rather than throwing. Snapshot reads retain invalid trusted heads as
blocking evidence; outsider records cannot block selection or abort the read.
Mixed routing is owned by [mixed areas](issue-mixed.prompt.md). Routes may also
have action split and optional parts (resolved area rows); no work starts on a
mixed parent. A trusted whole choice routes all parts to one external area owner
with one note naming every part and its evidence. Split creates independently
closable parts. A parent with confirmed parts holds until both are completed;
then ordinary paced auto/observe closure applies with both child completion links as evidence, independent of its stale
pre-split sort. Never group mixed parents or part issues by root cause.
Require evidence and a usable fixing locator for fixed: a GitHub PR/commit URL, a 7-to-64-digit hexadecimal commit identifier, or a file path with a line number. Reject a plain claim such as fixed or done. Require a different full
issue URL for duplicate, and a reason for not-genuine or old-code. Reject malformed
records before effects. A record must include its issue row, current area/release
row, its current label row (without PDD work labels), and every trusted requirement comment for its issue. Every examined input
must still have its recorded revision. Every named path must have its canonical blob/HEAD source row. Incomplete required observations hold the issue. An external repository can never become local work, even if an area names Autopilot. Unrelated issues do not stale a record.
Trusted intact records supersede only their named base records. Conflicting heads
wait. New comments, source, release or area changes queue another sort.

The sortPlan input admits the full normalized dependency snapshot, including issue metadata, saved reviews, impacts, edges, capture time and warnings. Preserve the existing required input fields. Metadata alone cannot authorize work.

`sortPlan({snapshot})` returns {queued,routes,groups}. Each route has issue,
action (work|close|assign|link|question|hold), area, owner, reason, record (or null),
umbrella (issue URL or empty), members (issue URLs), and evidence (string list).
Only open trusted issues in the root repo are considered. Unknown assignees,
human assignees and live claims hold; expired claims keep existing rules.
Fixed, duplicate, old-code and not-genuine take closure precedence over owner.
Otherwise resolve areas with autopilot-areas, using trusted title and issue body for keyword rules. Another owner is assign or link;
unknown owner is one question. Current unresolved local status is a question.
Every retained group member needs a current selected sort before its umbrella can be ready, regardless of area. Only unowned idle local work routes can newly join a group. Compare each new or changed sort with all open saved sort records and saved groups, without a separate full issue reread. Equal nonempty rootCause joins or forms a group across locally owned areas; a changed cause leaves the old group. Two members can use the lowest idle member as their work issue. At three members or across areas, hold member starts until a dedicated umbrella exists. A saved group has rootCause, area (area names joined by comma), umbrella (URL or empty), members (URLs), and optional merged (fixing PR URL), recheck (member to old sort-head IDs encoded as rows {issue,heads}), and notified (last member URLs announced to its umbrella). Persist these in sortContext.groups. A group retains its dedicated umbrella, including an empty member list; an empty dedicated umbrella cannot start. Remove an empty pair. A running, claimed, assigned or open-PR pair work issue remains the group work issue; never replace it with an idle member. Defer a dedicated upgrade until that work finishes. A closed pair work issue remains the group work issue until merge evidence is checked. Recovery from cause markers requires exactly one trusted match; multiple matches hold member starts and all conflicting umbrella starts, including when an umbrella ID is already saved. A synthetic umbrella with no selected group waits instead of becoming ordinary work. A claimed issue, person assignment, unknown execution or open PR cannot newly join. Existing running umbrellas can gain idle members and get one membership note per changed member set. Deferred issues are compared again after their run or PR ends. An umbrella is not its own member. Ignore its synthetic body as a member cause. A stale known sibling still holds its group.
After a global fix merges, the saved group names the fixing PR and each member's old sort heads. Every open member needs a new current sort that supersedes those heads. Until then, hold member routes and queue rechecks. Do not group a surviving member behind the merged umbrella. Only a fresh fixed decision closes that member with its own evidence; unresolved members stay open.
A previously sorted sibling with changed or incomplete inputs holds its known group until another sort. Its stale decision can hold work but cannot authorize an effect.
Members wait for that umbrella; group selection must not create a dependency
cycle or bypass any member's prerequisites, including a prerequisite closed as not planned. Check paths through issues outside the group too. The dependency graph retains
its own links and reviews. A global fix PR references members. It must not auto-close them before the post-merge sort.
`projectSortGraph(snapshot,graph)` adds each node's sort action, area, owner,
umbrella, members, rootCause and ready flag. Graph groups expose size through members.length, cause and umbrella. Ready is false for an unsafe group; it does not
replace ordinary eligibility. `sortClosingReferences({snapshot,issue,code,graph})`
returns extra full-URL Refs lines for both prompt and code PRs.
Require the current projected graph's group-ready flag before adding these lines;
an invalid or unobserved group supplies no extra references.



Do not queue or route manually held issues as sort subjects.

## Dependencies

- [Mixed areas](issue-mixed.prompt.md): required mixed-area policy and part identity.

- [Areas](autopilot-areas.prompt.md): required area and owner matching contract.
