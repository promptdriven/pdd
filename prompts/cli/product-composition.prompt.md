# Compose a product Try

Own `src/product-composition.mjs`. Export synchronous `composeProductTry({root,parts,journey,testPath}, ports)` and `selectJourneys(tests, selector)`. These are ordinary public module operations used by the Runtime client, not a second CLI or upload archive. Preserve standalone check and Try, product startup/status, source privacy and caller files.

## Composition

Reuse the product module’s pure `parseProductDocuments({mapText,planText})` with snapshot-reader bytes; do not copy its Markdown table parser. Existing async readProduct delegates to that same parser. Read the selected parts' `app/maps/PART.json`, with product-root-relative paths. Absent parts means all parts in map order; comma-list CLI parsing belongs to the catalog/client. Reject unknown or duplicate parts. Read JSON through injected synchronous `readFile(path)` returning UTF-8 string or Buffer; missing optional part seed is allowed, missing map is not. Return generated repository-relative upload artifacts as JSON text `{path,content}`; never write repository files. Use `app/maps/product.json` and `contracts/product-seed.json` for generated artifact names, returning map first and seed second in files. These names are local effective-source replacements and enter the normal privacy/symlink/size checks. The seed file is a world artifact, not a scenario: the client preserves request seed as the selected test.path and, in the same capture hook, replaces only that effective scenario’s initial_world using E1’s shared lossless expansion. Preserve all other scenario fields, steps and criteria. files still returns map first and world seed second; the client hook may additionally return replaced scenario bytes.

Namespace screen IDs as `PART/ID`, prefix initial_screen, handler.screen and next.screen. Preserve all seven screen fields exactly; runtime screens have no title field. Return separate labels `{id,title}` where title is `PART · ID`, for CLI/navigation presentation; owned render prompts may supply visible headings. Navigation between the joined screens uses these IDs. Merge stylesheets once preserving first occurrence and choose the first selected part's initial screen. A part wildcard handler expands only to that part's screens. Namespace each part state under its part name, rewrite /state pointers including template refs and existing after.bind, and lift state replacements so they replace only that part while retaining other parts and chain scratch slots. JSON-pointer escape part names. Never rewrite arbitrary input strings. Preserve a single map router. For multiple maps preserve non-null routers only when normalized router definitions are identical, route-name mapping is nonconflicting and all rewritten state/navigation references remain consistent. Mixed null/non-null routers or incompatible configurations refuse with unsupported-product-router: the current Runtime map has only one router slot. All literal-navigation maps compose normally; never silently drop a router.

Read `## After every tap` from product/plan.md as ordered list items `PROMPT_PATH#OPERATION`. Append these operations to every executable handler, after its existing after list, never to a gap handler. Reuse preflight’s interface/schema reader and E1’s shared contract resolver with the same attempt-local snapshot reader to obtain fully expanded complete operation result schemas, including $contract references. Never copy an unresolved $contract into the generated state schema or infer a schema from examples. E1’s published resolver/parser API is an unresolved integration dependency until delivered; do not invent its signature or duplicate its policy. Each appended step is exactly `{handler:{prompt_path,operation},input:{},bind:POINTER}`. Bind to a unique non-root /product_after/INDEX slot whose state schema accepts null initially and the exact complete typed result afterward. Preserve required parent objects. Later operations see prior world effects. Runtime permits at most eight after steps and forty total calls per tap; explain an over-limit map before upload. `tapOperations` reports executable handler plus after-operation count separately from the forty-call ceiling; it is not a claim about transitive model costs. Preserve all existing after input/binding/result semantics and source dependency closure.

## Seed and journey

Read contracts/seed-world.json, then each selected part's prompts/PART/seed.json in part order. Shallow-merge top-level world keys. Parse contracts/world.md writer declarations through the shared product preflight helpers: two distinct parts declaring the same top-level key as writable refuse with `world-writer-conflict`, naming key and parts, before upload. A part seed cannot overwrite a key owned by another part. A journey is an ordinary scenario whose Story lies directly under root user_stories/journeys. Apply its explicit initial_world.set JSON-pointer replacements last, including false/null/empty values, using E1’s shared seed expansion semantics. A literal full initial_world without $seed is also a valid ordinary scenario and provides its explicit top-level values last; do not require new seed syntax for existing journeys. Preserve explicit nulls and arrays and every own JSON key, including __proto__, without prototype mutation or inherited-key merging. Preserve JSON numeric values losslessly under E1’s numeric-copy rules; ordinary JSON.parse/restringify must not silently round integers beyond the safe Number domain or other decimal/exponent values. Reuse E1’s shared lossless seed parser/resolver through the same snapshot reader. Its public API remains unresolved until E1 publishes it; do not invent an API or a second parser. Do not merge arrays or run production rules during seeding. Serialize artifact JSON with recursively sorted object keys, compact separators and no trailing newline. Return canonical JSON text seed artifact without modifying fixtures. No journey means merged seed only.

`selectJourneys` takes discovered `{testPath,storyPath}` records and returns their original test paths in discovery order. Only root user_stories/journeys/*.md qualifies. No selector returns all such tests; a selector matches a complete case-sensitive basename ID token followed by '-' or '.' or end. J1 never matches J10. Exact Story path or test path also selects. Unknown and ambiguous selectors refuse with `invalid-journey`; list candidates. Multiple tests for one unambiguous Story remain selected. Use existing test discovery and Story matching helpers; no parallel parser. `testPath` chooses the single journey scenario for a Try seed; when multiple selected tests exist require the person to choose, never pick silently.

## Ports and source capture

The sole file port is native synchronous readFile(path), bound below by files.read returning content. Runtime tests supply actual file bytes, including product Markdown and map/seed JSON. No port computes composition or returns an expected answer. Reuse readProduct and shared preflight helpers in native code; dependency prompt calls are not filesystem substitutes.

The Runtime client passes E1's reviewed captureSource(root,{tests,appMap,attempts,prepareSource}) hook. Its per-attempt synchronous prepareSource({readFile,statFile}) returns [{path,bytes}] for the effective generated/replaced source; all reads must use that attempt's readers. Call synchronous composeProductTry inside each prepareSource attempt using those captured readers, not a separate unsnapshotted precompute or archive. Hook implementation/integration is pending E1 delivery; do not invent another hook, claim native snapshot behavior from file-port checks, or upload outside the existing capture pipeline.
