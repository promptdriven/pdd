# Compose a product Try

Own `src/product-composition.mjs`. Export synchronous `composeProductTry({root,parts,journey,testPath}, ports)` and `selectJourneys(tests, selector)`. These are ordinary public module operations used by the Runtime client, not a second CLI or upload archive. Preserve standalone check and Try, product startup/status, source privacy and caller files.

## Composition

Before encoding or upload, validate required v1 app-map fields used by composition, including the required router field. A missing or malformed required field gives finite invalid-product-map naming the field; never emit JavaScript undefined as JSON or silently default a malformed required field. Preserve permitted optional defaults and canonical target grammar without unrelated admission restrictions.

Reuse the product module’s pure `parseProductDocuments({mapText,planText})` with snapshot-reader bytes; do not copy its Markdown table parser. Existing async readProduct delegates to that same parser. Read the selected parts' `app/maps/PART.json`, with product-root-relative paths. Absent parts means all parts in map order; comma-list CLI parsing belongs to the catalog/client. Reject unknown or duplicate parts. Use injected synchronous `statFile(path)` returning {exists,is_symlink,size} before reading through `readFile(path)` returning UTF-8 string or Buffer. A missing optional part seed skips its read; a missing required map does not. Both ports bind runtime-preflight’s same attempt-local safe readers; unsafe, secret, symlink or unreadable paths are not missing and retain normal source-capture refusals. Return generated repository-relative upload artifacts as JSON text `{path,content}`; never write repository files. Prefer `app/maps/product.json` and `contracts/product-seed.json` for the two new virtual JSON artifacts, returning map first and seed second in files. Before upload, both paths must be absent on disk according to the same safe snapshot stat. If either is occupied, choose the smallest positive numeric suffix for which both `app/maps/product_N.json` and `contracts/product-seed_N.json` are absent. A refused or failed stat remains a refusal, never absence; preserve all path/privacy/symlink/size checks. Never overwrite or write an authored file. Generate no prompt file. The seed file is a world artifact, not a scenario: the client preserves request seed as the selected test.path and, in the same capture hook, replaces only that effective scenario’s initial_world using contract-refs’ shared lossless expansion. Preserve all other scenario fields, steps and criteria. files still returns those two new JSON artifacts, map first and world seed second. Separately, the client hook returns the effective replacement of the already tracked selected scenario required by the existing Runtime seed request; this is not a newly generated artifact or prompt.

Namespace screen IDs as `PART/ID`; initial_screen and handler.screen name local IDs and receive the part prefix. Resolve next.screen against the current part’s local screen IDs first, including local IDs containing a slash; prefix that local match. Otherwise keep an already-qualified selected product screen ID. An unknown target refuses invalid-product-map naming the missing part/screen. Selected subsets must be closed over explicit navigation targets; never drop a target or silently redirect it. Preserve all seven screen fields exactly; runtime screens have no title field. Return separate labels `{id,title}` where title is `PART · ID`, for CLI/navigation presentation; owned render prompts may supply visible headings. Navigation between the joined screens uses these IDs. Merge stylesheets once preserving first occurrence and choose the first selected part's initial screen. A part wildcard handler applies only to that part’s screens while preserving original exact-screen-over-wildcard dispatch priority. Handler compatibility follows Runtime matcher JSON equality recursively: object key order is ignored, array order matters, numerically equal number tokens compare equal, and in this matcher only true equals 1 and false equals 0 as in Runtime Python equality. Use contract-refs jsonNumberIdentity(value) for numeric identity; do not copy a numeric parser or change shared schema-equivalence Boolean policy. Wildcard-only maps, disjoint mixed rules, omission of a wildcard condition fully covered by an exact rule, and faithful collapse of identical rules remain supported. If a mixed exact/wildcard overlap cannot preserve the original actions and priority under Runtime’s handler admission rules, refuse with invalid-product-map and an explicit unsupported wildcard priority explanation. Never silently change actions or add a bridge prompt/model calls to simulate dispatch. Namespace each part state under its part name, rewrite /state pointers including template refs and existing after.bind, and lift state replacements so they replace only that part while retaining other parts and chain scratch slots. JSON-pointer escape part names. Never rewrite arbitrary input strings. Preserve a single map router. For multiple maps preserve non-null routers only when normalized router definitions are identical, route-name mapping is nonconflicting and all rewritten state/navigation references remain consistent. Mixed null/non-null routers or incompatible configurations refuse with unsupported-product-router: the current Runtime map has only one router slot. All literal-navigation maps compose normally; never silently drop a router.

Read `## After every tap` from product/plan.md as ordered list items `PROMPT_PATH#OPERATION`. Append these operations to every executable handler, after its existing after list, never to a gap handler. Reuse preflight’s interface/schema reader and contract-refs expandSource({path,text,format:"prompt"}, files) with the same attempt-local snapshot reader to obtain fully expanded complete operation result schemas, including $contract references. Never copy an unresolved $contract into the generated state schema or infer a schema from examples. Each appended step is exactly `{handler:{prompt_path,operation},input:{},bind:POINTER}`. Choose scratch container product_after, appending underscores until its name is unused by selected part namespaces, then bind to a unique non-root /CHOSEN/INDEX slot whose state schema accepts null initially and the exact complete typed result afterward. No part name is reserved: a part literally named product_after keeps its state and moves scratch to product_after_; continue for further collisions. Preserve every own part/state key, including __proto__, as data without prototype mutation. Preserve required parent objects. Later operations see prior world effects. Runtime permits at most eight after steps and forty total calls per tap; explain an over-limit map before upload. `tapOperations` reports executable handler plus after-operation count separately from the forty-call ceiling; it is not a claim about transitive model costs. Preserve all existing after input/binding/result semantics and source dependency closure.

## Seed and journey

Read contracts/seed-world.json, then each selected part's prompts/PART/seed.json in part order. Shallow-merge top-level world keys. Parse contracts/world.md with product’s pure parseProductWorldWriters({worldText}): two distinct parts declaring the same top-level key as writable refuse with `world-writer-conflict`, naming key and parts, before upload. Independently of world.md declarations, two distinct selected part seed files providing the same top-level key refuse with world-writer-conflict naming that key and both parts, even when their values are equal. The base seed is not a part and may be overridden by a part. A part seed cannot overwrite a key owned by another part. A journey is an ordinary scenario whose Story lies directly under root user_stories/journeys. For a journey initial_world with $seed, the product seed layers remain contracts/seed-world.json, selected part seeds, then only the journey’s explicit initial_world.set JSON-pointer replacements, including false/null/empty values. The authored $seed is the standalone Check base, even when it names another file; it is not another product merge layer. Preserve ordinary reference/scenario validation first through contract-refs’ shared expansion, including missing/unsafe paths and cycles, then apply the explicit set to the generated merged world using contract-refs’ shared seed semantics. Never expand the original journey base and overlay that whole world onto product layers, which would erase part seeds. A literal full initial_world without $seed is also a valid ordinary scenario and provides its explicit top-level values last; do not require new seed syntax for existing journeys. Preserve explicit nulls and arrays and every own JSON key, including __proto__, without prototype mutation or inherited-key merging. Preserve JSON numeric values losslessly under contract-refs’ numerical preservation rules; ordinary JSON.parse/restringify must not silently round integers beyond the safe Number domain or other decimal/exponent values. Use contract-refs parseJsonValue(text), stringifyJsonValue(value) and isJsonNumber(value) for lossless source values, and expandSource({path,text,format:"scenario"}, files) for shared seed resolution through the same snapshot reader; do not duplicate this owner’s parser or policy. Do not merge arrays or run production rules during seeding. Serialize artifact JSON with recursively sorted object keys, compact separators and no trailing newline. Return canonical JSON text seed artifact without modifying fixtures. No journey means merged seed only.

`selectJourneys` takes discovered `{testPath,storyPath}` records and returns their original test paths in discovery order. Only root user_stories/journeys/*.md qualifies. No selector returns all such tests; a selector matches a complete case-sensitive basename ID token followed by '-' or '.' or end. J1 never matches J10. Exact Story path or test path also selects. Unknown and ambiguous selectors refuse with `invalid-journey`; list candidates. Multiple tests for one unambiguous Story remain selected. Use existing test discovery and Story matching helpers; no parallel parser. `testPath` chooses the single journey scenario for a Try seed; when multiple selected tests exist require the person to choose, never pick silently.

## Ports and source capture

Propagate shared contract-refs errors with their canonical codes and diagnostics; composition does not remap them or replace their owner’s policy.

The native synchronous file ports are readFile(path) and statFile(path), bound below by files.read returning content and files.stat returning {exists,is_symlink,size}. Stat precedes reads, so optional absence is an observable value and never an attempted missing-file read. Runtime tests supply actual file bytes, including product Markdown and map/seed JSON. No port computes composition or returns an expected answer. Reuse the product pure parser and shared preflight helpers in native code; dependency prompt calls are not filesystem substitutes.

The Runtime client passes runtime-preflight’s captureSource(root,{tests,attempts,prepareSource}) hook without a static appMap and marks only the prepared map output role:'app-map' for attempt-local map selection. Its per-attempt synchronous prepareSource({readFile,statFile}) returns [{path,bytes}] for the effective generated/replaced source; all reads must use that attempt's readers. Call synchronous composeProductTry inside each prepareSource attempt using those captured readers, not a separate unsnapshotted precompute or archive. Never invent another hook or upload outside the existing capture pipeline.
