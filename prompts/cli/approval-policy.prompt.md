# Approval policy and durable prompt evidence

Own new `src/approval-policy.mjs`, the small shared native boundary used by standalone and workflow approval. It owns repository policy, invoking-actor identification and the durable prompt journal. It never decides that a person approved, changes a prompt, publishes or merges. New exports below are native production APIs, not Interpreter substitutes.

## Repository policy

Module function `readApprovalPolicy({root}, ports = {})` returns `{strictApprovals}`. Read only `pdd.json` directly in the trusted repository root supplied by the caller. Missing file or missing `strict_approvals` means false; false means easy; true means terminal-only. Require a JSON object and a boolean when that key exists. Unknown keys do not affect approval. Malformed JSON, wrong type and unreadable existing config fail with a finite diagnostic naming `pdd.json`; callers must stop before any approval mutation. Do not consult caller subdirectories, `pdd-source.json` or user agent configuration. Standalone uses Git's top-level root; workflows use saved `sourceRoot` (the initiating repository), falling back to `root` only for legacy records without sourceRoot. Never fall back after a read error.

## Actor and evidence

Module function `approvalActor(env)` returns `{kind,id}` describing the invoker, never claiming authenticated identity of the person whose words were supplied. Prefer concrete available session identity: a nonempty `CODEX_THREAD_ID` makes kind `agent` and id `CODEX_THREAD_ID=VALUE` (identifying Codex and its session). Otherwise a nonempty `CLAUDECODE` identifies the Claude invoker as `CLAUDECODE=VALUE`; do not claim it is a session ID. Only then fall back to nonempty `PDD_AGENT_SESSION` as `PDD_AGENT_SESSION=VALUE`. A generic PDD_AGENT_SESSION=1 must never hide a concrete Codex session. Otherwise kind is `terminal`, id is `USER`, falling back to `LOGNAME`, then `unknown`. Preserve the selected value verbatim; presentation safety belongs to the publisher.

An approval evidence record is `{route,actor,at,words,prompts}`. `route` is `said`, `terminal` or `chat` (existing native Herdr evidence). `actor` is the invoking identity above; `at` is the approval command's epoch-millisecond clock value, not a fabricated chat timestamp. `words` is the exact supplied --said value, the exact native chat message for chat, or null for terminal. Each `prompts` row is `{path,proseSha256}`: repository-relative POSIX path and current lowercase SHA-256. Empty prompt arrays are valid for gates without changed prompts. Native chat session/message-time fields remain in their existing run fields. These are local provenance claims, not cryptographic proof of a speaker.

Module function `recordPromptApproval({commonDir,evidence}, ports = {})` appends the evidence to `<commonDir>/pdd/approvals.json`; module function `readPromptApprovals({commonDir}, ports = {})` returns its records, missing file as an empty list. The journal is `{v:1,approvals:[...]}`; reject malformed/unreadable existing journals and never silently replace them. Shared Git-common-dir storage lets linked worktrees find standalone approvals. Preserve all previous records and verbatim words, write via temporary file and rename, and serialize concurrent updates so successful approvals are not lost. No credentials or native conversation log is copied. File operations and clock/identity inputs are injected through native ports (`fs`, `env`, `now`) with real defaults; Git root/commonDir resolution stays with callers.

Callers prevalidate journal readability and all selected prompt edits before mutation. A failed prompt or journal write never reports success or advances a gate; report any prompt paths already changed if rollback cannot complete. A journal row applies to PR evidence only when its path and hash both match the current published prompt. Later prose invalidates that association. Gate history and standalone journal may describe the same approval: publish it once, using route/actor/time/words/prompt identities, without deleting local history.

## Dependencies

No other business prompt supplies policy. Native filesystem concurrency, atomic rename, Git common-directory resolution and exact-byte hashing require native acceptance; no Runtime interface or alternate check-only API is declared for these unsupported effects.
