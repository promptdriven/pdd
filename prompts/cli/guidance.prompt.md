# Bundled guidance loading

Own `src/guidance.mjs`; export `loadGuidance({packageRoot,cwd,workflows,workflowName})` returning full instruction text. This is the common content authority for --skill and native session startup, not a new validator/installer. Read the complete canonical docs/prompting-guide.md FIRST, then skills/pdd/SKILL.md and all regular Markdown files recursively under skills/pdd/references. Include absolute package root/current cwd and require the agent to summarize the relevant guide method before ANY Story drafting; a link is not loaded context. With workflows=true also load required docs/workflows.md and every regular bundled .pdd/workflows/**/*.md in deterministic path order; missing recipe directory/empty recipe content refuses before launch. Preserve the full original file text, never truncate/copy the guide to another file. Read the complete bundle before successful output/launch. Missing required files/read failure is an error; do not follow symlinked directories/files. Recipe documents by themselves and pdd session/one-conversation shortcuts supply manual guidance. Explicit workflow.run/resume uses the separate local runner; its current-stage instructions own progression and PR effects. Do not contradict that authority or imply the native session itself is the runner. Existing project instructions remain native-owned through cwd, not copied into the package.

## Dependencies

Read the full [Prompting guide](../../docs/prompting-guide.md) before Stories. Follow [alpha boundary](public-boundary.prompt.md).

When workflowName is supplied it MUST be one of the catalogued BUNDLED_WORKFLOW_NAMES. Load docs/workflows overview, selected WORKFLOW.md and every regular Markdown sibling/subdirectory step under that one recipe only; missing selected WORKFLOW.md refuses before child. Mark the selected recipe explicitly before its content and tell the agent to follow it after summarizing the guide. Keep guide/skill/refs first, overview then selected recipe; unrelated recipes are not initial context. Ordinary session has no workflowName and keeps all recipes. No caller-supplied paths, code execution or auto PR promise.

## Installed command identity in native shells

Normal native tool login shells can override inherited PATH and resolve a different older/private `pdd`. In every loadGuidance result (ordinary session AND runner stage workflows=false), include the actual current process.execPath and absolute packageRoot/bin/pdd.mjs entry as a literal argv pair and safely shell-quoted command prefix. Instruct the agent to use that exact absolute invocation for PDD discovery/actions instead of bare pdd, even if command -v pdd returns another installation. Preserve inherited native environment/settings; no PATH/global profile edits, wrappers, config/auth copying, or extra launcher layer. This prefix identifies this installed package and does not authorize effects by itself. Full original canonical guide/skill/workflow loading and guide-before-Story rule remain unchanged.
