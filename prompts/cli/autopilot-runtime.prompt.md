# Automatic Runtime failure incidents

Own src/autopilot-runtime.mjs. #3147 authorizes this new module. Keep Runtime checks required while other runs continue. No prompt or workflow approvals and no model calls.

Export runtimeEvidence(run), the JSON identity described for blocker.evidence below. Export classifyRuntimeFailure(check,health=null): return null or a stable cause slug. check is a readRunResults pdd test record with batch, at, states and tests. Failed expectations, binding refusals, active checks and file-rule refusals are not Runtime failures. Classify timeout, runner-stopped, provider error and other no-verdict results from terminal batch evidence. Prefer explicit health cause/code when offered with a valid cause slug; healthy/access/absent health does not veto batch evidence. Health errors, including 401 or a missing endpoint, are tolerated. Never use raw messages or request IDs as the deduplication key.

Export async reconcileRuntimeIncidents(state,ports,config,runs,{localOnly=false}={}): return a Map from run number to runtime blocker. Runs supplied are the caller's owned runs. Ports inject now, readCheck(run), busy(run), health(), issue read/search/create/update, save() and configure(enabled). The launcher binds those to its native saved-result, GitHub, guarded state/effect and interpreter queue ports. No direct outside calls. Classify stopped/waiting/paused runs without independent questions or unrelated explicit blockers. Read other runs' checks for recovery verdicts. Per-run read/health/issue failures do not abort other runs. Persist state.runtimeIncidents = {causes,seen}; causes is a cause-keyed object; seen maps runId/batch/cause identities to observation times. Each cause record has cause, checkKind (pdd test), firstAt, failures (identity to batch start epoch ms, falling back to observation time), runs (runId to {number,batch}), issue (null or {number,url}), lastFailureAt (latest failed batch start time), dirty (whether the issue body needs update), optional creating (a creation intent has been saved), and optional recoveredAt (a later verdict or observed close epoch ms). A blocker is {kind:runtime,until:String(issue.number),cause,batch,checkKind,evidence}; evidence is JSON identity of current parkReason,runtimeWait,gate,done.check. A new batch or stop replaces evidence without resetting park age.

Use one repository issue per cause with stable marker <!-- pdd:runtime-cause:CAUSE -->, label pdd:runtime, optional configured runtimeOwner assignee, and every affected run and batch in its body. Search existing issues (all states) before creation, including after an uncertain reply or restart. Update the same issue for new runs, and reopen it on a genuinely later failure after closure/recovery. Save confirmed issue identity; on unknown create retain the marker for reconciliation and never blindly repeat creation. A confirmed rejection before creation clears creating for a later retry. An uncertain create retains creating and only searches for its marker. A failed issue effect holds that run for retry while other checks continue. A local-only tick retains matching saved runtime blockers and observes later verdicts, but does not classify a new failure before health context can be read. It makes no GitHub effects or health call.

A later pdd test with all rows passed/failed and a batch time strictly after a cause failure recovers that check kind. Retain the cutoff so an old verdict cannot clear a later failure. Keep the matching runtime blocker through a newer verdict observation until the guarded wake consumes it; legacy runtimeWait must not replace it with interpreter. Closing the cause issue also recovers it. The caller wakes through ordinary oldest-first capacity and journal custody, never sends a paid check from this tick. The notice asks the worker to read its saved receipt, then send only no-verdict rows once with their original call caps. Three distinct failed batches of the same cause observed within the last 1800000 ms enable the existing interpreter queue test mode with owner STATEFILE:runtime-causes, separate from legacy interpreter recovery; independent causes and duplicate ticks do not combine. A recovery removes the relevant restriction. Recompute at every observation so the 30-minute boundary expires. Keep other native work and intake running.

## Dependencies

No required shared policy. All outside work uses the ports above.
