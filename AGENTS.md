# Working on PDD Alpha

Before drafting or changing any Story or prompt, read the entire canonical [Prompting guide](docs/prompting-guide.md) in the current conversation. Follow its method for module ownership, public behavior, preservation, required dependencies and consequential edge cases. Reading a Story template or linking the guide is insufficient. If context was lost, reload the guide before authoring.

Read [skills/pdd/SKILL.md](skills/pdd/SKILL.md) for the working process. Prompts are the behavior source: change the owning prompt before code behavior. Keep independently expected cases separate from observed implementation results. Review changes to the intended contract with the person; do not invent their decision.

This public alpha contains local native sessions, issue workflow stages, guidance discovery, documentation, recipes and a synthetic example. The local native session launcher starts the agent with a short intro and the agent loads the PDD skills (`skills/pdd-*`) on demand, preserving cwd and the user's native login while starting agents in full-access mode without writing global agent configuration. Keep `skills/pdd-prompting/guide.md` identical to `docs/prompting-guide.md`. The public local runner may use owned local Herdr background native stages in separate issue worktrees and perform real GitHub PR stages under the user's requested workflow authority. Its foreground PDD controller owns stage acceptance and progression; controller exit does not create a persistent PDD daemon. Preserve actual workflow snapshots, worktree/session identity and shared ownership guards; native readiness alone is not pass. Keep this package self-contained: no hosted services, no private dependencies, no credentials. Do not import captured conversations or operational fixtures.

Each path has one active writer. Use a topic branch, preserve other work and keep implementation prompts with their code. Use ordinary Node tests for changed public behavior; avoid prose-whitelist tests and tests that merely repeat the implementation. The public full suite is `npm test`. No live service or model call is needed for those tests. User-authorized agent acceptance is a separate activity.

Report what changed, actual check results and any unproved behavior. A local draft or PR summary is not publication. Keep execution notes outside the repository. Public source publication requires review and a green public full suite; follow the designated integrator's route. Never force-push, rewrite private repository history or publish a package to npm as a routine check.
