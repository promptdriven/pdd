# Product journey seed

## Acceptance criteria

1. A journey uses its explicit initial world over base and part seed values, including null.
2. Two distinct parts declaring orders writable refuse before any upload.
3. Current J1 evidence gives the journey row one pass out of one; J10 is not another J1.

## Rules to check

Native integration must bind current journey evidence to actual selected-source identity through the existing Story evidence owner; a supplied evidence reply proves aggregation, not native capture/history. Seed merging preserves all own JSON keys, explicit nulls/arrays and lossless numeric values under E1’s shared rules.
