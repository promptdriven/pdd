I can lint my selected Story and see structural support, blockers and unknowns for its exact source and reported interpreter build.

Draft expectations for person review. No expectation is approved.

## Acceptance criteria

1. `pdd lint place-order` shows the selected Story and test, each operation and edge, its source location, exact server verdict and reason, and labelled client owner advice, without model work or product resource effects.
2. The view keeps supported, unsupported-capability, missing-binding, invalid-source and unknown distinct, and keeps two edges to the same target and repeated steps separate.
3. The view associates the report with the captured scenario and effective file bytes, the confirmed job build and its capability version; a known disagreement is unknown compatibility with a visible client association problem.
4. An absent, malformed, conflicting or incomplete selected report never looks ready; a concrete reported blocker remains visible when coverage is incomplete.
5. Unrelated inventory problems and incomplete reports for other tests stay visible without changing an independently admitted selected test.
6. Configured build metadata does not prove the installed engine, a host profile, physical observations or business behavior; absent evidence stays unknown or unproved, and no missing fixture fact is filled from an expected result.
7. Text and JSON keep the same selected facts and remove tokens, host paths and unsafe text; preflight zero-call facts never replace unknown paid-job usage.

## Rules to check

Only authoritative selected server rows classify operations and edges. Client source/build association can withhold readiness but cannot rewrite server reasons. Unknown, incomplete or stale evidence must never display ready. Configuration identity, installed-engine proof and physical observation are separate.
