# Use the parts of my product as one app

I can open the product prompt and move between its reached parts with one starting world.

## Acceptance criteria

1. Reached product maps open as one app with part-qualified screen names, faithful navigation and state, including selected parts that have no screen.
2. A small product opens without a world contract or base seed, starting from an empty world plus any part seeds; present files still keep their normal checks.
3. Only the world key table declares writers, and conflicting part writers or part seeds refuse before upload with the key and both parts.
4. After every tap, the declared follow-up operations run in order after existing follow-ups, with typed scratch state that does not erase part data.
5. A tap whose full worst-case draw, prompt-call and follow-up cost exceeds 40 calls is explained before upload; a cost of 40 remains allowed.
6. Generated map and world artifacts never overwrite authored or ignored files, preserve source diagnostics and numerical seed values, and require no Story.

## Rules to check

Forbidden results include dropping navigation targets, changing exact-screen-over-wildcard priority, treating every Markdown table as writer declarations, silently rounding seed numbers, or counting only direct operations against the 40-call ceiling. Existing single-router admission remains unchanged.

## Native verification boundary

Runtime check: NOT REPLAYED; native source capture, session adapters, localhost listeners and terminal output are not bound to interpreter observations. Replay the requirement cases against real module boundaries with fake transport and file bytes. A fake response does not prove the hosted Screen or runtime no-Story admission. Pocket tab navigation and curl against staging require separate live evidence.
