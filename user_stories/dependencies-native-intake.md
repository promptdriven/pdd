# Review requirements before selection

I can have the selected native coordinator review real prerequisites before new work starts.

## Acceptance criteria

1. The selected native coordinator receives current source and trusted requirement context for unchecked or changed work before selection; no automatic model call is made.
2. A completed independent analysis saves an explicit empty dependency list. A product question stays a question and writes no native edge.
3. A stale completion is pending and writes no review or native edge. A proposed cycle is refused before any save.
4. Work owned by another machine is skipped instead of starting another owner.
5. Reading repository B from repository A or from no checkout never borrows A-only trust. Its native graph stays visible while unverified review authority keeps work ineligible.

6. Source-backed prepare and completion use the same durable input revisions. A changed or missing required source stays pending without an edge; an unrelated file change does not replace a review.

7. A new unrelated issue is reviewed first with both-direction impact against exact saved heads. The two unchanged reviews are reused after restart. If one head is affected, only that issue is queued next.

## Rules to check

Only the current trusted prepared scope may be saved. No stale completion, unsupported cycle, outsider text or remote-owned work may create a new edge or owner. Semantic AI belongs to the already selected coordinator; graph and intake code do not choose a model. Native tests must prove repository-bound port wiring; normalized authority cases do not prove it.
